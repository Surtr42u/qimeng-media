## 技术栈（2026-09-04 二次定论，ADR-0014：先进优先，Compose 全新实现）

- Kotlin + Jetpack Compose（Material 3）+ Hilt + Coroutine/Flow + Navigation Compose
- Coil 3（签名直链：缩略图/原图）、Media3/ExoPlayer（直链播放；BiliPlayerView 手势语义 Compose 复刻或 AndroidView 桥接）
- Room（客户端缓存/事件队列，非数据源）+ DataStore（登录/配置）+ WorkManager（队列）
- make sdk 生成的 Kotlin 客户端（`media.qimeng.sdk`）；namespace `media.qimeng.app`；minSdk 26
- 架构：Now in Android 范式多模块（`:app` + `:core:model/network/data/ui` + `:feature:*`），依赖单向 feature→core

## 职责边界（薄客户端纪律）

- 列表/搜索/推荐/统计：调 API，客户端不复制任何算法——服务端 M3 已实现全部领域算法
- 图片/视频：签名直链交给 Coil / ExoPlayer，客户端不做解码管线
- 行为上报：事件本地排队，联网补传（离线不丢）
- 上传（核心功能）：系统分享接收 + 系统文件（SAF）唯一入口（2026-09-29 直传化）+ 直传/分片双通道 + 归档文件夹一键上传（2026-10-01）+ 队列进度——"手机采集端"主通道
- 本地持久化：登录/偏好配置、可设上限的媒体缓存（LRU）、离线事件队列和传输任务元数据；权威业务数据由连接的服务端维护
- SDK 隔离（2026-10-24 词表批）：feature 生产源码零 `media.qimeng.sdk` 引用（`:app` 单测 FeatureSdkIsolationTest 扫描强制）；编辑域模型（词表 `core:model` 的 EditableVocabulary 族）在 `:core:data` 边缘与生成 SDK 双向映射（VocabularyEditMappers），页面/VM 只见端内非 null 模型
- 当前交互约束见本仓 [GUIDE_UI](../docs/GUIDE_UI.md)，旧仓规格仅历史参考；实现全部 Compose 新写（禁搬旧 Kotlin，AndroidView 桥接例外记交付清单）

## 我的与管理子页

“我的”与数据管理共用 `core:ui` 的 QimengSettingsCard/Group/Row：白色卡面、日间 SoftDaylight 轻影、深色主题适配，分组标题与中性图标建立层级；不复制 Web 的 CSS 玻璃或引入材质依赖。副文允许换行，行高为最小值，触控/键盘入口有按钮语义，版本信息只读。

收藏/历史/作者入口仍走原页面与导航，计数读取当前服务端库存，不虚构账号身份。外观提取为无状态 AppearanceScreen，主题和底栏材质沿用原 DataStore 流，纵向单选避免窄屏挤压；主列表状态在子页分支外保留。推荐偏好沿用四预设与原权重，只增加弹层滚动、单选语义和就地保存反馈。退出登录确认后才调用既有 logout。

服务器卡复用日间轻影，当前连接、默认登录与仅充电扫描保持各自语义；键盘弹出时内容可滚动避让。数据管理按任务归组既有七入口；备份、库、缓存、TXT与词表管理的默认内容卡共用白卡轻影，错误/结果横幅保留语义颜色。备份目录设置先于导入导出，未设目录和任一文件操作中禁用导入/导出；读取和校验开始前即置忙，失败/取消释放，待确认期间不再读写。浏览补传与词表合并独立保留；说明只呈现当前v2事件身份幂等规则。归档页顶栏固定、目录操作独立滚动。无协议/权限/缓存池或媒体删除规则变化；云端构建与设备验证结果分别见 HANDOVER。

上传页按位置、可选作者来源、添加文件、归档与任务结果分卡；作者来源默认收起但保留配置与摘要，长权限/格式说明按需展开。空库可直达库管理，归档未配置可直达设置；库列表失败区别于空库并可重试，刷新列表不清空已选目录或待传文件。目录树的选择/展开及新建、SAF选择后编辑文件名再开始上传、系统分享直传和归档确认语义保持。

推荐偏好保存提示与进度条使用常驻状态区域，开始/结束保存不推动选项位置；点击已生效预设不发重复PUT。成功前仍保留原已保存项，等待期间防重入，失败保留原项，权重与网络调用层不变。

## 持久上传的目标归属

入队保存目标 base URL，不保存 token；直传、分片和挂靠使用同址的请求工厂并关闭重定向。切服后尚未发送的请求拒绝；旧记录无目标时显示失败，用户确认目标后重新入队。业务目标拒绝不取消后续队列，已发请求可能在原端完成。URL 不能识别同址更换实例；定向单测与 Kotlin 编译已验证，设备重启/切服场景仍待验收（ADR-0042）。

## 前台恢复与分片把手

归档一键上传：本机上传保留归档，PC/NAS 确认入库后清理已上传的手机归档副本。清理前核对归档范围与入队 size/mtime，拒绝链接；文件变化、旧载荷缺时间或清理失败则保留并在完成通知/持久队列提示，不重传文件。确认弹窗说明释放行为，范围与已知竞态见 SECURITY「客户端归档与服务端文件移动」。

前台健康恢复由 ChildHealthRecovery 编排：无句柄/已退出时补启动，单次超时先等候再复核，两次失败才重启；检查期间换代不动旧快照，Service 在启动锁内再次核对身份后才摘看护。探测在 IO 线程，取消可释放单飞门；不承诺后台永久在线或长期冻结来源已定位。

分片把手与目标地址保存在既有客户端 DataStore，App 进程重建后 GET 权威 offset 续传；新建会话先提交把手再发字节。成功后的清理失败不能转上传重试。未完成会话重启/过期仍按 404 重建；新任务用持久 localId 作为 uploadId，服务端完成凭据七天内可跨重启重放同一资产。首次上传以本次入队时间作为 sourceMtime，忽略下载文件自带的旧日期，并随 WorkManager 载荷固定；成功归档的副本写入同一时间，归档一键上传继续透传其时间，使隔天传到 PC/NAS 仍与 App 一致。源文件时间仍用于归档条目清理前的版本核对。取消采用 DataStore，提交成功才发布取消状态；Worker 发送前恢复，WorkManager 确认终态后清理，写入失败提示重试。服务端提交前中断、凭据过期和客户端挂靠/归档后处理不等同于全链路恰好一次。

SSE 客户端读空闲超时为 60 秒（服务端 15 秒心跳的四周期）；注释心跳字节同样续期，静默超时沿既有退避重连，并在重连成功后失效缓存。保留五分钟 TTL 及前台恢复兜底，不承诺系统冻结时仍按墙钟准时调度。用户本轮已恢复云端验证与双端更新，实际结果见 HANDOVER。

## 维护定位

首页/搜索的 suspend 业务调用经 `core:data/util/runSuspendCatching` 区分取消与普通失败；库管理及其充电扫描调用链显式重抛取消。列表写回和 loading 清理都检查请求代际，返回搜索入口作废旧代；库列表在途时合并保留一轮后续刷新，写入成功后的复核不能被旧 GET 吞掉；注册成功先记录，再触发扫描，后续取消不伪报注册失败。此纪律不要求替换纯解析/平台探测的普通 `runCatching`。

作者 TXT 读取在可注入的 `core:data/authorimport`，UI 只交 URI。读前校验扩展名/声明大小，流至多读取 1 MiB+1，再用实际 SDK JSON 字节核对 1 MiB 请求上限（含文件名与转义）；大小未知或假报仍受流上限保护。保留既有 UTF-8 解码（BOM 不特判、非法字节替换），不增加编码支持。合成流/JVM 与浏览器验证不代替 SAF provider/设备验收。

统计主/详情页的窗口总量、互斥分类、有浏览文件/作者/标签总数均直接读服务端；多系列趋势一次读取同轴维度，不再逐维请求或用均值/榜单长度反推。并发取数由请求代际与取消保护，失败显示明确错误和同档重试。SDK 缺少新统计字段时提示同步更新服务端，不回退伪零值。

统计主页、分类型及来源趋势共用 QimengTrendLineChart：显示折线、面积、数据点与日期标签，不绘制背景水平网格线；此次仅改变 Android 图表渲染，不改变事件、窗口或统计公式。

首页默认 COS 与常规推荐共用同一取数/分批/换轮状态机，分别保留 seed 和清单，COS 请求显式 `cosOnly=true`。下拉换批不报“已是最新”；推荐公式未变，小库/评分约束下仍可能同序。非默认筛选/排序继续使用 COS 资产游标列表，重置面板恢复推荐；切模式、刷新及缓存标脏都会作废旧代响应，保留常规/COS 隔离。

- 导航：QimengNavHost 保留会话分支、路由装配与常驻层 owner/saveable 状态；Routes 管路由/编码，TabNavigationPolicy 管点击防抖/回顶/顶层跳转，ResidentTabScreen 与 ClassicBottomBar 只渲染各自部分。恢复/隐藏屏生命周期与触摸隔离顺序保持。
- 详情：DetailUiState 独立声明；DetailTagEditor 接受 VM 的同一 StateFlow、scope 和详情重拉回调，集中标签草稿/乐观解绑/失败回滚，不增第二份资产态。生命周期、批次与播放打点仍归 DetailViewModel。
- 播放：VideoStage 持有播放器/状态机/方向与 surface 交接，TimelineTagDialogs 仅接位置快照与动作，不读取播放器、不建第二实例。
- 上传：SdkUploadRepository 负责 SDK 与 WorkManager 入队，UploadQueuePresenter 只做 WorkInfo→显示状态和顺序/名称映射；业务失败、取消、挂靠失败保持原终态。新任务的纯文件名 tag 随 WorkManager 保存，重建后未执行条目也可显示原名；旧任务继续原回退，不放源 URI/路径或凭据。

这些是职责提取，不引入新框架或跨 ViewModel 状态同步。导航装配与播放器控制仍有规模，需要按实际改动继续收敛；不按行数机械切分，也不宣称技术债归零。无视觉/手势/协议规则改变；可见设备回归仍须单独执行。

视频增强能力：现有 Media3 原片播放未接入视频超分或插帧；这需要播放器帧/GPU 管线适配，不等于 Go 动态插件加载。用户已决定暂缓，当前不安排实现；状态与触发条件见 [能力地图](../docs/CAPABILITY_MAP.md)，没有引入增强 SDK 或变更播放内核。

## 登录与局域网连接

登录页为本机/NAS双模式按钮：本机连接沿用内置服务启动与原登录验证；NAS包含电脑主机，先找最近成功地址，再按顺序查其余记忆地址，最后广播查当前IPv4局域网。只找到一个候选时自动填入，多候选需点选；候选和成功历史分开标记，历史不代表在线。DataStore保留最近5个成功NAS地址（去重、新到旧），兼容旧单地址槽；本机登录和未确认预置均不污染NAS历史，不保存密码。

地址/密码/当前token仍经原AuthRepository与ServerConfigDataSource流转。发现只产生候选，不自动登录、切换已登录端或迁移上传目标；Wi-Fi/网线切换后回到NAS页或点重新寻找；已登录时服务器设置提供「切换到NAS / 重新寻找影库」，经原登出链进入NAS登录模式，无历史地址也能使用。手填与显式选择不被迟到候选覆盖；页面失去前台、选本机或提交时取消发现，恢复前台重新查找。冷启动自动发现等壳层权限请求结束、页面恢复前台且已授权才发包，避免两份权限请求并发；主动选NAS/重新寻找与登录共用原权限门，拒绝不发包。局域网无法互通/隔离、IPv6-only、旧服务端或容器bridge时可用折叠的手填入口；具体协议与部署条件见[服务端入口](../server/README.md#局域网发现)。

MainActivity显式使用`adjustResize`，按[Android边到边适配说明](https://developer.android.com/develop/ui/compose/system/setup-e2e)接收IME insets，由页面padding/滚动让位键盘，避免系统整窗平移把标题顶入状态栏。

布局沿用中性主题和日间轻影，标题、模式按钮、连接卡、密码和主操作建立层级；内容可滚动以适应窄屏/键盘，地址允许换行，状态不伪称登录成功。新页面源码与实际安装/呈现证据见HANDOVER。

本地小批时间校正使用 App 专属外部 files 目录的 `upload-time-repair.json`，由内嵌服务启动前接线到服务端维护流程；配置的归档根仅供比对相同内容的归档副本。无请求文件时不执行维护，不开放 Intent 或 HTTP 写入口。格式和限制见[服务端入口](../server/README.md#本地上传时间校正)。


### Android 备份文件与恢复入口

当前v2作者段可选携带已下载头像的`avatarData`，SDK透传给内嵌服务端持久保存。资料与图片同步后，作者页继续调用同一认证头像接口，可在本机模式离线显示；旧备份只有来源地址时仍依赖目标端访问外站。已有资料补图条件与请求预算见[迁移专题](../docs/domain/migration.md#作者公开档案)。

## 统一资料目录

资料备份与归档以单一维护根目录和备份恢复/作者TXT/上传归档三个任务承接旧入口。根目录沿已有主共享存储浏览器和所有文件访问授权，创建`当前/作者资料`、`当前/备份`、`上次/作者资料`、`上次/备份`、`上传归档`与`目录说明.md`；备份目录、归档路径在同次DataStore编辑中保存，升级前保存的旧备份目录偏好在下一次导出时改指当前代。旧SAF目录继续可读写，明确选新根目录才切换派生路径。手动与每日自动备份都复用同一目录编排，更新v2、唯一作者主表、可阅读资料和主表索引；作者主表与完整备份按「当前/上次」两代分代、每份文件独立摘要，上传归档留在维护根、不参与轮换。

两代文件先写目录内临时文件再rename原子替换（目录说明等旧单文件仍用AtomicFile），目录编排互斥；上次目录中的同名文件摘要不符、不可读或不是普通文件时拒绝覆盖并保留现场，旧三代文件不删除而只报告可迁移/可清理清单。路径规范化后限定共享存储及固定子目录，拒绝链接逃逸，TXT仍经1MiB实际请求校验，备份有64MiB读取上限。导入、恢复及冲突确认保留原行为。作者资料显示清单顺序和入库记录时间，作者管理增加加入早/晚排序。作品详情作者弹窗使用当前服务认证头像与共享头像渲染件，旧请求迟到不得覆盖新作者/切服状态。

相册解除拖动及惯性滚动中的新缩略图暂停，减少占位等待；后台预取和分页仍复用现有实现。

Android本机模式选择统一根目录时，以master镜像模式绑定当前/作者资料/作者总表.txt；升级前保存的旧镜像路径在下一次导出时改指当前代，旧目录文件保留。先导入TXT再选目录及以后更换目录都将当前作者和实际关联写到新位置。远程连接不把手机路径写给远端。偏好提交失败会恢复先前镜像配置，补偿失败与原错误一并保留。主表摘要识别尚未导入的外部编辑，自动写回暂停并提示先导入；确认导入后的原文可由服务端片段识别，继续合成主表。

统一目录的作者TXT列表只保存文件名，点击导入会重新读取实际文件并沿现有1MiB校验链检查；确认弹窗持有本次读取的内容快照，避免导入较早浏览目录时的缓存正文。

目录备份附SHA-256校验，作者主表与完整备份各保留「当前」「上次」两代、每份文件独立摘要：内容变化时先把当前整代提交为上次再写新当前，相同数据重导出只刷新当前、不挤掉上次。备份页「恢复上次」读取独立的上次代目录，「恢复上上次」与旧布局历史份按只读兼容读取旧三代文件；解析真实文件名后才进入v2校验链，摘要不符或超限按读取失败处理。确认导入前保存本机状态并纳入同一备份链，保存失败阻止恢复，成功后刷新最新当前备份。master镜像与同一快照主表生成复用服务端，客户端不复制作者解析/合并规则。旧布局只读核对与复制迁移已提供repository层方法（`layoutReport()`/`migrateLegacyLayout()`，只复制不删除、不覆盖已有不同内容），维护页迁移入口留待后续接入。

资料维护页面采用紧凑目录摘要、四枚独立分段按钮（备份恢复/作者主表/原件归档/设备领取）与任务卡片。目录已连接后仅显示摘要，完整路径与目录选项按需展开；主动作集中在备份卡。备份导出/导入并排，自动备份精简为开关与完成时间，额外同步工具和恢复须知折叠。作者主表提供目录导入与外部TXT选择，来源移除/重建及镜像维护放入高级折叠区，移除需确认。原件归档采用状态卡与上传入口，完整路径独立展开，保留灰底白卡及深色层次。

## 设备结果包后台领取（task-17，源码已交付）

数据管理 → 资料备份与归档 → 「设备领取」提供最小设置面：设备标签、专用设备 AI 令牌（口令式）与后台领取开关，另有「立即应用」手动触发。设备令牌只用于设备结果包端点（device.apply + ai_clients.device_ids）；导入与两代备份导出仍要当前登录会话。令牌保存后只显示「已配置」状态、不回显明文，可输入新令牌替换或清除；未配置时明确提示登录会话 token 不能用于设备级授权，不提供回退。令牌与登录 token 同存于 client_prefs DataStore（明文落盘的既有威胁模型），不打日志、不写入结果包。**本机内嵌单机模式提供「生成本机设备令牌」**：用当前本机管理员会话调用 POST /api/v1/ai-clients（device.apply + 本设备标签，30 天有效），同名同设备客户端已存在时改走 rotate，创建成功但响应丢失后可再点一次轮换恢复，不会每次点击都新增客户端；该入口只在 127.0.0.1:18430 本机模式显示，401/403 明确提示需要本机管理员会话，不把会话 token 当设备令牌。远端 PC/NAS 模式仍由服务器主机侧 `qimeng ai-client create` 生成后手工填入。设备页另有「最近设备任务」只读区：设备令牌读取最近 20 条，显示状态/创建时间/段数，可刷新，不领取、不应用。本机内嵌模式还可另填「领取服务端地址（可选）」从 PC/NAS 领取：设备端点与回传走远端、段应用仍落本机库；跨端且本轮有段应用成功后会异步触发本机库重扫，媒体二进制仍需先复制到手机库目录，设备令牌必须来自远端服务端。设备页另新增「应用时覆盖作者资料」开关（默认关）：开启后 v2 备份段按 authorProfileConflict=replace 整份替换本机作者档案（含离线头像），关闭=keep 保留本机；跨端把 PC 新资料带到手机时打开。

WorkManager 周期链 15 分钟 + 一次性立即链，unique work 各自串行；远端要求 CONNECTED，本机回环模式放宽为 NOT_REQUIRED；Worker 本身不升级前台服务。执行体先读设置与本机模式拉起（EmbeddedServerController.ensureStartedIfLocalMode + 等端口就绪），再在 **claim 之前**校验本地前置（登录会话、已持久化维护根、所有文件访问）：任一缺失只记录本机提示并结束，任务保持 pending，用户修复后「立即应用」重试，不消耗任务、不回传误导性 failed。随后同时 list pending 与 claimed（claimed 未过期=上次领取后进程被杀/回传失败的可恢复态，claim 对已 claimed 幂等；列表沿 nextCursor 读到 null，最多 20 页 × 100 条，超过上限记录明确提示并结束本轮，不再只看第一页或无限翻页）→ 二次按目标/状态/到期过滤 → claim → 详情 → 校验目标/协议/规则指纹/段清单 → 下载全部段并复核 bytes/SHA-256 → 先导出「当前/上次」两代 → 主表 TXT 走 /authors/import-txt、v2 备份走 BackupValidator + /import/qimeng-backup → 按 manifest expectedReadback 逐段比较（导入响应计数口径）→ 回传 applied/partial/failed + readback + deviceLocalHashes + message（服务端另读库计算 authoritativeState/expectedStateMatches/hashVerified，只展示不改变回传状态）→ 应用后刷新当前代 → 清理 App 缓存临时文件。应用过程中授权被撤/写失败才回传 failed；结果回传 409 先对账终态，不覆盖既有结果。进程被杀后的恢复靠重新查询 claimed 并重放整包（服务端同名 TXT 重建、v2 事件身份幂等），不持久化段级进度。
