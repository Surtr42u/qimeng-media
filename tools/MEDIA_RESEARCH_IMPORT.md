## 逐文件工作单

先递归清点原目录，核对真实扩展名、类型、字节数、摘要、时长/分辨率，图组按独立作品归组。第三方报告是候选证据，报告内的历史操作要求按用户当前指令核对。

每个文件记录以下字段。

| 字段 | 内容 |
|---|---|
| 输入 | 相对路径、大小、SHA-256、作品组、原报告线索 |
| 身份 | 创作者姓名、内部authorId或待建别名、平台handle/稳定ID、归属等级 |
| 作品 | 原始标题/原帖URL、出处、角色、水印、画面比对和匹配依据 |
| 检索 | 查询词、实际搜索服务、时间、响应/截图文件及摘要、是否真的上传反向识图 |
| 主审 | 已确认/待核实、具体审核依据、争议及保留项 |
| 计划 | 目标库、相对目录、规范文件名、组内顺序、已有重名或重复内容处理 |
| 应用 | 原始uploadId、返回assetId/relPath、大小/摘要、作者关联、双端结果与时间 |

Google/Lens截图上传依照当轮用户授权与SECURITY，选择足够辨识作品的必要画面。相同模型、转载标签或同名账号只能作为线索，原帖、水印、稳定账号互链或字节一致等证据分别记录。不同置信度的结论逐项保留。

## 命名与正式入库

1. 读取目标库已有文件名和名称联想，按现有出处、角色规范及序号风格生成候选名。同一图组保持连续组内编号，多个独立作品延续外层序号。目标序号按入库前现状分配，保存原名到新名映射。
2. 先按摘要和已有资产核对重复内容。复制到独立本地暂存区，保留原始文件；正式操作遵守项目的路径、覆盖及回收规则。
3. 通过正式上传/本机同步/扫描入口入库。上传保留同一uploadId与sourceMtime，重试前先查完成事实及返回路径，自动同名改名后的实际relPath回写工作单。
4. 作者挂靠使用资产作者编辑API，复用已有身份和别名。它会回写TXT片段真相及现有镜像，确保重建后关联仍在。主页、数字ID、头像和双语简介写作者附属档案，使用读到的revision，冲突时重新核对现存修改。
5. 证据尚不足的作者继续留待审，作品的实际入库结果与作者身份确认分别记账。

## 手机与电脑同步

本机模式的媒体先行，双端使用可对应的规范文件名和相对目录，再通过v2备份导入元数据。作者资料包携带已下载头像正文，译文仅补同账号同原文的缺省字段，保留现有人工修改。

标签完善后，从修改端导出当前v2备份，在另一端导入。两侧标签组时间都已知时，以较新的整组为准，删除操作也可随较新整组传播；未知时间沿兼容并集合并。匹配率及歧义/跳过必须查看。手机连接电脑服务端时，保存即写同一库。

交付核对双端目标文件大小/摘要、作者关联和样页显示，备份目录与既有手动文件按操作前记录恢复。每轮作者/作品资料包只携带本轮需要的段，避免用过期整库元数据覆盖用户之后的标签编辑。

## 作者总表与当天增量

机器可导入的作者总表继续使用现有TXT解析格式，块编号、别名、作品行及单行来源区按作者领域保持。原导出和导入前片段留摘要与快照，通过正式导出得到最新TXT。

另外生成可阅读资料版，包含生成日期、实际确认数/待核实数、当天新增/修正/同步摘要、作者索引和逐人资料。逐人资料展示内部ID、别名、平台ID、原文/中文简介、核验状态与来源、头像可用状态、关联作品与本轮变更。长链接及证据放逐人小节，索引保持紧凑。当天记录明确区分研究发现、主审确认、电脑应用和手机应用。

真实媒体、作者清单、机器路径、原始响应、设备标识与正式应用结果保存在忽略的本地审计/用户交付目录。仓库正文只保存通用方法、结构和规范。每轮交接更新最新入口、待核实独立文件夹和相对路径/摘要清单，方便下一位AI追溯。
