# 识图与作品归属核实

本指南规定从一张图或一段视频回溯原作品、原帖与创作者的可重复方法、证据分级和成本约定，供主代理与外部 AI 共用。作者身份、平台资料与判定口径见[公开作者身份研究与证据留档](AUTHOR_RESEARCH.md)；逐文件整理入库见[媒体复核与双端整理流程](MEDIA_RESEARCH_IMPORT.md)；研究端点、状态码与证据落盘见[研究流水线 API](../docs/api/research.md)；素材提交与出站边界以[安全专题](../docs/SECURITY.md#作者公开资料出站访问)为准。

真实作者名单、截图、响应、哈希与结论只放忽略的本地目录；本文只写通用方法、结构和阈值。

## 优先序阶梯

先用"定作品"成本最低、召回最高的入口；早停发生在拿到可核验的原帖或稳定作品 ID 时，而不是页面出现同名时。

| 顺序 | 入口 | 用途 | 成本与边界 |
|---|---|---|---|
| 1 | Google Lens（本机 sidecar） | 整图或裁剪帧视觉反查，发现转载页、作品名、签名线索 | 单实例串行，单帧 17–18s（实测 25–40s）；`links` 常为空，`status=ok` 不等于认出作者 |
| 2 | Yandex CBIR | 二次视觉反查，补 Lens 未覆盖的站点 | 结果页结构随平台变化，需复核 |
| 3 | SauceNAO | 绘画/二次元作品与 Pixiv、Twitter 来源 | 配额有限；只按相似度排序，不直接给作者身份 |
| 4 | trace.moe | 动画/视频帧定位作品与时间点 | 仅覆盖可索引的动画；镜头剪辑与二创可能无命中 |
| 5 | 标签库/作品索引：Danbooru、AIBooru、Iwara、rule34、SFM Compile、Kemono | 已标注角色/作品/作者页、转载索引 | 标签由上传者填写，可能错标；同名角色不等于作者 |
| 6 | X（fxtwitter） | 原帖、作者数字 ID、发布时间 | 需先有账号或帖子 ID 线索 |
| 7 | Patreon 公开页、DeviantArt oembed | 创作者主页与公开作品页 | 只读公开页；付费内容不碰，不登录、不截图会员帖 |
| 8 | 容器元数据（ARTIST/PURL/comment） | 原始下载文件自带的来源线索 | 可被转载工具改写或清空，只作线索 |
| 9 | 水印/帧比对（dHash、字节一致） | 确认同作品或同文件 | 需要本机原图或已知样本 |

阶梯不是必须逐级跑完：任一级拿到可核验的原帖或稳定作品 ID 即停，转入身份核验。反过来，身份核验不能替代作品归属——X 上同名账号不等于该图作者。平台核验顺序（X 优先）见[作者研究指南](AUTHOR_RESEARCH.md#平台与简介优先级)。

v1 研究网关只代理 Lens 与固定 provider 矩阵（fxtwitter、pixiv、yandere、e621、wayback、steam、bing）；Yandex、SauceNAO、trace.moe、标签库、容器元数据与哈希比对属于本地或人工步骤，不是 API 端点。

## 提高准确率

### 采样与裁剪

| 手段 | 做法 | 适用与边界 |
|---|---|---|
| 多帧采样 | 视频取 15%/50%/85% 三帧，优先无水印、正脸、全画面 | 任一帧命中即可继续；三帧全空才判定本轮失败 |
| 四角水印裁剪 | 四角各裁约 1/4 区域并放大 2–4 倍 | 水印常含 handle 或签名；可被转载者覆盖或伪造 |
| 面部裁剪 | 人脸占比较大时单独裁剪，给 CBIR | 提高角色图召回；不能据此认定作者 |
| 原图与同尺寸核对 | 用原图或长边 ≥1600px 的版本，核对分辨率与宽高比 | 缩略图、聊天压缩图会让 Lens 命中率明显下降 |

### 比对口径

- dHash 用 64 位（9×8 灰度相邻比较），汉明距离 ≤2 视为同帧；≥16 视为不同作品（常用判定区间 16–40）；2–16 之间必须人工查看或补字节/时长核对，不直接判定。
- 同文件判定 = 字节一致（SHA-256）+ 时长一致（视频）+ dHash 距离达标，三重成立才能写"同文件"；缺一项只写"同作品疑似"。
- 跨平台互链只采用来源页面自身写出的数字 ID（如 Pixiv userId、X 数字用户 ID、Iwara user.id）；第三方目录给出的映射按第三方来源标记，回到平台页核对。
- 排除法记录：每个被排除的候选写 URL、排除原因（同名不同人、转载账号、时间不符、水印指向他人）与日期，与[作者研究指南](AUTHOR_RESEARCH.md#判定与纠错)的 rejected_candidates 同口径，下一轮不重复认领。

### 证据分级

| 等级 | 作品归属所需依据 |
|---|---|
| confirmed | 原帖/官方作品页直接给出作者，并与该作者账号互链；或字节一致 + 稳定作品 ID 与作者页同源 |
| likely | 单一强来源（平台作品页、作者页作品列表）指向同一作者，仍缺独立互链 |
| candidate | 识图命中转载页、水印、标签或第三方索引，尚不能排除他人 |
| unresolved | 本轮没有取得可复核线索 |

`topTitles`/`topDomains`/`cites` 与空 `links` 最高只能支撑 candidate；升级为 verified 必须回到平台接口字段或创作者可控来源。研究阶段一律先写 candidate，主代理复核后才升 verified，判定细节见[作者研究指南](AUTHOR_RESEARCH.md#判定与纠错)。

## token 降本

### 单文件预算

- 每个文件最多 1–3 个 Lens job：整图 1 次；仍不确定才加 1 次四角水印裁剪、1 次面部裁剪。不做"每帧都传"。
- 上传前统一转为长边 1600px 的 WebP（保持宽高比、质量中高），单文件 ≤20MiB；原始文件另存 SHA-256 用于去重和同文件判定。
- 同一 `frameSha256` 缓存命中直接跳过，不重复上传同一帧。
- 失败最多重试 1 次：422 仅在 sidecar `healthz` 就绪后重试一次；429 按 `Retry-After` 等待；502/503/504 不立即重试，降级到下一阶梯或人工。

### 批处理与留档

| 约定 | 做法 |
|---|---|
| 批处理 | 每文件一行 JSONL：文件摘要、SHA-256、尺寸/时长、工具、状态、候选摘要；按行续跑 |
| 断点续跑 | 状态文件记录 frameSha256、查询摘要与时间；只补未完成项，不重跑已完成项 |
| 只回摘要 | 只保留候选标题、域名、URL、平台 ID 与排除理由；不落原文 HTML，不把整页正文塞进提示词 |
| 缓存 | 优先复用本轮或历史证据文件；重启后已完成结论不丢 |
| 留档位置 | 客户端 JSONL 与截图放忽略目录；服务端证据目录只含公开字段与哈希，见[证据落盘](../docs/api/research.md#证据落盘) |

### 限速表

| 情况 | 预算/间隔 | 处理 |
|---|---|---|
| Lens | 默认 20/小时、100/天（可配） | 超限 429，排队而不是重试 |
| provider | 默认 20/分钟/provider | 超限 `status=rate_limited`（仍 200），换 provider 或稍后 |
| sidecar BUSY | 单实例串行，`Retry-After` 至少 2s | 串行排队，不并发重试 |
| BLOCKED_BOT | 503 | 停止该出口 30–60 分钟，人工处理 |
| 超时/不可用 | 网关等待上限 120s | 降级到下一阶梯，最多 1 次有界重试 |

## 水印与容器元数据

先读容器与流标签，再决定是否裁水印；两类线索都只能作为候选证据。

```powershell
ffprobe -v error -show_format -show_streams -of json "<本地媒体>"
```

| 位置 | 字段 | 线索 |
|---|---|---|
| `format.tags` | artist、title、comment、description、purl、copyright、encoder | 原始作者、来源站点、下载/转码工具 |
| `stream.tags` | 同名字段（按流重复） | 多流文件可能只写在某一条流 |
| `format` | duration、size、format_name、bit_rate | 同文件判定用的时长与字节量 |
| `stream` | codec_type、codec_name、width、height、r_frame_rate | 分辨率、帧率与同尺寸核对 |

图片侧读取 PNG `tEXt/iTXt`（Software、Author、Comment、Source）、JPEG EXIF `Artist/Copyright/ImageDescription` 与 XMP `dc:creator`。社交媒体转存通常已清除这些字段，缺失不代表没有作者。

| 线索 | 能证明 | 不能证明 |
|---|---|---|
| ARTIST/PURL/comment | 该文件曾写出这些字段 | 当前账号就是原作者（可被转载工具写入） |
| 水印/签名 | 画面中出现过该标记 | 上传者即作者（可能盗图或覆盖水印） |
| dHash 同帧 | 两帧画面相同 | 作者相同（转载、合集、同一模型） |
| 字节一致 | 文件相同 | 来源合法或作者相同 |

## 与作者核验的衔接

1. 本指南只产出"作品 → 原帖/作者线索"和证据等级，不直接写作者档案。
2. 拿到稳定账号、作品页或数字 ID 后，按[作者研究指南](AUTHOR_RESEARCH.md#查询顺序)核验身份；X 优先，官方平台次之。
3. 头像下载、字段长度与档案写入顺序见[头像与档案写入顺序](AUTHOR_RESEARCH.md#头像与档案写入顺序)。
4. 结论以 candidate 进入候选，主代理复核后才写 verified；写入走正式作者档案 API 与受控填充，不手改数据库。
