# CAPABILITY_MAP - 能力地图

> 本文是用户核心思想「内置一个正常 NAS 软件该有什么」的载体：对照 Jellyfin / Immich / Plex 这类成熟自托管媒体库的应有能力，逐域记录本项目**现状与缺口**。
> **本文是 AI 主动提案的依据**——AI 做新功能前，先对照本图找缺口，而不是等用户撞到问题再补。
> 最后更新：2026-08-31（M2/M3 验收同步：推荐/统计/作者体系/上传整理/标签/监控面板已落地；M4/M5 仍规划中）

## 状态图例

- **已有** = M1 已交付（代码 + 测试 + 文档落地，可运行验收）
- **规划中** = 已列入 PROJECT_PLAN M2-M4 里程碑（标里程碑号）
- **明确不做** = 决策排除（见 ADR-0002/0006/0007 与用户拍板），AI 不得主动提案

## 明确不做清单（AI 提案禁区）

| 项 | 依据 |
|---|---|
| 公网裸端口映射 / 自管 HTTPS 直连 | ADR-0006（只走隧道） |
| 实时转码（播放即转） | ADR-0002 + 用户拍板"查看永远发原件" |
| AI 识别 / 人脸聚类 | ADR-0002 排除清单 |
| iOS 客户端 | ADR-0002（单人手成本） |
| 跨端 UI 框架（Flutter/RN/Compose Multiplatform） | ADR-0008 |
| 公网多租户 SaaS 化 | 产品定位：自托管家庭媒体库（ARCHITECTURE §1） |

## 与文档触发矩阵的关系（三级升级）

- 现状：仓库已有「模块 → 文档」两级路由（`AGENTS.md` 任务→文档路由表，任务驱动）。
- 本图补上第三级「能力域」：**模块 → 文档 → 能力域**。能力域是跨模块的横向切面（如"统计"横跨 events/store/stats/sysmon 多个包与 OBSERVABILITY/DOMAIN_RULES 多篇文档），传统路由表覆盖不到。
- 用法：AI 接任务时先查路由表（找文档），做完功能/提新方案时对照本图（找能力缺口）；两者互补，不互相替代。

## 维护规则（常驻任务）

- 每个里程碑验收后，本图"已有"区同步勾选（与 PROJECT_PLAN 勾选同 commit）。
- 用户新拍板"不做"或"要做"的能力，立即更新本图三态；新能力提案先写 ADR，再入本图。
- 文档漂移检测（对照代码核对本图与 PROJECT_PLAN 口径）是**常驻任务**，见 PROJECT_PLAN 尾部。
