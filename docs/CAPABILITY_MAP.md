# CAPABILITY_MAP - 能力地图

> 本文是用户核心思想「内置一个正常 NAS 软件该有什么」的载体：对照 Jellyfin / Immich / Plex 这类成熟自托管媒体库的应有能力，逐域记录本项目**现状与缺口**。
> **本文是 AI 主动提案的依据**——AI 做新功能前，先对照本图找缺口，而不是等用户撞到问题再补。
> 最后更新：2026-10-01（上传整理行补「归档文件夹一键上传=已有」「本机自动同步=已有（ADR-0030）」「断点续传分片双端接入=已有（ADR-0028）」；备份行补「导入语义=幂等合并」。更早历史见 `CHANGELOG.md`。）

## 状态图例

- **已有** = M1 已交付（代码 + 测试 + 文档落地，可运行验收）
- **规划中** = M7+ 储备或触发条件项（M2-M4 已收官）
- **明确不做** = 决策排除（见 ADR-0002/0006/0007 与用户拍板），AI 不得主动提案

## 与文档触发矩阵的关系（三级升级）

- 现状：仓库已有「模块 → 文档」两级路由（`AGENTS.md` 任务→文档路由表，任务驱动）。
- 本图补上第三级「能力域」：**模块 → 文档 → 能力域**。能力域是跨模块的横向切面（如"统计"横跨 events/store/stats/sysmon 多个包与 OBSERVABILITY/DOMAIN_RULES 多篇文档），传统路由表覆盖不到。
- 用法：AI 接任务时先查路由表（找文档），做完功能/提新方案时对照本图（找能力缺口）；两者互补，不互相替代。

## 维护规则（常驻任务）

- 每个里程碑验收后，本图"已有"区同步勾选（与 PROJECT_PLAN 勾选同 commit）。
