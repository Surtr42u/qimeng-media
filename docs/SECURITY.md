# SECURITY - 安全设计

> 威胁模型：纯内网单用户起步。防御目标 = 局域网内误访问与横向渗透（访客 WiFi、被入侵的智能设备）+ 未来远程访问的暴露面。不防御公网级 DDoS/爬虫。
> 安全要求通过机制与门禁验证，测试要求见本文「安全测试」；实际覆盖及未验收边界如实记录，不将文档声明当测试证据。
> 维护日期：2026-10-20。变更经过见 CHANGELOG 与 git 历史。

## 按任务读取

所有安全相关任务先读红线；再读对应鉴权/开发模式、上传、文件恢复/跨卷、同步、镜像、快照或缓存机制及相关已知边界。纯样式任务不默认通读安全全文。

## 红线清单（AI 改代码时逐条自查）

| # | 红线 | 机制 |
|---|---|---|
| 1 | 路径穿越 | 一切来自请求的路径参数：`filepath.Clean` 规范化 → 前缀校验限制在 Library 根内 → 拒绝 `../` 逃逸。统一在接口层拦截，handler 禁止自行拼接路径 |
| 2 | SQL 注入 | sqlc 全参数化，禁止字符串拼接 SQL（lint 规则卡） |
| 3 | 媒体误删 | DELETE 一律进回收站；物理删除仅在回收站内显式操作；Docker 中媒体目录挂载可写但回收站兜底 |
| 4 | 上传滥用 | 四道校验：扩展名白名单 + MIME 嗅探（读文件头）+ 单文件大小上限 + 目标路径穿越检查。写入用临时文件 + 原子 rename |
| 5 | 无鉴权访问 | 除健康检查与认证端点（setup/login/dev-login）外全部 API 要求 Bearer token；媒体直链用短期 HMAC 签名 URL（默认 6h 有效），禁止裸直链 |
| 6 | 请求体滥用 | JSON body 上限 1MB（例外：旧版备份导入 64MB，errors.go decodeJSONWithLimit / legacyImportMaxBody，单文件全量备份随库规模增长）；分页 size 上限；SSE 连接数上限。**2026-10-17 起全部 JSON 端点强制 `Content-Type: application/json`**：跨站"简单请求"（no-cors + text/plain 等 safelisted 类型）无需 preflight 即可打内网地址，不校验则任意网页可向免鉴权 setup 投递 JSON 抢注密码；强制后跨域请求触发 preflight 被无 CORS 的服务端拒绝（合法 SDK 本就声明 JSON，零行为变化） |
| 7 | 信息泄露 | 错误响应不含内部路径/堆栈（已实现）；访问日志脱敏（token 只记前 4 位）为规划项——访问日志本身尚未实现，见 OBSERVABILITY；/metrics 随全局 Bearer 门禁。**2026-10-17 修复一处例外**：`POST /local-sync/trigger` 的 409 不再透传含绝对路径的通道级 lastErr，固定文案 + 详情只进服务端日志 |
| 8 | 公网暴露 | 永不开公网端口；远程访问只走 Tailscale/WireGuard 隧道（服务端零改动） |

## 文件移动 / 回收站的跨卷安全边界（2026-10-15）

跨卷移动的目标不是「尽量完成」，而是失败时不破坏源文件，也不误删本次操作未创建的目标。`filing.MoveFile` 的自动化测试与真实双挂载点验收分开记录：

| 验收场景 | 自动化门禁 | 真实部署验收 |
|---|---|---|
| 同卷 rename 成功 | Linux/Windows `filing` 单测覆盖快路径 | 非必须；真实双卷测试不能由同卷替代 |
| 跨卷复制成功后删源 | 内容/权限等复制行为单测；Windows 原生 job 覆盖 Windows build-tag | **必须**：源与目标分别放在不同挂载点/卷，确认目标字节一致后源才消失 |
| 目标已存在（包括同名文件/目录） | 单测断言返回冲突、源与既有目标内容都不变 | 必须至少在部署实际使用的文件系统验证一次 |
| 复制/写入中途失败或磁盘空间不足 | 可注入的复制错误由单测覆盖；不能据此声称覆盖真实掉电/设备断连 | **必须**：在隔离合成目录模拟目标卷不可写/空间不足，确认源保留、既有目标不变、无半成品被误认成功 |
| meta 写入失败 / 回滚清理失败 | HTTP/filing 测试检查失败分类与清理边界 | 必须在部署形态检查回收站条目、meta 与文件实体一致；清理失败须可观察，不能删除冲突目标 |
| 目标预检查与提交之间的并发创建（TOCTOU） | 现有单测覆盖操作前已存在目标，不证明跨进程竞态消除 | **已知边界**：Go `Lstat`→`os.Rename` 和 Android 归档的「存在性检查 → 改名/无覆盖发布（`File.renameTo` / `Files.move`）」都不是可依赖的跨进程原子 no-replace 原语；真实测试也不能证明所有竞争都安全。要消除此窗口，需要文件系统/平台原子 no-replace 操作或所有写入方共用的协调。 |

**部署验收操作限制**：只使用隔离的合成测试文件与临时目录，不拿真实媒体做故障注入；不在生产 NAS 上执行磁盘满、拔盘、强杀进程等破坏性测试。记录 OS、文件系统、源/目标挂载点、故障注入方式、HTTP 结果、源/目标/meta 最终状态。CI 的 Linux/Windows 单测通过不等于跨卷端到端验收通过。

## 文件访问与恢复一致性（ADR-0039）

- `PathWithinRoot` 在词法根内限制后，检查库根及所有现存父段，拒绝符号链接和 Windows junction（`Lstat` + `Readlink`）；不存在的末级路径允许后续安全创建。扫描、目录树、预热均跳过链接；原件读取用 `os.OpenInRoot`，直传临时写入/落位、库内移动/回滚、新建目录、恢复/本机同步目标建目录使用 `os.Root` 实际操作。
- **边界**：保留回收站/本机同步跨根 `MoveFile` 与续传跨根硬链接的同卷快路径；这些绝对路径操作及 ffmpeg 路径输入，在检查后被外部进程恶意换链时仍有 TOCTOU 窗口。本次验证静态链接拒绝，不宣称全链路消除该竞争。`os.Root` 也不隔离 bind mount 或硬链接所共享的内容；媒体根、数据根与宿主挂载由管理员控制。根目录本身及其祖先为链接的库会被拒绝，需注册真实路径。
- 扫描失败不再把“不曾成功读取/入库”当成“已消失”：返回部分失败、保留本轮全部破坏性差集；已提交变更仍广播。扫描不持整库长锁，仅在单文件提交和逐条差集持库锁，视频探测留在锁外；合并的候选删除与旧身份更新为同一事务。候选按 size+mtime 分桶，避免批量改名引入平方级 SQL/Stat。
- 恢复先保存 `restore_path/restore_size/restore_mtime` 意图，文件搬回且原资产 ID 持久化成功后才删除 meta。失败可重试同一落点；扫描通过显式意图索引避让，重启后从 meta 重建索引；后台到期清扫跳过此类条目。手动清空/物理删除仍会丢弃该回收站恢复依据，不会据意图物理删除库内媒体。回收站写操作串行防止清扫与提交互相删除 meta；缓存重建/发布与失效互斥，删除失败路径也失效。
- 意图的 size+mtime 仅为版本一致性检查，并非内容哈希证明；跨卷复制保留源 mtime，目标版本不一致时保留文件/meta并报错，避免猜测身份。原子 meta 替换保证普通进程中断下旧文件或新文件可见，**未声称通过真实掉电/磁盘满/跨挂载点验收**。
- 续传封存后拒绝追加；源 `.part` 保留到入库成功或明确放弃/过期。同卷优先硬链接预置，不支持硬链接及跨卷则流式复制。会话记住最终落点，入库失败重试不会生成第二个改名文件。complete、放弃、关闭按会话串行，清扫跳过正在 complete 的会话；已发布媒体不因放弃/清扫而被物理删除。会话仍仅驻内存，重启失效的既定边界不变。

## 鉴权设计

- **单用户起步**：首次启动 `POST /api/v1/auth/setup` 设置管理密码 → 服务端用 `crypto/rand` 生成 token 返回（只显示一次）；后续请求 `Authorization: Bearer <token>`。
- **多设备并发会话（ADR-0021，2026-09-17 起）**：有效 token 哈希存 `auth_sessions` 表（migration 0011）——每次登录/setup/dev-login 签发一条独立会话，多端并存互不挤兑（旧「单 token 签发即重铸」模型废弃，它是手机反复掉线的根因）；`POST /auth/logout` 按请求 token 吊销单条会话，其他设备不受影响；每用户会话上限 16，超限自动裁最旧。升级兼容：旧模型唯一哈希由迁移回填成一条 legacy 会话，已登录设备不掉线。`users.token_hash` 列弃用不删（NOT NULL 兼容占位）。
- 用户表结构第一天就按多用户设计（id/名称/密码哈希/角色/token），实现先只放一行。密码哈希用 argon2id（标准库外选型写 ADR）。
- **auth 端点限速（2026-09-17 起；2026-10-17 计数口径修正）**：setup/login/dev-login 共享进程内固定窗口限速（默认 10 次/分钟，超限 429 `RATE_LIMITED`）——缓冲暴力猜解与 argon2id（m=64MB/次）的内存 DoS；Bearer 业务端点与 /auth/verify 不受限速影响。**计数只发生在真正进入凭据校验路径之前**：dev 模式关闭时的 404（及格式非法的廉价请求）不消耗共享配额——否则未鉴权方可把窗口打满、让管理员 setup/login 永久 429（2026-10-17 审计修复）。窗口仍是进程级共享（不区分客户端 IP），属已知可用性边界：单用户内网下接受，若未来多客户端形态出现再按 IP 分桶。
- **安全响应头基线（2026-09-17 起；2026-09-22 补 frame 头）**：全部响应带 `X-Content-Type-Options: nosniff`（MIME 嗅探防护）+ `X-Frame-Options: DENY`（点击劫持防护——SPA/验收页/管理页禁止被第三方 iframe 嵌套；`<img>`/`<video>` 标签消费媒体直链不受 framing 头影响）。
- **签名直链**：`/media/orig/...?exp=...&sig=HMAC(路径+过期时间, 服务端密钥)`——浏览器/播放器无需带 header 即可加载，但链接有时效。**exp 窗口对齐（ADR-0027，2026-10-01 起）**：exp = 下一窗口上界 + TTL（窗长=TTL=`token_ttl` 缺省 6h，对齐 Unix 纪元整点），同一窗口内所有响应签出**逐字节相同**的 URL（浏览器 HTTP 缓存/ETag 得以命中，URL 格式与参数未变、三端零适配）；有效期恒 ∈ (6h, 12h]，**吊销粒度=窗口级**——泄露直链最长存活约 2×TTL（粗于旧「请求级 6h」，风险接受换缓存命中），总闸不变 = 删除 media-secret 文件换密钥立即吊销全部存量直链。
- token 泄露应急（多会话模型口径）：受控设备直接 `POST /auth/logout` 吊销对应会话；**注意「自己再登录一次」不再吊销旧 token**（旧模型的挤兑行为已废除）。全部会话吊销 = 停服清空 `auth_sessions` 表（或删除数据目录重建）；直链吊销仍走删除 `media-secret` 文件。「管理端一键重置全部 token」为规划项。

## 开发模式（红线 5 的受限例外）

- **默认关闭**：`config.auth_dev_mode`（env `QIMENG_AUTH_DEV_MODE`）默认 false；关闭时 `POST /api/v1/auth/dev-login` 恒 404，所有 API 依旧要求 Bearer token——生产/默认部署零行为变化。
- **开启时语义**：`/auth/dev-login` 免密码直接签发 token（未初始化自动创建 admin 占位用户；多会话语义与 /auth/login 相同，ADR-0021——签发独立会话，既有会话不失效）。
- **App 端免密通道（2026-09-06 起）**：Android 客户端登录时**密码留空即走 dev-login**（`AuthRepositoryImpl` 空密码分支）；服务端未开启 dev 模式时 404 → App 提示「该服务器未开启免密模式，请输入密码登录」并要求密码，生产部署零影响。纯客户端行为，协议面无改动（dev-login 端点 2026-09-03 即有）。
- **内嵌形态共享密钥门禁（2026-09-30 批A）**：服务端配置 `auth_dev_shared_secret`（env `QIMENG_AUTH_DEV_SHARED_SECRET`）时，`/auth/dev-login` 须携带 `X-Qimeng-Dev-Secret` 请求头且匹配（`subtle.ConstantTimeCompare` 恒时比对）否则 401。**校验顺序（2026-10-17 起）= dev 模式 404 → 限速 → 共享密钥 401**：404 语义优先、不泄露密钥配置状态；404 在限速之前，使生产形态下未鉴权请求无法靠打恒 404 端点耗尽共享限速配额；401 在自动建户之前，越权者触发不了占位用户创建。**未配置密钥时零校验零影响**（Web 端 bat 免密/日常开发完全不变）。Android 内嵌形态由 `EmbeddedServerConfig.generateDevSharedSecret()` 每次拉起子进程随机生成（SecureRandom 32 字节 URL-safe，256bit 熵下限），经 ServerConfigDataSource **内存槽**（不落盘不进日志，生命周期=子进程）供 devLogin 同源带出。
- **适用边界**：默认仅本机调试；日常 PC 启动链的 dev 免密 + LAN 监听是用户明确接受的受信家庭内网例外（见「通用响应与后台可靠性」）。同 LAN 不可信设备可免密取得 admin token，例外不适用于访客网络、生产或远程/隧道访问；这些场景必须关闭 dev。非回环监听的 Warn 仅提醒，不是防护或拦截。
- **本机开发脚本**：仓库根 `_server-common.cmd`（两份 `启动服务端*.bat` 共用的启动链单点）已默认带 `QIMENG_AUTH_DEV_MODE=1`（2026-09-03 起）——生产/远程部署**必须移除该行**（或改回 `0`）。
- 部署清单检查项：docker-compose / 生产 yaml **不得**出现 `auth_dev_mode: true`（CI 不做强制 gate，靠部署者自查 + 文档双签）。

## 媒体库注册（allowed_library_roots）

- **配置键**：`allowed_library_roots`（yaml）/ `QIMENG_ALLOWED_LIBRARY_ROOTS`（env，路径列表，`;` 或本平台 `os.PathListSeparator` 分隔）。
- **空 = 关闭**：默认空列表，注册行为与本开关引入前一致——任意服务端可访问的绝对目录均可注册（本地零配置开发不受影响）。
- **非空 = 强制**：`POST /api/v1/libraries` 的 `rootPath` 必须位于任一允许前缀之下（含前缀本身，路径 Clean + 大小写不敏感），否则 400 `INVALID_PARAM`「库路径不在允许的根目录白名单内」。白名单外路径不探测文件系统，避免存在性侧信道。
- **生产建议**：NAS/Docker 部署务必配置，把注册面收敛到已挂载的媒体卷（如 `/media`、`/mnt/photos`），防止误把 `/`、系统目录或无关共享挂进扫描/直链管线。该白名单只约束**新注册**；已入库的库不受影响（改配置不会追溯删除既有库）。

## 上传安全（对应需求：手机直传 NAS）

Android 持久上传任务在入队固化服务器 base URL；直传、分片会话及后续作者/来源挂靠绑定同址，切服/旧任务无目标则拒绝并显示失败，不向新端续传，且关闭自动重定向。已发出的请求仍可能在原端完成；绑定请求的迟到 401 核对当前地址和 token 后才处理。此措施不提供同 URL 下的服务端 UUID 识别，也不承诺条件清 token 的原子性。测试与设备边界见 ADR-0042/RESTORE。

- 白名单：图片 jpg/jpeg/png/gif/webp/avif；视频 mp4/mkv/webm/mov/m4v/avi。
- MIME 嗅探按文件头魔数判断（不信 Content-Type 声明）。
- **ffmpeg/ffprobe 输入协议白名单（2026-10-17 起）**：缩略图/抽帧/探测调用统一带 `-protocol_whitelist file`（输入只允许本机文件协议）。库内媒体属不可信输入（互联网下载/手机直传），ffmpeg 按内容选 demuxer，HLS/concat 等可引用外部 URL 或本地路径——不加限制时恶意媒体可让 ffmpeg 抓取内网 URL（SSRF）或读取服务端本地文件，并经"缩略图成功/404"形成侧信道，同时扩大解码器 CVE 暴露面。新增输入形态（如管道）须在此扩展并同步测试。
- 文件名清洗：去路径分隔符、控制字符、Windows 非法字符 `:*?"<>|`；冲突自动追加序号。
- 流式落盘（禁止整个读进内存），临时目录写入完成后原子 rename 到目标。
- 挂靠参数退役注记（2026-09-25，ADR-0024）：上传曾有的可选作者/来源 query（`authorId`/`authorName`/`source`，ADR-0023 曾设收流前 fail-fast 校验：互斥/依附/上限/能力限定/控制字符拒绝）已**整体删除**——上传回归纯四道校验路径，参数面仅 libraryId/dir/filename，原「控制字符可向 TXT 片段注入任意行」的注入面随参数一并消失。程序化写 TXT 的新入口是作者编辑端点（PUT /assets/{id}/authors、PUT /authors/{id}/sources、PUT /authors/source-vocabulary，ADR-0024）：资产作者关联只接受既有作者 ID（不接受自由文本新建），来源词仍逐项拒绝控制字符（单项超 500 rune/原始数组超 32 项 400）——行文本一律由服务端构造，不存在用户自由文本拼行面；既有四道校验与上传行为不变。
- 上传速率/并发上限为规划项（尚未实现）：当前防线 = 单文件大小上限（配置 + 设置页 kv 双层取小）；速率/并发档位待 NAS 实机压测后立项。
- **分片续传通道的四道校验分布（ADR-0028，2026-10-01）**：`POST /uploads` 创建会话时做**可前置的三道**——文件名清洗（第④道规则，禁止路径穿越）、扩展名白名单（第①道）、size ≤ 上限（第③道），另与直传同闸 `upload.autoAccept`（false 时两通道一起 403，防分片通道成为直传被关后的旁路）并要求库存在且启用；`POST /uploads/{id}/complete` 对拼装完成的整文件做**终检**——魔数嗅探（第②道，读拼装文件头）+ 四道复跑（`filing.ValidateUpload` 同一函数）+ 目标路径穿越检查，终检失败会话保留可重试。分片字节落 `DataDir/uploads-tmp/`（服务端私有数据根，**不入库目录**——未过四道校验的半成品绝不进媒体面；.part 后缀在媒体白名单外，目录误配进库也不会被扫描器收）；入库走与直传完全相同的管线（临时文件+原子 rename、单写事务）。会话/分片生命周期：无活动 24h 过期清扫连临时文件回收、关停尽力清理；全部操作 Bearer 鉴权（无匿名豁免）。同名冲突语义与直传一致：自动重命名，永不 409。

## 客户端归档与服务端文件移动（2026-10-15 边界加固）

- Android 归档的库目录必须是归档根的真实直接子目录：通过规范化路径检查拒绝 `..` 逃逸与指向根外/其他库的符号链接目录别名。源/目标文件名拒绝路径分隔符、控制字符及 Windows 非法字符，降低手机端归档复制到桌面系统后路径含义改变的风险。
- 同卷归档优先**无覆盖改名**（存在性检查 + `File.renameTo`，瞬时且绝不复制）；跨卷才走受控复制（唯一 `.part` 临时名 + 无覆盖发布 + 失败只清本次临时文件）。**不用 `Files.getFileStore` 判定卷**：Android 上它恒抛 `SecurityException`（AOSP SELinux 策略），吞异常后会把每次归档静默退化成整文件复制（2026-10-15 审查缺陷，见 ADR-0038）；也**不把跨卷交给 `Files.move`**——libcore 会自行 copy+删源，绕开受控路径。
- 对 `content://` 归档，目标先写入 `.part` 再改名；目标同名且内容不同则使用冲突序号，绝不覆盖。发现同内容目标时保留目标；由于通用 SAF URI 无法可靠判定是否与目标是同一物理文件，不尝试删除该 URI，避免把归档本体一并删除（代价是可能保留重复源文件）。
- 服务端跨卷搬移在调用 `os.Rename` 前拒绝已存在目标，复制回退通过 `O_EXCL` 独占创建目标；回收站清理逻辑识别目标冲突后不把既有目标当作本次半截副本清理。复制失败后的残留清理仍使用保守的文件大小判定。
- **边界说明**：标准跨平台 `os.Rename` 的目标预检查与重命名之间并非所有操作系统都提供原子 no-replace 语义。应用内通过文件/库操作协调缩小竞争窗口，跨卷 copy 使用 `O_EXCL` 二次保护；但对同一文件系统上由外部进程在检查后并发创建目标的极小竞态，不宣称已完全消除。涉及真实双挂载点的部署仍应做端到端验证。

## 本机同步通道（ADR-0030，2026-10-01 起）

- **配置显式启用**：`QIMENG_LOCAL_SYNC_ROOT`（yaml `local_sync.root`）非空才启用，**空 = 关（默认）**——这是唯一开关形态，不设独立 enabled 布尔（防「路径与开关互相矛盾」的误配组合）。未配置时调度不启动、`/local-sync/trigger` 恒 409 `LOCAL_SYNC_DISABLED`，零攻击面。
- **根重叠禁令（双向含相等）**：同步根与任何已注册库根、服务端 DataDir **一方包含另一方或相等**一律拒绝——通道级错误不启动（status lastError 可见），防同步管线与扫描器/回收站/备份快照互相搬动对方管辖的文件。
- **四道校验与 autoAccept 闸与直传同权**：媒体入库走 `filing.ValidateUpload` 同一函数（扩展名白名单/MIME 魔数嗅探/大小上限/目标路径穿越四道缺一不可），受 `upload.autoAccept`（false 时媒体暂停处理）与 `upload.max_bytes` 同闸——自动通道不构成绕过上传管线的旁路，入库管线（含落位 size 复核）与直传完全一致。
- **隐藏条目与符号链接不处理**：点前缀隐藏文件/目录（含 `.synced` 归档目录自身）与符号链接一律跳过计入 ignored，不给软链/伪装入口进管线的机会。
- **子路径规范化 + 根内限制复用**：递归扫描所得子路径经 NormalizeRelPath + PathWithinRoot 校验后才映射库内子目录，同步源内的路径穿越不可能落位到库外（红线 1 同一机制）。
- **`.synced` 为内部目录**：TXT 导入成功的归档位置 `<同步根>/.synced/`，不入库、不外显（不进资产/事件面）、同名加序号绝不覆盖既有归档。
- **TXT 恒 keep**：作者片段导入 `conflictResolution` 恒 keep（无人值守通道绝不 remove）——重导入保护语义下永远并回缺失条目，绝不静默丢弃既有上传登记；仅 UTF-8（剥 BOM）、10MB 护栏。

## 回收站（可写目录的安全补偿）

- 位置：数据目录内（`/data/trash/`），与媒体库隔离。
- 结构：保留原相对路径结构 + 元数据 JSON（原路径/删除时间/asset_id）。
- 恢复：原路径被占用时冲突重命名。
- **到期自动物理清除（2026-09-22 实现原规划项）**：后台清扫按 `trash.sweep_interval`（默认 1h，env `QIMENG_TRASH_SWEEP_INTERVAL`）巡检，超过 `trash.retention_days`（默认 30 天，env `QIMENG_TRASH_RETENTION_DAYS`）的条目物理清除并联动清理缩略图缓存；trash 列表 ExpiresAt 按生效保留天数返回（DOMAIN_RULES §9）。误配兜底：retention <1 永不判过期（`filing.TrashExpired`）。
- 清空回收站 = 二次确认的显式管理操作。

## Host 校验（DNS rebinding 防御，2026-09-22 起）

- **威胁形态**：恶意页面把自有域名解析到内网 IP，其页面对本服务的请求在浏览器同源判定下"看起来同源"——本服务无 CORS 输出、Bearer 走 Authorization 头，正常跨域读取默认被拒，但 rebinding 伪同源绕过这层；dev 免密形态下 `dev-login` 等于凭空送出 admin token，未初始化形态下 `setup` 可被抢跑。
- **机制**：最外层中间件校验 Host 头——默认白名单 = IP 直连（v4/v6 字面量）+ `localhost`，其余一律 403 `INVALID_PARAM`。局域网/隧道的既定访问形态全是 IP 或本机名，**默认零配置零影响**；空 Host（HTTP/1.0 古董客户端）放行（rebinding 必须携带攻击者域名，空 Host 不构成该向量）。
- **域名访问**：需要域名（如 Tailscale MagicDNS 主机名）访问的部署，把主机名加入 `trusted_hosts`（yaml）/ `QIMENG_TRUSTED_HOSTS`（env，`,` 或 `;` 分隔）；匹配大小写不敏感。
- 测试锁定：`httpapi/host_check_test.go`（判定表驱动 + 中间件端到端，含伪 IP 域名 `192.0.2.5.evil.com` 拒绝用例）。

## 备份快照（库文件热备，2026-09-19 任务Q 批B 起）

- **快照是敏感数据**：快照 = 完整 SQLite 库文件（VACUUM INTO 产出），内含 argon2id 口令哈希与全部行为/库登记数据——拿到快照 ≈ 拿到整库（离线爆破口令哈希面）。备份目录位于 `DataDir/backups/`，不出服务端私有数据根；运维做异地保管/上传网盘时自行承担同等密级责任，建议加密后传输。
- **端点面三道防线**（POST/GET /backups、GET /backups/{name}/file、DELETE /backups/{name}）：
  1. **鉴权**：全部走既有 Bearer 中间件（无 security: [] 豁免；无 token 401，进 CI 安全测试清单）；
  2. **文件名白名单**：{name} 严格匹配 `^qimeng-\d{8}-\d{6}\.db$`，任何带路径分隔符/扩展名变体/目录段的输入一律 400 INVALID_PARAM（快照名完全由服务端生成，白名单外的都当穿越探测处理）；
  3. **os.Root 目录锚定**：下载/删除的文件访问经 `os.Root` 打开并锚定在备份目录内（Go 1.24+，原生拒绝绝对路径与 `..` 段），白名单误放行时的第二道闸（与 spa.go/trash.go 同一标准库底座）。
- **删除语义**：DELETE /backups/{name} 是物理删除（快照可由 VACUUM INTO 随时再生，不走回收站——铁律 4 的「媒体文件回收站」语义不覆盖服务端自产的库文件副本）。
- **扫描自噬**：备份目录在 DataDir 内，若 DataDir 被误注册为媒体库，既有扫描自噬两道防线已将其排除（与缩略图/回收站同待遇），快照文件不会被扫进媒体面。
- **恢复流程（文档化手动操作）**：停服 → 用快照替换数据目录中的库文件（`qimeng.db`，注意 WAL/SHM 伴生文件一并清理）→ 起服。v1 无在线恢复端点（防误操作把「恢复」变成「覆盖现库」的单按钮事故）。

## 作者总表镜像（唯一例外写点，2026-09-25 起，ADR-0023）

- **路径由用户显式配置**：`GET/PUT /api/v1/authors/mirror` 配置镜像目标（持久化 kv_settings `author_mirror`）；path 空=关闭（默认），非空必须是**绝对路径**（相对路径 400 INVALID_PARAM），PUT 走既有 Bearer 门禁。**能力口径（2026-10-17 审计修正）**：配置生效后，服务端确实获得「向该绝对路径原子覆写 UTF-8 文本」的能力——这是本项目服务端写「数据目录/媒体库之外」路径的唯一例外，属**认证后的高权限原语**（等价于可覆盖任意文本文件），不是"仅在数据目录内"的受限功能；因此镜像路径必须只指向本机 TXT 数据文件，**禁止指向可执行文件/启动脚本/配置文件/`authorized_keys` 等敏感目标**。无配置即无写点，配置动作本身有鉴权；token 保护等级按最高档执行（见「token 泄露应急」）。
- **写法与故障语义**：镜像单向（服务端→本地），本地 txt 手改会被下一次服务端变更覆盖；写入=临时文件+rename 原子落盘，**尽力而为**——失败仅 slog Warn，绝不阻塞/回滚资产作者/来源编辑、TXT 导入等核心操作；未配置或目标片段不存在时跳过，路径恢复后下一次变更自动补写。刷新挂点=资产作者/来源编辑保存后（ADR-0024，上传挂靠入口已退役）/TXT 导入落库后（含 keep/remove 结果）/片段删除后/镜像配置保存后/**备份导入的 TXT 片段段后/本机同步通道 TXT 导入后**（后两处 2026-10-11 补齐，见 CHANGELOG 第五百二十五笔——此前这两条写入路径不刷镜像，桌面镜像会长期落后于片段真相）/（rebuild 不改片段不挂）。

## 仓库卫生（密钥与隐私不入库，2026-09-30 开源前审计建立）

- **红线**：明文口令/令牌/密钥/共享密钥、设备序列号、内网拓扑细节、含用户名的本机绝对路径，一律不得进入任何被跟踪文件——代码、配置、测试、文档（CHANGELOG/HANDOVER 等记录性文档一视同仁）。

## 通用响应与后台可靠性

以下是现行机制；实施经过见 CHANGELOG 第五百三十六笔。

- **JSON Content-Type 强制**（红线 6 已同步）：全部 JSON 端点拒绝非 `application/json` 请求体，关闭跨站简单请求打未鉴权 setup/登录的伪造面。
- **auth 限速计数顺序修正**：dev 模式 404 与格式非法请求不再消耗共享配额；窗口仍为进程级共享（不区分 IP）的已知可用性边界已记档。
- **明文 token 响应加 `Cache-Control: no-store`**（setup/login/dev-login 三处统一 `writeAuthToken`）。
- **ffmpeg/ffprobe 输入加 `-protocol_whitelist file`**：阻断不可信媒体的外部 URL/本地路径引用面。
- **local-sync trigger 409 脱敏**：通道级 lastErr（可能含绝对路径）只进服务端日志，响应固定文案。
- **可靠性同批**（非攻击面，但影响可用性与数据安全兜底）：后台任务统一 `safego` panic 兜底、优雅关闭超时不再 `os.Exit(1)` 跳过清理、HTTP Server 增 IdleTimeout/MaxHeaderBytes、SQLite 连接池显式上限（每连接 32MiB 页缓存 × 不限连接的内存放大）、facets 并发限 4、缩略图预热单飞、回收站恢复残留清理补 `ErrMoveDidNotCreateTarget` 哨兵（ADR-0038 三调用点一致）。
- **用户拍板保留项**：日常本机启动链的 `QIMENG_AUTH_DEV_MODE=1`（`_server-common.cmd`）与 `:8420` 局域网监听**保持现状**（用户本人使用）。这仍是「免密登录通道暴露给整个局域网」的风险接受项：仅限受信家庭内网，生产/远程部署必须关闭 dev 模式（见「开发模式」节）；同 LAN 的不可信设备（访客 WiFi）可免密取得 admin 的风险由用户承担。

## 已知安全边界（2026-09-17 全检审计记档，均为风险接受而非遗漏）

- **App 全局明文 HTTP**（`usesCleartextTraffic`，无 network_security_config）：局域网 http 是既定部署形态（本机 18430 与 LAN 8420 都是 http），远程访问走隧道兜底（红线 8）。network_security_config 只能按域名放行明文、无法表达「任意私网 IP 放行、其余拒绝」，收窄会直接断掉核心场景，故维持现状；陌生 WiFi 下连局域网地址时 token/媒体明文过空口属用户责任边界。
- **Android 内嵌形态回环共享风险的现行缓解**：Android loopback 全设备共享。App 拉起子进程时随机生成 256bit 共享密钥并经内存槽注入；dev-login 校验 `X-Qimeng-Dev-Secret`，不匹配 401。不能因为地址是 127.0.0.1 就认为同机其他 App 不可访问；Termux 未覆盖该缓解的边界见下一条。
- **Termux 形态 A dev-login 是共享密钥缓解的漏网路径**（2026-10-03 记档）：`deploy/termux/qimeng-start.sh` 同样以 `QIMENG_AUTH_DEV_MODE=1` 绑 127.0.0.1:18430，与上条同一台设备共享回环，但**没有**共享密钥门禁——同机恶意 App 可直接 `POST /auth/dev-login` 免密取得 admin token（后果同上条）。内嵌形态 B 已用随机共享密钥缓解（`X-Qimeng-Dev-Secret`），Termux 形态 A 是该缓解未覆盖的路径。理论缓解 = 密钥落 `~/.qimeng/`（权限 0600）+ App 侧取用，但 App 跨沙箱读 Termux 私有目录无标准通道、如何把密钥交给 App 需产品决策——暂记边界待立项。
- **App token 明文 DataStore**：2026-09-06 风险接受决策（代码注释记档）。2026-09-17 补备份排除规则（`dataExtractionRules`/`fullBackupContent` 排除 `server_config.preferences_pb`）——明文本机落盘在接受范围，随系统/云备份外带不在，已关闭。2026-10-03 审查批扩排除面：暂存浏览事件 Room 库（`databases/qimeng_events.db` 及 `-wal`/`-shm` 三文件，两规则文件同集排除）——行为数据随系统/云备份外带面一并关闭；`client_prefs`（UI 偏好 + 搜索历史）维持可备份（低敏感口径，风险接受）。
- **web token 存 localStorage**：Bearer-SPA 常见取舍（XSS 可读面）；多会话模型下泄露后果收敛为单会话（可 logout 吊销），维持现状，有实测需求再动协议（cookie/刷新机制）。

## 远程访问姿势（将来启用）

NAS 与手机均装 Tailscale（免费档够用），登录同一账号组成虚拟内网。服务端 HTTP 不变，加密由隧道保证。**禁止**自行在路由器做端口映射 + 反代裸露服务。

## 缓存与便携备份边界（ADR-0040）

v2 备份只携带库名/库内相对路径及身份，不导出服务器绝对库根。新增元数据段仍受 64MB 鉴权 JSON 上限约束；非法 v2 在任何写入前拒绝。缩略图过期版本响应 no-store，未带版本的旧直链须重验证；版本选择不扩大媒体签名授权，路径/过期时间验签不变。表示版本依赖扫描器 size+mtime，不能证明相同大小/时间戳的恶意原件改写；内容哈希仅作为实际缩略图强验证器。

推荐顺序缓存最多 32 流/100000 个 ID；超预算不截断候选，仅退回冷算。快照页重新检查存在/启用库/媒体/COS 资格，协议响应和签名 URL 不持久缓存（ADR-0046）。Go 构建与扫描读取 go.mod 的安全补丁版本，lint 使用同工具链从固定源码构建；Web 已移除未使用的 shadcn CLI 漏洞链，安全扫描不添加忽略项。

Go 1.27.2 的导出格式要求升级 lint 至 v2.15.0；新增 G703 污点检查对 MoveFile 的四个底层文件调用给出跨函数校验误报。只在这四行标注 G703 及调用方 NormalizeRelPath/PathWithinRoot 依据，不关闭规则，不豁免 depguard，也不把既有外部换链风险写成已解决。根边界和跨卷场景继续由 filing/httpapi 的安全回归覆盖。
