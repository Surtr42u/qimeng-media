# 备份、迁移与恢复演练

只在隔离目录和隔离端口演练，禁止向 8420 真库写测试数据。先读 [文件安全](SECURITY.md)；格式和合并口径见 [备份 API](api/backup.md) 与 [迁移规则](domain/migration.md)。

## 三类副本的用途

| 副本 | 包含 | 不包含/限制 |
|---|---|---|
| `/export/qimeng-backup` v2 JSON | 行为事件身份、收藏等便携元数据、TXT 片段 | 不含媒体字节；目标先入库，再按映射合并；不能代替整库恢复 |
| `/backups` 在线 SQLite 快照 | 快照时刻的库登记、资产/关联/事件、设置和凭据哈希 | 不含媒体、回收站文件和独立密钥文件；默认仍在同一 DataDir，不是异机灾备 |
| 停服后的完整 DataDir + 全部媒体根副本 | 数据库、回收站/meta、密钥、媒体与部署配置分别保存 | 必须同一停写窗口；缓存可重建，秘密与原件不可由 DB 推导 |

原件副本保存目录层级、大小、mtime，并生成 SHA-256 清单核对字节。副本放在独立存储；复制完成、恢复核对前不要释放手机/原机文件。备份与清单按敏感数据保管，真实绝对路径、凭据和哈希明细不要提交仓库。

## 新环境恢复步骤

1. 记录服务端版本、schema、库根到新挂载点的映射与副本时间；保存忽略的配置和 DataDir 中独立密钥（如媒体签名密钥）。暂停各客户端写入与同步。
2. 正常停止源服务端，确认进程退出。冷拷贝整个 DataDir（包括仍存在的 SQLite `-wal`/`-shm`）及所有媒体根；不要在写入时单拷贝 `qimeng.db`。在线备份只从已完成的 `/backups` 快照取得。
3. 目标用独立空目录、独立端口、相同或兼容的新版本，先恢复副本并核对清单；保持旧环境停写。若选在线 DB 快照，把它放进**全新空** DataDir 的配置 db_path（默认 `qimeng.db`），独立恢复原件与必要配置/密钥。不得把新快照与旧环境遗留 WAL 混用；不得直接覆盖仍运行的库。回滚保留整个旧目录，禁止通过删除真实 WAL“修复”。
4. 整库恢复保留原库 ID/绝对库根；优先用挂载映射保持原根可达。路径无法维持时选便携 v2 迁移流程，在目标注册/扫描媒体后合并；禁止手改运行库路径。schema 升级用已有 migration，旧程序不能直接打开已升级库。
5. 先验证健康与鉴权、库根权限/可达、样本播放与缩略图，再核对资产数、收藏/点赞、原事件身份/时间、作者/TXT 和原件 SHA-256。扫描前确认全部根在线，防把未恢复文件误当删除。快照和原件时间不同步可能出现缺失/孤立记录，不能只凭健康检查成功宣布恢复完成。
6. 仅目标验收后恢复客户端写入；重新登录并清除旧签名 URL 缓存。旧环境保持只读或停机，保留可回滚副本。NAS 上另验收重启、卷权限、失联和实际备份介质恢复。

## 可重复自动化

以下维护操作由 AI 执行，不要求用户手写命令。`tools/cold_backup.py` 只复制和核对显式传入的目录，不会停服或猜测真库位置；执行 AI 必须先正常停服并确认所有写入/同步已暂停，再使用 `--offline`。首个 source 放完整 DataDir，后续按本地记录顺序放全部媒体根与仓外配置目录；root-1/root-2 等顺序及实际挂载映射保存在忽略的本地记录，不提交真实路径。

```bash
python tools/cold_backup.py create --offline --source <停服DataDir> --source <媒体根> --destination <不存在的副本目录>
python tools/cold_backup.py verify --backup <副本目录>
python tools/cold_backup.py restore --backup <副本目录> --destination <不存在的隔离恢复目录>
```

工具复用 shutil.copytree/copy2，保留层级/mtime，逐文件 SHA-256 核对源与目标；拒绝静态链接/特殊文件、源目标重叠、已有恢复目标、缺失/多余/损坏文件和非法清单路径。复制失败保留无完成清单的半成品供 AI 排查，不自动递归删除。清单最后生成，包含相对路径、字节数、mtime 和 SHA-256，不保存源绝对路径。`--offline` 是执行者确认，不是自动检测停写；逐文件核对不能证明跨文件同一事务快照，也不消除外部进程恶意换链竞争。工具不证明副本介质独立，AI 仍须选择独立存储并按上文核对恢复业务内容。当前仅隔离合成目录自动化验证，不据此声称已备份真实媒体或完成 NAS/掉电验收。

## AI 升级与回退执行清单

1. AI 先在干净检出完成当前 head 必需门禁，正常 `go build` 保留 VCS 信息；`qimeng-server -version` 核对版本/提交/dirty。版本单源及 Android 安装序号见 [服务端入口](../server/README.md#构建身份)。
2. 使用 `python tools/release_manifest.py --server <本机服务端产物> --web <Web构建目录> --output <忽略的交付目录/新清单.json>` 生成产物 SHA-256、schema 版本、协议/SDK 锁摘要。缺/旧提交和 dirty 正式产物拒绝；`--development` 仅供工作区验证，不能算正式发布。该工具只直接验证本机服务端身份，Web/APK 哈希只标识所给文件，不能替代其构建来源、APK 签名/内嵌 Go 检查。
3. 停写后建立上述完整副本，保存匹配的旧二进制、Web/APK、配置与本地根映射；升级前完成副本核对。新版本先在隔离恢复目录验证迁移和样本业务；通过后再替换日常包并记录实际运行身份。
4. 升级后失败时正常停服，使用**新的空目录**恢复升级前完整副本并使用匹配的旧程序；不让旧程序打开已升级库、不对真实库执行 down、不覆盖运行库、不删除真实 WAL。恢复窗口之后新增的媒体/事件需独立核对，不能承诺换回旧程序即可无损回退。
5. 源码、检查通过、已准备产物、已部署分别记入 HANDOVER；不把交付清单的 deployment=not-performed 改写为装机证明。NAS 验收按本轮用户要求暂不做。

### 数据库与跨卷回归

在 `server/` 执行：

```bash
go test ./internal/store -run TestSnapshotRestoreIntoFreshDataDirectory -count=1 -v
go test ./internal/httpapi -run TestUploadWithoutSourceMetadataUsesLandingTime -count=1 -v
```

首项使用真实 migration、在线快照和新数据目录重新打开，核对事件身份/收藏，并证明原件需独立副本；不是完整服务进程/硬件恢复验收。第二项确认上传仅传字节时不会保留源文件系统 mtime；EXIF 时间不能代替它。需要保留日期排序时，先选支持时间保留的文件复制通道；新增上传时间字段须另行按 OpenAPI/SDK 流程实施。

真实跨卷测试须显式选择两个**可丢弃临时根**。PowerShell 示例（用自己的两卷测试根替换占位符，先创建目录；同卷会明确 SKIP）：

```powershell
$env:TMP = '<第一卷的临时根>'
$env:TEMP = $env:TMP
$env:QIMENG_TEST_CROSS_VOLUME_ROOT = '<第二卷的临时根>'
go test ./internal/filing -run TestMoveFileRealCrossVolume -count=1 -v
```

测试先用真实 rename 的跨设备错误证明两卷，再核对字节/mtime、目标冲突不覆盖、复制中断保源且清理半成品。中断由复制钩子注入；不模拟断电、NAS 缓存落盘或设备拔出。测试只清理由自身创建且已核对父目录的临时目录。

## 本批验证范围（2026-10-19）

- Windows 本机真实 C/D 两卷：上述三项跨卷场景通过；迁移库快照在全新目录恢复测试通过。
- Android：请求绑定的切服/重定向/迟到 401 单测与 App Kotlin 编译通过；未做设备切服、进程重启后队列和 NAS 验收。
- 源 mtime 的 HTTP 上传保留尚未实现；现有跨卷文件移动可保留 mtime。两者不混称“迁移无损”。
- 当前无 NAS 硬件，本指南不表示未来挂载、权限、断电恢复已验收。当前剩余事项统一见 [能力地图](CAPABILITY_MAP.md)。
