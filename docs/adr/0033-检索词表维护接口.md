# ADR-0033：检索词表维护接口（自定义出处组）

## 背景（Context）

出处/角色的检索表（130 组 SourceGroup）自 M3 移植后冻结在代码里
（`source_groups_data.go`），增补词条必须改代码、重编译、重启。用户的库
持续收录「单一角色多文件」的内容，新角色/冷门资源会不断出现（如守望先锋
新角色 Dmon、怪物猎人杰玛），检索表跟不上就会出现「文件已入库、角色恒
空白、胶囊筛选行永远看不到」的断链。2026-10-03 实测对账还暴露一个内置表
缺陷：第一后裔组的复合变体 `"第一后裔 邦尼"` 在长度降序前缀命中即停的
strip 规则下把 `第一后裔 邦尼 1.mp4` 的角色名整体吃掉（剩余串只剩 "1"），
角色匹配落空。另澄清一个前提：匹配只发生在扫描/富化时（索引构造期建好 +
8192 结果缓存），检索表大小不进任何请求热路径——本决策的动机是维护性，
非性能。

## 决策（Decision）

1. **内置 130 组冻结为基线**，只修数据 bug（删除吞角色的复合变体
   `"第一后裔 邦尼"`；全表审计确认无同类）；后续词条一律走运行期词表，
   不再改代码扩表。
2. **新增检索词表维护端点** `GET/PUT /api/v1/sources/custom-groups`
   （整体替换语义）：载荷为出处组列表（canonical + variants +
   characters），canonical 与内置组同名 = 并入（扩变体/角色，同名角色扩
   别名），新名 = 追加新组；服务端规范化（trim/去空/去重/重复 canonical
   取首个/canonical 自并入变体与别名）后持久化 kv_settings
   `custom_source_groups`（存储形态 = 引擎输入形态，与
   `custom_sources` 裸名名单语义隔离并存）。
3. **引擎合并层**（sourcematcher.MergeGroups，纯函数）：内置表 → 裸名层
   → 出处组层按 canonical 深拷贝合并；裸名与内置组同名时角色表不再被
   覆盖（修复旧 rebuild 的 map 覆盖行为）；两层自定义更新互斥串行化。
4. **存量传导复用既有闭环**：PUT 成功 → 引擎同步替换 → 后台对全部常规库
   重算富化（RecomputeEnrichment）→ `library.changed` 事件——新词条即刻
   传导到已入库资产的 source 列与 asset_characters 行。

被否决的替代：词条直接改进内置表（每批都要重编译，正是要解决的问题）；
新库表存储词条（词表是小型配置，kv 先例充分，migration 无必要）。

## 状态（Status）

已接受（2026-10-03）

## 后果（Consequences）

- 受影响文件：`api/openapi.yaml`（新端点 + CustomSourceGroups 三 schema）、
  `server/internal/sourcematcher/{custom.go(新),matcher.go,source_groups_data.go}`、
  `server/internal/scanner/{enrich.go,scanner.go}`、
  `server/internal/httpapi/{server.go,source_groups.go(新),wire 适配}`、
  `server/internal/authoring/authorid.go`（kv 键常量）、
  `server/cmd/qimeng/wire.go`、三端 SDK 再生成 + `api/sdk.lock`。
- AI/用户可随时经 PUT 增补词条，保存即生效并自动重算存量，无需改代码。
- 词表是普通配置数据：随 kv_settings 进库快照备份；清空即回退内置基线。
- 词条上限（组 256/变体 64/角色 128/别名 32/单串 100 rune）与 openapi
  maxItems/maxLength 双写同步。
- DOMAIN_RULES §4 增补「用户自定义出处组」小节；130 组基线口径不变。

## 补记（2026-10-03 同日晚：本 ADR 的词层定位收窄）

落地当天用户复盘提出真实诉求：「方便维护 + 准确，降低角色表依赖」——收藏
命名高度统一（`出处  角色名 序号.扩展名`），逐角色补词条追不上收录速度。
据此引擎侧新增**命名规约兜底提取层**（DOMAIN_RULES §4「命名规约兜底提取」，
第四百五十八笔）：别名表命中非空时结果完全以表为准；表零命中时按命名位置
直接提取角色名（序号终止、画质词防线、"+" 分段隔离，规则详见 §4）。

对本 ADR 的影响：**本词层的角色 entries 从「收录必需」收窄为「改名/归一
可选」**（如 `Dmon`→`D.Mon`；新组仍需 canonical+variants 让出处先命中）。
端点协议与存储形态零变化。同批加固：两词表入口对含 U+FFFD 替换符的词条
显式 400（非 UTF-8 载荷静默落库即死词条，曾致「PUT 后重算不生效」的假象）。
