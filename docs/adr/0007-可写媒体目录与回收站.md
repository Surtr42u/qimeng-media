# ADR-0007：媒体目录可写 + 回收站 + 上传白名单

- 状态：已接受（2026-08-22，修订于同日——原设计"只读挂载"被用户新需求推翻）

## 背景

原设计延续旧项目"媒体文件只读"原则（Docker `:ro` 挂载）。用户确认新场景：**手机下载的资源要能通过 App 直传 NAS 并整理（移动/重命名），不能每次开 NAS 网页去弄**——"手机是采集端，NAS 是仓库"。只读假设不成立。

## 决策（三条补偿性安全设计）

1. **媒体目录可写，但删除一律进回收站**：`/data/trash/` 独立于媒体库；保留 30 天（可配）；物理删除仅限回收站内显式操作。"保留原图主旨"不变：上传文件原样落盘永不转码，缩略图/预览副本只存数据目录。
2. **上传四道校验**（SECURITY.md 详述）：扩展名白名单 + 文件头 MIME 嗅探 + 大小上限 + 目标路径穿越检查；流式临时文件 + 原子 rename 落盘。
3. **容器权限收敛**：进程非 root 用户运行；媒体目录与数据目录分离挂载；审计日志记录全部写操作（谁/何时/什么操作/结果）。

## 权衡

放弃了"无上传面"这个安全优势（对比 Immich 有公网上传，我们仍只接受内网/隧道内上传），换来核心使用价值——这是产品目的决定的，不是疏忽。
