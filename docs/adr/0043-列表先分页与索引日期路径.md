# ADR-0043：列表先分页与索引日期路径

日期：2026-10-20。

## 背景（Context）

5 万资产探针发现列表先富化大量候选再限页；通用 CASE 排序无法直接利用 mtime 顺序，首屏计数和日期分桶重复扫描。用户要求探索可测量的架构优化。

## 决策（Decision）

- 通用查询用 page CTE 先筛选/排序/LIMIT，再按主键装配本页，只返回需要的列；单条 SQL 保持同一快照。
- 日期排序且仅库/COS 条件时走索引路径；NULL/非 NULL 游标用互斥 UNION 分支，让深页 seek。任何未支持字段（包括新字段）自动回退完整筛选查询。
- 日期分桶保留内部 NULL 桶参与总数，只向协议输出有效日期；一次扫描替代独立 COUNT+分桶。
- 复用 0018 索引，无 schema/协议/公式/缓存变更。sqlc 不解析 AS MATERIALIZED，采用其支持的普通 CTE+LIMIT/外层 join，由计划断言防止富化前移。依据 [SQLite 优化说明](https://www.sqlite.org/optoverview.html#subquery_co_routines)。

## 状态（Status）

Accepted；功能等价、计划与合成性能通过，目标设备另验收。

## 后果（Consequences）

新增窄查询须维护白名单与分页等价测试，不能漏筛选；不以 SQL 加速倍数宣称整页收益。影响 server 的 browse 查询、列表适配与测试；现行边界/基准见 [筛选专题](../domain/filtering.md)，API 用法与架构 §7 同批对齐。
