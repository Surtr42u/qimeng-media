# ADR-0013：M4 Android 客户端走「旧 UI 照搬 + 数据层网络化」路线

- 状态：已接受（2026-09-04，用户拍板）

## 决策

M4 Android 客户端不按原计划「Compose 重写旧交互」，改为把旧项目（QimengMedia）的 UI 层资产整体照搬进新工程：

- **照搬范围**：`ui/` 包（15 Fragment、19 XML、5 自定义控件：BiliPlayerView / ZoomImageView / FlowLayout / LineChartView / MaxHeightScrollView）、ViewBinding、Fragment 单 Activity 架构、手写 AppContainer DI、Coil 3、Media3/ExoPlayer。包名沿用 `com.qimeng.media`（照搬文件零包改动），applicationId 同。
- **数据层替换**：`LocalMediaRepository` 接口保持形状，实现从「Room 单机库」换成「生成 SDK（HTTP）+ Room 缓存桥接」；UI 消费点从本地 `content://` URI 换服务端签名 URL。
- **禁搬清单（单机生态）**：`scan/` 全部、`domain/ScanUseCase`、`domain/AutoSyncUseCase`（本地自动扫描）、`backup/BackupManager`、`core/` 本地缩略图解码管线（ThumbnailCache / ThumbnailLoader / LargeImageDecoder / SpngDecoder）、`data/repository/DefaultLocalMediaRepository` 旧实现；算法纯函数（`MediaBrowserLogic` 的 recommend / rank / applyFilter）**不搬**——服务端 M3 已实现并测试锁定，客户端不复算（薄客户端纪律，ADR-0008）。

## 背景

- 2026-09-04 架构调研（只读子代理实测旧项目源码）：解耦良好——UI 全部经由单一 `MediaLibraryViewModel` 持有 `LocalMediaRepository` 接口；实体是纯 Kotlin 数据类；`MediaBrowserLogic` 为零 IO object 纯函数。「换数据源时 ViewModel 以下可整体替换」成立。
- 已知泄漏点（移植时处理，不推翻路线）：约 10 处 Fragment 绕过 ViewModel 直取 `appContainer.appPrefsManager`；`MediaDetailFragment` 4 处直接消费 `content://` URI（图片加载/播放器/元数据/输入流）；`MediaLibraryViewModel` 自带 contentResolver 读 TXT 与 MediaStoreObserver 注册。
- 用户意愿：App 端完全沿用已验证的旧 UI（旧项目 2.4 万行 100% AI 生成，交互经长期使用打磨）。

## 理由

- **交互保真度最高**：BiliPlayerView（837 行 B 站式手势播放器）、ZoomImageView、胶囊筛选联动、标签管理流——Compose 复刻成本高且必然走样，照搬即得 100% 旧体验。
- **技术栈兼容**：旧项目已用 Coil 3.4 / Media3 1.8 / Room（与 android/README 原定论的主力库一致），无迁移负担；放弃的只有 Compose/Hilt 两项原定论（它们从未落地，无沉没成本）。
- **工作量重心明确**（调研结论）：URI 消费点改造（约 4 处）+ 缩略图管线废弃（服务端出图）+ 单机生态页删除——比 15 页 Compose 全重写显著更小。

## 后果

- `android/README.md` 技术栈定论变更：View/XML + ViewBinding 照搬，不引入 Compose/Hilt。
- 「禁止搬运旧项目实现代码」铁律口径收窄为「禁止搬运单机生态代码」（AGENTS.md / AI_README_FIRST 同步修改）。
- minSdk 沿用旧项目 31（原 M4 规划冻结的 26 作废）；targetSdk/依赖版本执行时按官方兼容表取新。
- `LocalMediaRepository` 约 100 个方法中 ~40 个是 `observe*(): Flow`（Room invalidate 驱动）——网络实现需要「API 拉取 → 写 Room 缓存 → Flow 自动推 UI」桥接层，是本路线最大实现风险（HANDOVER_APP M4-1 批次先行验证；接口按 UI 实际调用面渐进实现，不要求一次做满）。
- 服务端断点续播基座（commit 9773213）叠加进照搬来的 BiliPlayerView（新功能，非旧交互复刻）。
