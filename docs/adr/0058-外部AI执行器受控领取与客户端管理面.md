# ADR-0058 外部 AI 执行器受控领取与 AI 客户端管理面

- 状态：已接受（2026-11-08，用户要求补齐外部执行器受控领取/续租/完成与权限管理）。源码与本机定向测试已通过；未安装到现装 PC/手机，未做真机或 NAS 验收。
- 影响范围：维护任务执行面（`/api/v1/maintenance/executor/*`）、AI 客户端凭据管理/审计 HTTP 面、scope 与限流、设备结果包权威回读与 migration 0026、Android 设备领取与工具层适配。
- 关联：[ADR-0054](0054-持久维护任务队列.md)、[ADR-0055](0055-手机无前台维护结果包协议.md)、[ADR-0056](0056-独立AI接入平台架构.md)、[ADR-0057](0057-AI客户端凭据与细粒度权限模型.md)；协议以 [api/openapi.yaml](../../api/openapi.yaml) 为准，权限细节见 [SECURITY](../SECURITY.md#独立-ai-客户端凭据scope-与审计adr-0057-p1p22026-11-08)。

## 背景

- 维护账本（ADR-0054）已有内部 `Claim`/`Heartbeat`/`Complete` 与租约围栏，但只有 Go Worker 能使用；外部 AI 执行器没有受控领取、续租、步骤/工件登记与终态回传通道，无法在不复制业务逻辑的前提下参与长任务。
- AI 客户端凭据（ADR-0057 P1）只能通过服务端本机 CLI 管理，手机内嵌单机模式无法创建自己的设备令牌；Android 只能连接由 PC 生成令牌的实例。
- 设备结果包的 `readback` 是导入响应里的**增量计数**，不是应用后的权威业务状态；`deviceLocalHashes` 只做格式校验，未与登记段摘要比对。
- Android 的 pending/claimed 恢复只读取列表第一页（100 条），积压时旧任务饿死；Worker 恢复时只看到详情端点最近 50 条步骤，长任务会重复执行更早的已完成步骤。

## 决策

1. **在唯一账本上开放执行器通道**：新增 `POST /api/v1/maintenance/executor/claim`（无可领取任务 204）与 `jobs/{id}/heartbeat|steps|artifacts|complete`。领取由服务端生成每次唯一的 fencing `leaseToken`，客户端不得自选；暂停、取消、终态、租约过期或重新领取后旧 token 一律 409 `LEASE_LOST`。租约 30–1800 秒（默认 120）。领取响应返回账本**全量** `completedSteps`，执行器按名跳过已完成副作用。
2. **步骤/工件写入同样受租约围栏**：按 `(job, step)` 幂等 upsert；完成态保留 running 阶段记录的 `startedAt`。工件正文不入库，`(job, kind, uri)` 去重。
3. **管理面只归管理员会话**：`GET/POST /api/v1/ai-clients`、`DELETE /{id}`、`POST /{id}/rotate` 与 `GET /api/v1/ai-audit` 对 AI 客户端 Bearer 一律 403（即使持有 `admin` scope）；明文 token 只在创建/轮换响应出现一次。本地 `qimeng ai-client` CLI 继续可用。
4. **scope 扩展与默认拒绝**：新增 `asset.write`、`asset.upload`、`asset.delete`、`tag.write`、`source.write`、`library.write`、`trash.restore`、`maintenance.execute`；未映射写请求仍 403。高风险删除/清空/恢复仍需独立 scope。
5. **按客户端限流**：进程内令牌桶，默认 600 次/分钟、突发 120（`QIMENG_AI_RATE_LIMIT_PER_MINUTE`/`_BURST`，0 关闭），超限 429 `RATE_LIMITED` + `Retry-After`。这是单实例保护，不是跨实例配额。
6. **设备结果包权威回读**：manifest 可声明 `expectedState`（assets/authors/assetAuthorRefs/tags/assetTagRefs/viewEvents 的绝对计数）；回传时服务端读取库内真实计数比较，并核对手机回传摘要与登记段是否逐段一致。验证快照写入 migration 0026 新增的可空列 `verification_json`，与 `result_json` 分离，因此相同结果的幂等重放仍逐字节相等、不会因库状态变化被判 409。
7. **Android**：pending/claimed 列表按 `nextCursor` 全量翻页（100/页，硬上限 20 页=2000 条，超限明确失败）；本机模式用**当前管理员会话**创建/复用/轮换 `android-local-<device>` 设备客户端（scope `device.apply` + `deviceIds` 绑定），明文只落 DataStore；新增只读最近任务列表。本地与远端仍共用同一个 `DeviceApplyRunner`。
8. **Worker 恢复修正**：恢复时从账本读取全量 completed/skipped 步骤名，而不是使用详情端点 50 条窗口，避免长任务重复副作用。

## 后果

- 外部执行器与 Go Worker 共用同一任务账本、状态机与终态，不新增第二套任务系统或数据库。
- 旧执行器在重领后无法续租或写证据，重复副作用由 fencing + 全量完成步骤双重约束。
- 设备结果包从"客户端自报"升级为"客户端自报 + 服务端权威计数/摘要核验"；`result_json` 语义不变，旧任务与旧客户端兼容。
- Android 单机模式获得正式的设备令牌创建通道；仍要求本地管理员会话，且撤销/轮换入口在 PC/服务端，不在手机 UI。
- migration 0026 只新增可空列，不修改历史迁移；回退 = 停用执行器通道并回退代码，列可保留（旧代码忽略）。

## 边界与非目标

- 不开放任意 SQL/文件/shell 执行；执行器仍只能通过正式 API 写业务数据。
- 未实现多实例共享限流、动作级高风险确认凭据（G3）、设备配对/设备证明（G6）、设备包 GC、Web 管理/审计 UI。
- 未安装到现装 PC/手机，未在 `qimeng_api35`/真机验证后台周期、Doze/厂商限制、后台拉起内嵌 FGS 与 SAF 撤回；这些必须在安装轮验收，不能以本 ADR 或云端编译替代。
- 研究 provider 的真实网络复验、NAS 硬件部署与长周期运行仍属后续验收。
