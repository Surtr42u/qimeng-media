# ADR-0046：推荐跨页顺序快照与 Web 缓存刷新

日期：2026-10-20。

## 背景（Context）

Web 每 60 条翻页换响应缓存键，重复查询完整候选并评分；前页展示惩罚回写又会使后页重复/漏项。启动只预热 App 的 1/200 参数，Web 初始 0/60 不命中。库变更映射遗漏统计/排行/历史，成功备份导入也没有跨端通知。

## 决策（Decision）

- 新 recommendfeed 专职编排保存完整 ID 顺序，键不含 offset/limit；最多 60 秒、32 流、全缓存 100000 个 ID。只读元数据不进入缓存；当前页查询重检启用库/媒体/COS/存在性。
- 复用标准库 mutex 和既有 x/sync/singleflight，保留 panic 转错误、错误不缓存和迟到登记保护。预算不足可淘汰，单流超限不缓存、不截候选。
- 去除旧协议响应缓存，避免页响应与顺序快照分别到期造成混用；展示计数只在真实请求返回页累计，预热不计数。App seed=1 与 Web seed=0 分别预热，不改变权重或固定公式。
- 成功导入发布 library.changed；Web 在库变更/重连统一刷新统计、排行、历史及内容缓存。

## 状态（Status）

Accepted；实现与自动化验证范围见 HANDOVER，部署/设备实测另列。

## 后果（Consequences）

替代原按分页窗口缓存响应的策略。短期翻页共享一次评分，但首算需生成完整顺序，启动有两 seed 的冷算成本。TTL/容量淘汰/结构变更可重排，客户端仍需去重；并发资格变化可能不足一页。不存在跨请求永久快照或推荐质量提升承诺。现行语义见 [推荐专题](../domain/recommendation.md)，协议以 OpenAPI 为准。
