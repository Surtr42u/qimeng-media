# ADR-0054：持久维护任务队列

## 背景（Context）

外部 AI 维护需要"研究→计划→应用→回读"这类跨多次调用、可能部分成功的任务。此前只有进程内守护循环与一次性脚本：服务重启、断网或进程被杀后无法知道做到哪一步，也没有统一的幂等键、租约与逐项证据索引。ADR-0051/0052 把持久队列列为 P3 的结构性能力，P0 底稿 §4.2 给出最小方案。

本切片只做**账本与端点**，不实现 worker：没有执行器时任务不会被自动消费，但外部 AI 已可通过正式 API 创建/查询/暂停/恢复/取消任务，为后续 worker、Web 任务中心与 PC→手机桥接提供唯一账本。

## 决策（Decision）

1. **三张只增表**：migration `0023_maintenance_jobs` 新增 `maintenance_jobs`、`maintenance_steps`、`maintenance_artifacts` 与索引，不改历史表/索引。任务表含 kind/status/library_id/payload_json/input_fingerprint/rules_version/authorization_scope/budget_json/idempotency_key/lease_owner/lease_until/created_at/updated_at/started_at/finished_at/error_code/error_message；步骤按 `(job_id, step)` 主键；工件按 `(job_id, kind, uri)` 去重，正文不入库。
2. **状态机**：`queued → inventory → research → planned → applying → verifying → completed`，等待态 `waiting_evidence/waiting_authorization/waiting_device`，以及 `paused/partial/failed/cancelled`；`completed/partial/failed/cancelled` 为终态。公开 HTTP 只触发 `paused/queued/cancelled`，其余由后续 worker 推进；非法迁移与终态变更统一 409 `STATE_CONFLICT`。
3. **幂等**：`idempotency_key` 在任务表上永久唯一（终态后仍保留）。创建在单事务内先查后插；并发同键由唯一索引/事务串行化兜底，重放返回既有任务（首次 201、重放 200），不重复建行。payload/budget 归一化为稳定 JSON 并计算 `input_fingerprint` 入账；重放不比较指纹差异。
4. **端点族**：`POST/GET /api/v1/maintenance/jobs`、`GET /api/v1/maintenance/jobs/{id}`、`POST …/{id}/pause|resume|cancel`。列表为状态过滤 + 新建倒序 keyset 分页（limit 1–100），详情带最近 50 条步骤与 100 条工件元数据。所有响应沿用既有 `Error` 结构与 RFC3339 时间。
5. **分层**：账本、状态机、幂等、租约与步骤/工件索引全部在 `server/internal/maintenance`，只依赖 `store/db` 与标准库，不依赖 `httpapi`（depguard）；httpapi 只做协议校验、错误映射与响应装配（ADR-0019）。
6. **租约为后续 worker 预留**：`lease_owner/lease_until` 已入表；包内提供 `Claim/Heartbeat/Complete` 与 `RecordStep/AddArtifact` 内部原语，本轮不出 worker HTTP API。恢复语义定义为 `paused → queued`，worker 后续从 inventory 重启。
7. **无独立特性开关**：账本端点只读写本地 SQLite、不出网、不执行任务，默认即可用；worker 上线前不会自动消费。与 research 的默认关闭策略区分。
8. **协议先行**：OpenAPI 先加路径/schema，再 `make sdk` 生成 Go/TS/Kotlin 三端，`api/sdk.lock` 同批重算（331 项）。Go 枚举使用 `x-enum-varnames` 前缀命名，避免 oapi-codegen 全局常量去重冲突。

## 状态（Status）

Accepted（2026-11-07）。源码、协议、SDK 与锁同批交付；**未安装**到现装 PC/手机，worker 执行器、Web 任务中心、PC→手机桥接、`author.cleanup.prepare/apply` 与 MCP 适配仍未实现。业务 `go test` 按仓库规定走云端 CI，本地已跑 `go build ./...`、`gofmt`、`go vet` 与 `make sdk`。

## 后果（Consequences）

积极后果：任务在重启/断网后仍有唯一账本；同幂等键不会重复建任务；终态不可变，外部 AI 可安全重试；步骤与工件索引让"部分成功"可逐项追踪；worker/Web/桥接共享同一状态机，避免各自发明状态。

代价与风险：worker 未实现前任务不会自动执行，账本可能堆积 queued 行；恢复语义是重排队而非精确断点续跑，worker 必须用幂等步骤/工件避免重复副作用；`partial` 的进度按已完成步骤计算，不代表业务结果完整；payload/budget 是自由 JSON，业务 schema 校验由后续 worker 负责；`libraryId` 不校验存在性，调用方需自行处理库已删除的情况。

## 2026-11-07 实现补充：worker 与幂等冲突保护

在账本/端点之上补齐进程内执行面与误用保护（**不改 OpenAPI、不加 migration、不建第二套任务表**）：

1. **幂等冲突保护**：`Service.Create` 命中同 `idempotencyKey` 时比较新输入 fingerprint；相同 = 既有重放语义（200，created=false），不同 = `ErrStateConflict`（HTTP 409 `STATE_CONFLICT`）。并发竞争路径同样比较，避免把不同任务误认为成功重放。原「重放不比较指纹」由此收紧，属任务书 §8.3 要求的补充。
2. **按 kind 领取**：`Claim(kind, owner, ttl)` 只领取本进程注册 handler 的 kind；`queued` 与租约已过期的在途状态（inventory/research/planned/applying/verifying）可领取，`waiting_*`/paused/终态不可领取。未注册 kind（asset_research/author_cleanup/custom）保持 queued。
3. **状态推进**：新增内部 `AdvanceStatus(id, owner, next)`，事务内校验租约 owner 与 state.go 状态机；同状态幂等 no-op。状态机补充 `inventory -> applying` 边，供无 research/planned 步骤的短流水线使用；完成前 worker 把状态补齐到 `verifying`，不会从更早阶段直接写 completed。
4. **worker 可靠性**：默认启用；有界并发（默认 1，硬上限 8）；租约 TTL 2m + TTL/3 心跳；逐步骤 RecordStep（running/completed/failed/skipped，含 attempt/时间/detail）；租约过期或重启后重新领取并从已完成步骤续跑（completed 步骤不重复副作用）；暂停/取消后停止后续步骤并保留已提交步骤；panic 兜底只影响单任务；终态 completed/partial/failed 可判定。
5. **首个真实 handler**：`backup_export`（maintenance 包内，调用既有 backup.Manager.Create/OpenFile，不改 backup 包业务语义）：inventory -> export -> verify 三步；export 生成快照并记录工件 kind=backup_snapshot / uri=文件名 / sha256 / bytes，verify 回读核对大小与哈希。
6. **装配**：`server/cmd/qimeng/main.go` 用 safego.Go + Start(ctx) 启动，并与 HTTP 共享同一 maintenance.Service/sql.DB；配置 `maintenance_worker.*` 与 `QIMENG_MAINTENANCE_WORKER_*`（默认 enabled=true、poll_interval=5s、lease_ttl=2m、concurrency=1）。
7. **边界与遗留**：仍不开放 HTTP/外部执行器的领取/续租/完成端点；等待态恢复与 Web/桥接的完整验收不在本切片。崩溃窗口内正在执行的步骤可能重跑一次（backup_export 极端情况多一份快照，由既有保留/轮转清理）；其余 kind 无 handler，保持 queued。验证：本机 gofmt/go build/go vet + 定向 go test（临时 SQLite/合成 handler），完整回归走云端 CI。
