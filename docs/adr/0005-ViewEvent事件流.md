# ADR-0005：ViewEvent 事件流（替代计数器累计）

- 状态：已接受（2026-08-22）

## 决策

浏览/播放/停留时长记录为**只追加的事件流**（view_events 表），统计数值（viewCount/playCount/按天聚合/排行/趋势）全部从事件流**聚合**得出；按天聚合物化表是缓存，可随时从事件流重建。

## 理由（新旧架构最本质的升级之一）

- 旧项目是「计数器累加」：算法或口径出 bug 时**永久污染数据**，无法回溯修复
- 事件流只追加不修改：任何统计口径变更（如趋势分桶规则调整）都可全量重算历史
- 会话级去重（同一会话不重复计数）、每日点赞限制等服务端规则在写入事件时判定，口径集中一处
- 行为数据天然支持未来的任意分析（时段分布、深度分布等）而无需提前设计

## 代价与对策

- 存储量高于计数器：单用户量级（日均数百事件）下可忽略；事件表按年分区归档即可
- 聚合查询成本：按天聚合物化表（与旧项目 daily_browse 同构）承担热查询，事件流只在重算/冷分析时全量扫描

## 写入契约

客户端只上报原始事件（open: ViewEventReport），**禁止**客户端上报算好的计数——服务端是唯一计算点。

## 实现澄清（2026-08-22，随 store migration 0001 落地）

view_events.asset_id **不设数据库外键**：只追加的事件流不能被 ON DELETE CASCADE 波及（否则删除资产会抹掉历史），而 NO ACTION 外键又会阻塞资产的物理清除。事件表引用 asset_id 值但不做引用完整性强制——孤儿事件是历史事实，由统计口径（JOIN 不上的事件不聚合）自然隔离。
