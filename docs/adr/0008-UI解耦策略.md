# ADR-0008：UI 策略——逻辑协议共享，UI 各端原生

- 状态：已接受（2026-08-22）

## 决策

三端 UI 各自用最主流框架实现（Web: React+shadcn；Android: Compose），**不上任何跨端 UI 框架**；跨端一致性靠两层保证：

1. **服务端与 UI 解耦**：API 只返回领域数据（排序好的列表/算好分的推荐），永不返回 UI 结构；禁止为某端开专属接口（BFF）
2. **协议生成的 SDK 是共享数据层** + 各端内部强制逻辑/UI 分层（Web: TanStack Query hooks 层；Android: ViewModel 层），UI 组件禁止直接调 API、禁止内嵌业务规则

## 理由（对应用户需求 #2 #4）

- 用户痛点"UI 不好看、改 UI 怕牵连逻辑"的正解 = 让 UI 成为**最便宜可换的层**：换皮/重做只动组件层，逻辑与测试不动；AI 可并行生成多套风格供挑选
- 跨端 UI 框架（Flutter/CMP）每端都有短板（视频播放、Web 性能、AI 语料），而"UI 各端原生 + 逻辑共享"没有短板
- 设计 token 集中管理（颜色/间距/圆角/动效时长变量），延续旧项目 GUIDE_THEME 的成功经验

## 边界

- 换 UI ≠ 零成本：组件仍要重写；省的是逻辑与接口层
- 各端交互习惯差异（手势/快捷键）属 UI 层内部事务，不算耦合
