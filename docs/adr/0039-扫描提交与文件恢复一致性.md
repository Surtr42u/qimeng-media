# ADR-0039：扫描提交与文件恢复一致性

## 背景（Context）

2026-10-19 合成故障复现：扫描失败误删身份、整理与扫描交错自删、恢复/续传提前丢失重试依据。媒体原件仍在也不能靠重扫找回收藏或原身份。

## 决策（Decision）

1. 扫描视野不完整时报告失败、停止破坏性差集；成功提交仍广播变更。视频探测与遍历在锁外，单文件提交及逐条差集共用 filing 库锁，实时复核路径/身份。移动候选仅取扫描新建身份，size+mtime 分桶排序后逐次复核，合并删除/更新共用事务。
2. 恢复先原子写 meta 意图（目标、size、mtime），同库锁内搬回并重建原 ID，成功才删 meta。扫描显式读取未提交意图并保留路径；意图缓存由写入/清理方显式失效，到期清扫跳过未完成恢复。重试继续同一目标，异常版本保留文件及 meta。
3. 续传封存后禁止 PATCH；保留源，以硬链接预置，同卷不复制，不支持硬链接或跨卷则复制。会话记录最终落点，串行 complete/放弃/关闭，入库失败重试同一文件。会话仍不跨重启持久化（ADR-0028）。
4. 路径逐段拒绝链接；可行的库内操作用 os.Root 锚定。跨 Root 移动保留同卷快路径，外部并发换链仍是 SECURITY 边界。

## 状态（Status）

Accepted（2026-10-19）

## 后果（Consequences）

不改协议/schema，不引框架。恢复意图不是掉电事务；size+mtime 不能证明内容相同，跨卷复制保留 mtime，异常时保留副本供重试。硬链接不可用时增加临时空间。涉及 scanner/reconcile.go、filing/restore_intent.go、httpapi 上传/回收站、uploadsess；同步 SECURITY、DOMAIN_RULES §9、ARCHITECTURE §5、GUIDE_API、CHANGELOG。
