# ADR-0002：服务端形态 = 模块化单体（明确不做清单）

- 状态：已接受（2026-08-22）

## 决策

服务端是**单进程模块化单体**，模块边界 = `server/internal/` 包边界（见 ARCHITECTURE §5）。同时确立"明确不做清单"，防止范围膨胀：

| 不做 | 理由 |
|---|---|
| 微服务/消息队列/K8s | 单人反模式；Immich/Jellyfin/Gitea 等主流自托管项目全部是单体 |
| AI 识别/人脸聚类 | 用户库是动漫/COS 媒体，AI 识别价值低成本高（Immich 的 ML 微服务是团队工程） |
| 实时转码 | 内网千兆/WiFi6 带宽足够 4K 原盘直链（50-80Mbps）；转码是流媒体服务 80% 的复杂度来源。远程带宽不足时的按需转码档位放 M6+ 储备 |
| 公网多租户/注册体系 | 内网单用户；表结构预留多用户但不实现 |
| iOS 端 | 用户明确放弃 |

## 演进保证

模块间通过进程内事件总线解耦、领域逻辑纯函数化——将来任何一个模块要拆分/替换，边界是现成的。**"可以拆"但"不拆"，这是单人体量下稳定性的最优解。**
