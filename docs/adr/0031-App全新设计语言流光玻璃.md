# ADR-0031：Android App 全新设计语言「流光玻璃」（液态玻璃质感 + M3 Expressive 动效 + 暗色优先）

## 背景（Context）

M4 App 端按 ADR-0014 落地后，视觉沿用旧项目「中性极简灰」色板（Color.kt 逐行对照旧 colors.xml），信息架构与功能已全（M0–M6 收官）。本项目定位媒体全存 NAS 的多端媒体库，核心场景=媒体库浏览/检索/播放/上传归档/行为数据——消费场景下旧灰系观感平淡，与 Jellyfin/Immich 及 iOS 26 Liquid Glass 等当代媒体应用的设计水位有代差。任务要求：设计语言级重做（非局部美化），功能守恒（页面/路由/交互语义一个不少），技术边界不动（Compose M3 + feature→core 单向依赖，ADR-0008/0014；UI 不碰网络与业务规则；不引白名单外重依赖）。

备选：① 引 haze 等 backdrop-blur 三方库（白名单外重依赖，否）；② 升级 material3 到 1.5 线拿 Expressive（已在用 1.5.0-alpha28，零成本）；③ 纯换色板（不满足"设计语言级"）。

## 决策（Decision）

自建设计语言「流光玻璃」，落点分四层：

1. **色彩**：暗色为第一基准（媒体消费暗色优先；主题仍跟随系统，深浅两套同源设计，不新增主题开关功能）。暗色基底=深蓝紫夜色（近黑非纯黑，层进 surface 阶梯），主色=鸢尾蓝紫（iris），强调=极光青（aurora teal）与霞粉（blossom）三元；浅色=冷瓷白 + 同族低饱和。品牌色单源 `QimengBrandColors`（core:ui/theme/Color.kt 全量重写，旧灰系 token 移除）。
2. **玻璃质感（自建，零新依赖）**：官方 Compose 无 backdrop-blur API（已核官方文档/生态现状，haze 系为三方方案不取）。实现路径=「分层半透明 + 受光描边 + 高光 + 深色投影」的 `GlassSurface` 组件族（core:ui/glass）+ **环境辉光**（`AuroraBackdrop`：自带内容的径向渐变辉光团做"被磨砂的景深"，玻璃面板覆于其上即成磨砂观感——辉光本体是自绘内容，不需采样背后像素，全 API 级别一致）。**当前实现零 blur（对抗审查勘正，2026-10-02）**：玻璃质感与景深全部为自绘分层，分支内无任何 `Modifier.blur`/RenderEffect 调用；`Modifier.blur`（API 31+ RenderEffect）仅为**未来**对自有内容（头图/氛围层）做真模糊的预留策略。**降级策略**：玻璃面板本就是自绘分层形态，各 API 级别观感一致（fill alpha 取值保证文字对比度达标），无需分支代码；未来若引入真 blur，API < 31 须回落「半透明纯色层+阴影」。
3. **动效（M3 Expressive + spring 物理）**：主题换 `MaterialExpressiveTheme` + `MotionScheme.expressive()`（material3 1.5.0-alpha28 已具备，官方 API）；覆盖页（pushed 路由）转场从 snap 瞬切换 spring 物理滑入（横滑+淡入，详情页缩放入场）；按压微交互统一 spring 缩放（`Modifier.pressScale`）；**Tab 切换保持 snap 瞬切不动**——常驻层防闪烁机制（NavHost 空壳跳板 + 乐观翻转）依赖瞬时交换，spring 化会复活已根修的叠影/闪烁问题。SharedTransitionLayout 评估后不取：真实 Tab 屏在常驻层渲染于 NavHost 之外，跨路由共享元素无载体，收益仅剩 pushed→detail 一段，风险/收益不成立。
4. **形状/排版/组件**：大圆角语言（卡 20dp、面板 24dp、胶囊 100dp 不变）；页面大标题 Display 档；共享组件（QimengSegPill 胶囊、骨架屏、TopBar、媒体卡）换装新 token；壳层底栏换自绘玻璃导航栏（GlassNavBar，视觉重做、点击/防抖/双击回顶/常驻层逻辑逐字不动）。

范围纪律：只动 `android/core/ui`（主题/玻璃件/共享组件）+ `android/app`（导航壳视觉与转场）+ 各 feature 渲染层（Screen/组件文件），ViewModel/Repository/SDK/协议/路由字符串零改动；`BiliPlayerView`/`ZoomImageView`（ADR-0014 桥接件）与详情沉浸状态机不碰视觉逻辑，仅色值适配。

## 状态（Status）

Accepted（2026-10-02）

### 设备纪律（2026-10-02 夜增补，本 ADR 实施期间的事故沉淀）

「流光玻璃」走查（emulator-5580 上的 r1 轮）前，发生了本仓历史上第二次「调试装机落到雷电」事故（2026-09-09 首次）。根因是**端口分裂脑**：雷电的 adb 桥占用 adb **传输**端口（0.0.0.0:5555），项目 AVD 只占到 adb **控制台**端口（127.0.0.1:5554）——于是 `adb -s emulator-5554 emu avd name`（走控制台）恒答 `qimeng_api35`，而 install/am start/screencap/input（走传输）全部落到雷电。控制台验身在分裂脑下**不构成身份证明**。

夜间无人值守走查的硬设备协议（后续代理必须照做）：

1. 只允许操作 `emulator-5580`（`emulator -port 5580` 显式端口启动，serial 与雷电的 5554 物理隔离）；`emulator-5554` 及任何新出现 serial 一律禁区，`adb devices` 出现第二个 serial 即冻结记录、不枚举不触碰。
2. **每批**设备命令前双命令门禁：`adb -s emulator-5580 emu avd name` 答 `qimeng_api35` **且** `adb -s emulator-5580 shell getprop ro.product.model` 答 `sdk_gphone64_x86_64`——两验皆过才继续，任一不过即冻结上报（getprop 走传输通道，与控制台验身互补，正是分裂脑的破绽补位）。
3. 禁止 `adb kill-server` / `adb reconnect` / `adb connect`（adb server 是宿主共享状态）。
4. 模拟器启动一律显式 `-port`（避开 5554/5555），日志重定向文件（管道接 head 会把模拟器写日志阻塞在半路，表现为「启动卡死」假象）。

### 预览变体与端口纪律（2026-10-02 夜增补）

设计语言的真机预览装机（2026-10-02 手工临时改包名装过一次）暴露两个痛点：①两个同装 App 的内嵌服务端同抢 127.0.0.1:18430，后装者 `bind: address already in use` 起不来；②CI 的 debug APK 签名来自 AGP 每次自动生成的随机 debug keystore，用户每次下载都要卸载重装。据此把预览装机工程化（用户拍板：夜间禁止本地构建，装机产物唯一通道=云端 CI）：

1. **预览变体开关**：`-PqmPreviewAurora=true`（`android/app/build.gradle.kts` 文件头注释为同步责任单点）——applicationId 换 `media.qimeng.app.aurora` 与正式包**并存安装**（数据随包名隔离）、应用名「绮梦影库·流光」（app_name 单源迁至 resValue）、版本名加 `-aurora` 后缀。正式构建不传属性零变化；禁止回到手工改文件再还原的临时方案。
2. **端口错开**：预览变体内嵌服务端监听 **18431**（正式恒 18430）。单源=`ServerAddress.LOCAL_MODE_PORT`（`core:network` 的 `BuildConfig.QM_LOCAL_MODE_PORT` 构建期注入是唯一字面值点），内嵌 Service 监听（QIMENG_LISTEN）、健康探测、前台通知、登录/设置页预设地址全部从该源派生——任何端口消费方禁止再写字面值。
3. **CI 通道**：android job 在既有 debug artifact 之后追加预览构建步（`:app:assembleDebug -PqmPreviewAurora=true`），产物 `qimeng-aurora-preview-debug.apk`（artifact `qimeng-aurora-preview-apk`）；既有 debug artifact 与全部门禁语义零变动。触发通道=分支 push（2026-10-02 实测：分支与 master 分叉后 PR 转冲突态，GitHub 对冲突 PR 不建 merge ref、`pull_request` 事件不触发——push 触发分支名单增补 `ui/app-redesign`，夜间纪律「分支 push 后盯门禁」的落地形态）。
4. **签名稳定化**：专用预览 debug keystore 本机 keytool 生成、仓库外保管（绝不入 git——铁律14），base64 经 GitHub secrets（`QM_AURORA_PREVIEW_KEYSTORE_B64`）注入 CI 还原接入 signingConfig——固定签名=重复下载覆盖安装。secrets 缺失时自动退回 AGP 随机 debug 签名（降级=每次下载先卸载再装，README 记档）。口令为明显合成值，仅承担调试预览签名，非发布凭据。
5. **退役纪律**：预览分支合并（或废弃）时，qmPreviewAurora 开关、端口错开、CI 预览步与 secrets 一并清理——预览变体是设计语言评审期的脚手架，不是长期形态。

## 后果（Consequences）

- **积极**：媒体应用当代观感（暗色玻璃 + 辉光景深）；UI 仍是"最便宜可换的层"（ADR-0008），逻辑层零触碰；无白名单外依赖；API 26–30 自动降级不崩。
- **代价/风险**：旧灰系 token 全量退役，`QimengBrandColors` 消费点（QimengNavHost 底栏指示器、TimelineTagColors）须同步改；半透明面板对无障碍对比度需自查；expressive spring 的动能观感需走查校准（过弹则调 dampingRatio）；**MaterialExpressiveTheme/MotionScheme.expressive 消费 material3 1.5.0-alpha28 的 alpha 线 API，stable 前签名可能变动——版本本身是 master 既有基线，风险在本 ADR 新增的消费面（Theme.kt 两处调用），升级 material3 时须跟查**。
- **受影响文件**：`android/core/ui/src/main/java/media/qimeng/app/core/ui/theme/*`（Color/Theme/Type/Dimens）、`android/core/ui/.../glass/*`（新）、`android/core/ui/.../component/*`（换装）、`android/app/.../navigation/QimengNavHost.kt`、`android/feature/*/…Screen.kt`（渲染层）、`docs/adr/INDEX.md`、`docs/HANDOVER.md`、`docs/CHANGELOG.md`、`android/README.md`。
- 明确不做：主题手动开关（无既有功能，不擅自加）、backdrop 采样式模糊（无官方 API，降级路径已覆盖）、跨路由共享元素（见上）、Web/桌面端（本 ADR 仅 Android）。

## 修订记录

- **2026-10-03 底栏换代（悬浮玻璃坞移植）**：本文档级的「玻璃底栏（GlassNavBar）」实现退役，替换为自评审分支 ui/app-floating-glass-tab 移植的「悬浮玻璃坞」（FloatingTabDock：单颗滑动胶囊+液态玻璃 backdrop 采样管线，依赖 io.github.kyant0:backdrop 2.0.1——本文档「明确不做 backdrop 采样式模糊」一项随真实依赖落地而撤销，依赖决策详见主线分支 ADR-0033 四问记档）。双胶囊交叉淡化三缺陷（相位独立空隙不均/透明主色浅色洗白/胶囊与图标垂直错位）随换代根修。底栏的其他设计语言（悬浮坞形态/玻璃材质/日夜双板）与本 ADR 一脉相承。
