# ADR-0024：上传拆分——资产编辑页承载作者挂靠与通用来源词表

## 背景（Context）

ADR-0023 把挂靠入口放在上传协议（可选 query `authorId`/`authorName`/`source`），实践暴露四个问题：① 上传是**批量动作**，媒体归属往往要看图/看内容后才能确认，传前填表违背操作自然顺序；② 挂错**无事后纠错**——参数一旦随上传提交，改归属只能重传或手工改 TXT 再重导；③ 来源建议取「个人片段来源区词表」（GET /authors/sources），作者各自的个人链接对他人是噪音，个人词表污染全局建议；④ 「来源」语义误设——它实际是**获取渠道/平台名**（如「forum-c」），不是 §4 SourceMatcher 的作品出处，靠上传顺带填写的定位抬高了理解与维护成本。约束不变：TXT 片段本体仍是唯一真相（DOMAIN_RULES §6），任何旁路存储都会在统一重建时漂移。

## 决策（Decision）

1. **上传挂靠参数退役**：POST /assets/upload 删除 `authorId`/`authorName`/`source` 三参数，上传回归纯上传（参数面仅 libraryId/dir/filename，四道安全校验不变）；GET /authors/sources（个人片段词表）删除。
2. **挂靠入口迁资产编辑页**，新增三端点（TXT 真相模型原样沿用：写片段本体、与手工片段同构、落点规则与 ADR-0023 的 Apply 共用）：**PUT /assets/{assetId}/authors**（body `{authorIds}` 整体替换资产作者关联——新增=资产当前文件名作为作品行写作者块〔落点规则同原上传挂靠〕，移除=遍历全部片段删该资产行〔行文本精确匹配优先、trim+小写+去空格归一回退且**归一保留扩展名**——png/mp4 同名互不误伤〕，同事务更新 asset_authors，200 回 AssetDetail；仅 `capabilities.authorAttach=true` 可用否则 400）；**GET/PUT /authors/{authorId}/sources**（常规作者片段来源区读写；GET 无块=空数组、作者不存在 404、COS 作者 400；PUT 整体替换该作者块来源区，无块=最近导入片段新建块，无片段自动建「上传自动挂靠.txt」）。编辑成功后**同步修剪** kv `imported_txt_upload_entries` 机器写入条目——修剪方向=内容中已不存在的登记条目才剪（编辑是有意变更，防同文件名重导入 409 误报）；编辑不新增登记条目，故重导入保护此后只覆盖存量条目。
3. **来源建议改服务端手动维护的通用词表**：新增 GET/PUT /authors/source-vocabulary（kv_settings `author_source_vocabulary`；GET 无记录=空数组；PUT 整体替换、trim+去重、单项控制字符/超 500 rune 400、原始数组超 32 项 400），作为来源建议**唯一数据源**；Web 设置页设维护卡收编自由输入的新词；个人片段来源区词表退出建议场景；与 §4 SourceMatcher/custom_sources 继续严格隔离禁混用。
4. **客户端**：Web 上传卡撤作者/来源控件 + 新增拖拽目录递归上传（webkitGetAsEntry，相对路径映射库内子目录）+ 资产编辑页（详情页「编辑」进入：作者增删 + 每作者来源区编辑）+ 设置页通用来源词表卡；Android 上传选文件改**内置相册式选择器**（MediaStore 缩略图网格多选，替代系统 SAF 选择器；权限 READ_MEDIA_IMAGES/READ_MEDIA_VIDEO + READ_EXTERNAL_STORAGE≤32，MANAGE_EXTERNAL_STORAGE 保留给服务内嵌服务端）+ 资产编辑页（详情作者 Sheet 进入）+ 上传页撤作者/来源段。桌面壳零改动（自动继承服务端 Web）。

## 状态（Status）

Accepted（2026-09-25）

## 后果（Consequences）

- **积极**：归属确认回到「看图后编辑」的自然时点且支持事后纠错；来源语义归位（获取渠道）且建议源单一可控；上传参数面收敛回最简形态。
- **代价**：重导入保护覆盖面收窄——只保护 kv 存量登记条目，编辑后的新状态不再有上传条目兜底（有意取舍；修剪方向=只剪内容中已不存在的条目，保证不误报 409）。
- **已知缺口（记档，不修）**：① 资产改名/移动不回写片段作品行（既有行为）——按当前文件名匹配不到的残留行会被统一重建重新关联，后续项=改名同步片段行；② 同片段跨块同名作者 RemoveWorks 只清首遇块（与解析器身份口径一致，统一重建兜底）。
- **与 ADR-0023 的关系**：真相模型（片段本体唯一真相、同事务、重导入 409+conflictResolution 保护）全部不变；其决策 3（上传协议可选 query 参数）由本 ADR 退役，已在该 ADR 追加修订记录。
- **联动**：`server/internal/httpapi/upload.go`（参数退役）、`server/internal/authoring/edit.go`（RemoveWorks/ReplaceSources/PruneUploadEntries 纯函数）、`server/internal/authorattach/edit.go`（编辑编排）、`server/internal/httpapi/author_edit.go`、`web/src/pages/AssetEditPage.tsx`（含上传卡撤控件/拖拽目录）、`android/feature/upload/`（MediaPicker 相册式选择器）、`android/feature/detail/`（AssetEditScreen）、`api/openapi.yaml`、`docs/DOMAIN_RULES.md` §6、`docs/GUIDE_API.md`、`docs/SECURITY.md`（上传安全退役注记）、`docs/ARCHITECTURE.md` §5、`docs/CAPABILITY_MAP.md`、`docs/HANDOVER.md`、`docs/adr/0023`（修订记录）、`docs/adr/INDEX.md`。

## 修订记录（2026-09-25 同日，上传流程自动挂靠）

用户澄清真实工作流：下载文件需**先核对作品名/作者/来源再上传**，希望 App 内一步完成（暂存列表逐项快捷编辑 → 上传 → 自动同步 TXT），而非上传后另去编辑页。修订：**上传协议保持纯上传不变**（决策 1 不回收——挂靠仍不走上传参数），但 App 上传流程在单文件 201 后由客户端依次调用 PUT /assets/{assetId}/authors（authorIds 单项，新资产零关联无覆盖风险）与 PUT /authors/{authorId}/sources（**mode=append**——该端点请求体增可选 `mode=replace|append`，缺省 replace 即决策 2 原语义；append=并入去重永不覆盖，对齐 ADR-0023 原上传来源口径）。挂靠失败不重试上传（防文件重复入库），条目落「已入库待挂靠」态由编辑页补挂——决策 2 的编辑页由此兼任上传流程的失败恢复路径，REQ 原子性关切以「可恢复」口径满足。真相同步/落点/修剪与编辑端点完全同链路。

## 修订记录 2（2026-09-25 同日，持久暂存区与作品名序号联想）

用户进一步固化工作流：下载文件放进手机点前缀隐藏文件夹（相册不可见）可能放置数日，需 **App 内持久暂存区**（改到一半的元数据跨进程/跨天保留）+ **收件箱**（设置页 App 内目录浏览器指定真实文件夹〔依赖 MANAGE_EXTERNAL_STORAGE，纯 File API 不用系统弹窗〕，文件夹内媒体文件自动进暂存区，上传成功后源文件移入其 `uploaded/` 子目录归档〔该口径由修订 3 升级，未设归档文件夹时对收件箱来源继续生效〕）+ **作品名序号联想**（新端点 GET /assets/name-suggestions：规范化前缀匹配+少空格吸附、建议吸附库内既有命名风格+下一序号〔裸/括号风格跟随、跨扩展名同系列、前导零不保留〕、cap 3；客户端扩展名锁定不可编辑）。同批：通用词表出厂自动预填（键不存在时从片段来源区统计——≥2 位作者共用保留、单作者个人地址与链接形态排除、cap 20，PUT 恒写键故清空不复活）。暂存区客户端持久化属 App 本地态，不入协议。

## 修订记录 3（2026-09-28，上传归档文件夹与浏览文件入口）

用户澄清同步诉求：上传到 NAS 的文件要在手机侧按库整理成「可手动复制到电脑」的自留归档区。修订（全部 App 客户端行为，协议零改动）：

1. **上传归档文件夹**（取代 uploaded/ 通用归档）：用户指定归档根后，上传成功的**路径来源**（isPathSource，收件箱与浏览文件同权）源文件移动到 `<归档根>/<sanitize(库名)>/<原文件名>`（库名按 Windows 保留字符集 sanitize，归档根会被复制到电脑故取更严口径；同名异容加序号绝不覆盖、同名同内容删旧放新；renameTo 优先、copy+delete 跨挂载兜底，copy 走 `.part` 临时名落地防半截残留）。相册（content://）来源永不移动。**未设归档根时回退收窄**：仅收件箱来源维持修订 2 的 uploaded/ 旧行为（源父目录与收件箱目录 canonical 精确相等才归档），其它路径来源不动源文件——修复 uploaded/ 搬移对任意浏览目录的扩散。库名经上传载荷入队传递（UploadRequestSpec.libraryName，旧载荷缺键回退空串→按未设处理保底不丢文件）。归档失败只记完成通知提示不阻断上传。
2. **浏览文件入口**：上传页第三入口「浏览文件」——App 内目录/文件浏览器（目录浏览器组件上提 core:ui 单源 `DirectoryBrowserCard`，收件箱设置页同款复用），**含点前缀隐藏目录**（系统相册扫不到的 `.xxx` 正是目标场景），多选入暂存区；需 MANAGE_EXTERNAL_STORAGE，未授权弹引导跳系统设置。
3. **作者选择默认全显**：批次/逐项/资产编辑三处的作者联想控件空输入即显示全部常规作者（GET /authors 全量过滤 COS，纯函数 toRegularAuthorSeeds 单源；不动 /authors/suggest 协议），输入后仍走服务端联想。
4. **入口迁移**：收件箱设置页（更名「上传收件箱与归档」，双卡：收件箱路径 + 归档文件夹）入口从设置页迁到数据管理页。

同批另有与上传链路无关的 App 列表修复（触底哨兵 reloadTick 重评估/推荐流空轮续拉/翻页失败退避重试/下拉刷新立即受理+预取避让），见 CHANGELOG 第三百九十六笔，不属本 ADR 范畴。
