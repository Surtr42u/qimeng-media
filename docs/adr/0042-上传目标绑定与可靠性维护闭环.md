# ADR-0042：上传目标绑定与可靠性维护闭环

日期：2026-10-19。

## 背景（Context）

持久上传原来执行时读取可变地址，切服可能让旧任务落到新端。备份恢复、文档同步和供应链检查缺少可重复验证。用户授权完善现有模块化单体。

## 决策（Decision）

- 入队固定 URL，不存 token；直传/分片/挂靠同端，关闭重定向。切服或旧任务缺目标则拒绝，用业务失败输出避免取消整条 WorkManager 链。迟到 401 核对地址与 token 后处理。
- 逐步下沉只读扫描计划到 localsync；作者查询先聚合资产 open 事件，共享/零作品计数不变，不改 schema 或公式。
- 文档专题同步进 PR 门禁；固定 Actions SHA、只读权限及扫描工具，接入五生态更新及 Go/npm/Cargo 漏洞检查。容器降权显式选择，先验卷权限。

## 状态（Status）

Accepted。自动化范围与设备验收分开记录。

## 后果（Consequences）

URL 不识别同址新实例，已发请求可在原端完成，清 token 不是原子条件写。遗留写入编排仍待下沉，源 mtime 上传未实现；不以单测替代 NAS/实机/掉电验收。漏洞未修复或网络失败不算门禁通过。

影响 Android 上传/network、server 的 localsync/store 查询、tools 与 .github。现行约束见 [SECURITY](../SECURITY.md)、[ARCHITECTURE](../ARCHITECTURE.md)，演练证据见 [RESTORE](../RESTORE.md)，验证与剩余项见 [HANDOVER](../HANDOVER.md)。
