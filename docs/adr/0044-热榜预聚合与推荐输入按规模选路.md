# ADR-0044：热榜预聚合与推荐输入按规模选路

日期：2026-10-20。

## 背景（Context）

共享作品让事件与作者/标签连接成倍展开；窄媒体/COS 推荐仍聚合全库事件、读取全库标签。直接统一为候选查询虽加速窄流，却使合成宽流变慢。

## 决策（Decision）

- 热榜按窗口、资产汇总 open，再连接现存资产及作者/标签求和，保留每位关联者的完整归属。
- store 装载推荐输入：默认宽流保留原两查询；显式媒体/COS 流先 COUNT，候选不超过总资产一半时按候选读事件与标签，否则顺序聚合。规模仅选计划，实际查询重判资格，不能据此跳过或截断候选。
- 复用 sqlc/参数化 JSON 集合与既有索引；无 schema、依赖、协议、评分或缓存变化。保留旧 SQL 对照、计划与宽窄基准。CTE 可被展开，依据 [SQLite WITH 文档](https://www.sqlite.org/lang_with.html)。

## 状态（Status）

Accepted；合成验证通过，真实硬件另验收。

## 后果（Consequences）

显式宽筛选多一次 COUNT；比例阈值须随历史密度复测。SQL 资格谓词的静态副本由等价测试约束。影响 server/internal/store 与 httpapi/recommendations.go；现行策略、复跑命令及代价见 [统计](../domain/statistics.md#热榜查询策略与性能边界)、[推荐](../domain/recommendation.md#16-输入装载策略与性能边界)，同步 ARCHITECTURE/server README/能力地图。
