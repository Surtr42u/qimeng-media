# ADR-0055：手机无前台维护结果包协议

## 背景（Context）

ADR-0052 与 [AI 维护 P0](../AI_MAINTENANCE_P0.md) §4.5 要求「PC→手机无前台维护」：PC 生成作者主表 TXT 与 v2 便携备份，手机在充电/未计费 Wi-Fi 条件下后台拉取、应用并回读，不依赖 USB 或打开前台界面。手机既不能监听入站（内嵌服务回环对 PC 不可达），也不能由服务端推送执行，因此必须由手机主动出站领取并回传；服务端需要一个可持久、可校验、可恢复的结果包账本。

本轮是 P4 第一刀，只做**服务端 API 与存储**：没有 Android Worker、没有配对/设备身份、没有真机后台验收。没有服务端包账本时，Phone Worker 无法判断包是否完整、是否重复应用、断网/进程被杀后从哪继续。

## 决策（Decision）

1. **两张只增表**：migration `0024_device_apply_tasks` 新增 `device_apply_tasks`（id/目标设备标签/状态/协议版本/规则指纹/manifest_json/created_at/updated_at/claimed_at/finished_at/expires_at/result_json）与 `device_apply_segments`（task_id/kind/bytes/sha256/rel_path），并加设备+状态+新建倒序索引与过期索引；不改历史表/索引。段字节不进 SQLite。
2. **包结构**：创建为 `multipart/form-data`，字段 `manifest`（JSON 字符串）加可选 `masterTxt`/`v2Backup` 文件段。manifest 声明 `targetDeviceId`（不透明标签）、`protocolVersion`（仅 1）、`rulesFingerprint`（64 位小写十六进制）、`ttlSeconds`（300–604800，缺省 86400）与 1–2 个 `segments`（kind/bytes/sha256/expectedReadback）。manifest 未知字段直接拒绝，协议演进必须升版本。
3. **上限**：masterTxt ≤1MiB、v2Backup ≤64MiB、manifest ≤256KiB，整个请求体 66MiB；单个段超限或整体超限 413 `TOO_LARGE`，manifest 声明超限/实际字节不符 400。
4. **先落盘校验后写库**：按 taskId 生成 `<dataDir>/device-apply-packages/<taskId>/<kind>.bin`，写入时流式 SHA-256、写完 `Sync` 并比对声明字节数与摘要；全部通过后才在单事务插入任务与段行，任何失败删除任务目录。读取时要求 rel_path 与「taskId/固定文件名」逐字相等并做根目录包含校验，下载前复核文件类型与大小。
5. **状态机与惰性过期**：`pending → claimed → applied/partial/failed`；`pending/claimed → cancelled`（PC）或 `expired`。终态不可再变更。过期不靠后台循环：列表/详情/领取/下载/回传/取消路径先执行条件 UPDATE，把到期活动任务标记 `expired`。
6. **端点族**：`POST/GET /api/v1/device/apply-tasks`、`GET /api/v1/device/apply-tasks/{id}`、`POST …/{id}/claim`、`GET …/{id}/segments/{kind}`（octet-stream + Content-Length + X-Content-SHA256）、`POST …/{id}/result`、`POST …/{id}/cancel`。全部沿用全局 Bearer，不新增免鉴权面。
7. **幂等语义**：创建无幂等键，重复登记生成新任务；领取对已 claimed 且未过期任务幂等返回 200（本切片无领取者身份，无法区分重试与另一设备，因此按幂等处理）；回传只在结果按归一化 JSON 完全相同时幂等 200，任何字段不同 409；取消对已 cancelled 幂等 200，其他终态 409。上述语义写入 OpenAPI 与 `docs/api/device.md`，后续配对/身份落地时重新评审。
8. **分层**：账本、状态机、过期、段文件与摘要校验全部在 `server/internal/deviceapply`，只依赖 store/db 与标准库，不依赖 httpapi（depguard）；httpapi 只做 multipart/query 校验、错误映射与响应装配（ADR-0019）。
9. **安全边界**：targetDeviceId 只是标签，本轮不做配对、设备身份或设备级授权；任何持 Bearer 的调用方可登记/领取/回传，与单用户管理面一致，不能当作已实现设备授权。取消/过期不删除段文件，本切片无包清理任务。
10. **协议先行**：先改 `api/openapi.yaml`，再 `make sdk` 生成 Go/TS/Kotlin 三端，同批重算 `api/sdk.lock`（355 项）。Go 枚举用 `x-enum-varnames` 前缀命名，避免 oapi-codegen 常量冲突。

## 状态（Status）

Accepted（2026-11-07）。源码、协议、SDK 与锁同批交付；**未安装**到现装 PC/手机。Android Worker、配对/设备身份、真机后台领取/应用/回传、包清理与 Web 任务中心仍未实现。业务 `go test` 按仓库规定走云端 CI；本地已跑 `make sdk`（含 `go build ./...`）、`gofmt`、`go vet`、文档/隐私/迁移检查。

## 后果（Consequences）

积极后果：PC 与手机之间有了可持久、可校验的包协议；段摘要与字节数在写库前验证，坏包不会留下半条账本；手机可安全重试领取与相同结果回传；惰性过期保证断网/遗留任务最终可判定；协议与三端 SDK 同源，后续 Worker 不必自定义传输。

代价与风险：没有设备身份时领取/回传只靠 Bearer，无法阻止另一设备领取同一包；领取幂等以「无 owner」为前提，加入配对后需要重新设计；结果幂等依赖服务端归一化规则，客户端更改 readback 字段会得到 409；取消/过期不清理字节，长期运行可能堆积；创建无幂等键，重复登记会产生重复包；binary 下载不支持 Range，大备份失败需重下；未做真机后台可靠性验收，Doze/厂商限制仍是后续风险。
