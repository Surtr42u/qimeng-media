# ADR-0037：跨库浏览事件兜底重映射

## 背景（Context）

用户实测事故：App「同步浏览数据」把本地优先队列的浏览事件按**原 assetId** 直发当前连接的服务器；用户「本机模式→NAS/PC」切换后同步时，事件的 assetId 属于源库、目标库不存在 → 服务端现行行为 = 事件入库 `view_events`（真相源无外键，ADR-0005）、物化表 `asset_daily_stats` 因外键拒绝跳过、202 返回（engagement.go「已删资产迟到事件」分支）→ 所有 JOIN assets 的口径（趋势/榜单/作者标签/App 统计页）都不显示，只有 overview.totalViews（直接数事件流）计入——表现为「本机模式→NAS 后同步记录不显示」且桌面端计数虚高（同一批数据 totalViews 与明细口径劈叉）。PC 库实查有 273 条此类孤儿事件。

关键约束：跨库投递场景下事件载荷只有**源库 assetId**，目标库无从据以定位资产；但设备侧事件产生时天然可知文件身份（展示文件名 + 库内相对路径）。

备选方案：① 不新增按钮/不改用备份导入通道（用户拍板直接升级现有「同步浏览数据」——备份导入 §10 本就有按文件名匹配能力，但载荷全库重、不是该按钮的语义）；② 实时通道也按「同名多命中取最早入库行」宽松兜底（镜像 §10 导入口径）；③ 服务端单方面修复。

## 决策（Decision）

1. **协议**（openapi.yaml 唯一事实源，ADR-0001/0009）：`ViewEventReport` 增可选 `fileName`/`relPath` 文件身份；新增 `EventsViewAccepted`（`outcome`: ok/remapped/unmatched）作为 `/api/v1/events/view` 202 响应体（字段缺省/无法解析按 ok 处理，客户端不得据此判定失败）。
2. **服务端语义**：assetId 命中本库 → 原路径（outcome=ok，带 fileName 也不重映射）；未命中且携带 fileName → 按文件名精确匹配本库资产（**唯一命中**，或（多命中时）经 relPath **精确等值**消歧后唯一）→ 事件记入该资产、正常物化计统计（跨库合并）、202 outcome=remapped；**零命中/仍歧义/未携带** → 维持「已删资产迟到事件」口径（事件入库、统计跳过、202 outcome=unmatched）。
3. **歧义绝不猜测，宁少勿错**：实时通道不镜像 §10 备份导入的「同名多命中取最早入库行」宽松兜底——那是 legacy 批量通道的历史约束；本通道未匹配宁可不计也不误配（误配=把甲文件的浏览记到乙文件，污染推荐输入）。
4. **会话去重/幂等键口径不因重映射改变**：去重键 = 重映射后的目标资产；幂等键（clientEventId）命中、会话去重命中都按 ok 回复（未新增计数，不虚报合并）。
5. **刻意不做**：不新增按钮（否备选①，用户拍板直接升级现有同步按钮）；不做服务端单方面修复（否备选③，事件载荷缺文件身份无从重映射——App 侧补身份是必要前提）；不加索引/不加 migration（file_name 无索引的全表扫描只在 assetId 未命中的罕见路径发生，属可接受成本，函数注释说明）；响应 outcome 不落库（纯透出，幂等重放语义不依赖它）。

## 状态（Status）

Accepted（2026-10-11，用户拍板）。

## 后果（Consequences）

- **积极**：跨库切换后同步的浏览记录正确计入目标库全部统计口径；App 可据 outcome 如实提示（「N 条已按文件名并入 / M 条未匹配未计入统计」）；旧客户端忽略响应体行为不变（202 语义与状态码零变化）。
- **代价与风险**：同名误配风险 → 缓解 = 唯一命中才用 + relPath 精确消歧 + 歧义不猜；实时通道统计从严比导入通道少计部分事件（接受：少计优于误配）。
- **复查条件**：出现误配证据或同名碰撞率高 → 评估增加字节数指纹（sizeBytes）等文件身份增强（协议已预留加字段空间）。
- **受影响文件/文档**：`api/openapi.yaml`、`server/internal/store/queries/assets.sql`（AssetExists/ListAssetIDsByFileName）、`server/internal/httpapi/engagement.go`、`engagement_remap_test.go`、`api/sdk.lock`、`docs/DOMAIN_RULES.md` §5（含与 §10 差异说明）、`docs/GUIDE_API.md`、`docs/CHANGELOG.md`、`docs/HANDOVER.md`；App 侧事件队列加 fileName/relPath 列（Room 2→3 迁移）并携带文件身份上报。
