# ADR-0032：关联/作者类记录溯源体系（created_at + origin 双列）

## 背景（Context）

2026-10-02 三方数据取证暴露两个真问题：

1. **关联类记录无溯源可考**：asset_authors/asset_tags（部分）/asset_characters/authors 行不带"何时、经何通道写入"的证据。跨设备核对时 PC 端多出 152 条作者/标签关联**无时间戳可考**，无法判定是用户手工操作产生还是某次导入写入——合并裁决只能靠猜，"宁可少替换也不造假版本"的既有纪律（§10 标签组语义）在行级无据可施。
2. **view_events 三代回放叠加**：1×/3×/6× 三代键各不相同，09-18 引入的内容键幂等只能拦同代重复，拦不住跨代并存。该问题**不在本 ADR 范围**（见下方「边界」），但同批取证确认了"没有溯源的记录无法做确定性裁决"这一共因。

溯源缺口的本质：库内记录只有"内容"，没有"来历"。跨端合并、数据取证、真伪判定都要求记录携带来历证据，且该证据要能随备份**跨设备透传**——A 端手工创建的关联被备份带到 B 端后，B 端应知道它最初经何通道产生，而不是盖一个"导入"章把来历抹掉。

## 决策（Decision）

### 1. 范围与列设计（migration 0016，只加不改）

| 表 | 新增列 | 类型与哨兵 | 说明 |
|---|---|---|---|
| asset_authors | `created_at TEXT`（可空） | **NULL = 不可考** | 存量行回填 NULL——历史关联时间无据，**禁止伪造**；新写入恒盖当前时刻 |
| asset_authors | `origin TEXT NOT NULL DEFAULT 'legacy'` | 受控词表见 §2 | 存量行默认 'legacy'（如实记录不可考） |
| asset_tags | `origin TEXT NOT NULL DEFAULT 'legacy'` | 同上 | `created_at` 已由 0004 建立（NOT NULL DEFAULT epoch），**不动既有列**；epoch = 既有"不可考→视为最旧"哨兵，口径不变 |
| asset_characters | `created_at TEXT`（可空）+ `origin`（同上） | NULL = 不可考 | 角色行是扫描器重算产物（先删后插），其 created_at 语义 = **当前推导发生时刻**，每次重算刷新——不是首次出现时刻，如实记档 |
| authors | `origin TEXT NOT NULL DEFAULT 'legacy'` | 同上 | `created_at` 已有，不动 |

**时间戳格式沿用库内统一口径**：UTC + RFC3339 固定毫秒文本（0001 文件头约定，`store.FormatTimestamp` 单源），不引入整数毫秒列——字典序可比性与全库一致性优先。

**哨兵口径的分表差异（有意取舍，记档）**：asset_tags.created_at 是既有 NOT NULL 列，只能沿用 0004 的 epoch 哨兵（且它驱动详情页"最近添加置顶"排序，需要全序）；asset_authors/asset_characters 的新列是本次新建，取 NULL=不可考的诚实口径（无排序职责，NULL 在 DESC 排序中与 epoch 同样沉底）。两种哨兵语义等价：都表示"不可考"，都不伪造。

### 2. origin 受控词表（服务端写入通道口径，常量单源 `server/internal/store/provenance.go`）

| 值 | 通道 | 盖章点 |
|---|---|---|
| `client` | HTTP 客户端端点写入 | PUT /assets/{id}/tags、PUT /assets/{id}/authors（ADR-0024 编辑页）、上传挂靠 authorattach.Apply |
| `txt` | TXT 片段统一重建 | POST /authors/import-txt 手动通道（关联随重建重挂） |
| `import` | 备份导入通道 | POST /import/qimeng-backup（含备份 TXT 片段段触发的重建；备份未透传来历时的兜底章） |
| `local-sync` | 本机同步通道 | ADR-0030 自动导入的 TXT（经同一 importTxt，通道参数区分）；其媒体文件入库后的关联由扫描器派生盖 `scanner`（媒体本身不经挂靠） |
| `scanner` | 扫描器派生 | asset_characters 全部、COS 作者关联（目录结构派生，重扫重挂） |
| `legacy` | 0016 迁移回填 | 存量行专用，=「不可考」；写入端**永不**主动写此值 |

**为什么只有 `client` 不分 app/web**：两端命中完全相同的服务端端点，服务端无从区分（User-Agent 猜测=会随客户端 HTTP 栈漂移的脆弱启发式，违反"宁可不可考也不造假"原则）。设备级区分留待协议级客户端标识（如请求头）再立项；词表以 TEXT 存储、Go 常量校验（不设 SQL CHECK），未来扩枚举不需要迁移。

### 3. 透传与导入裁决（合并语义升级，DOMAIN_RULES §10 同步修订）

- **导出透传**：备份载荷 `LegacyAuthor.origin`、`LegacyAuthorMediaRef.createdAtMillis+origin`、`LegacyMediaTagRef.origin` 新增（全部可空/缺省=旧版备份无此信息）。导出把库内**原始来历**原样带出——A 端手工创建的关联到 B 端仍是 `client`，来历不因搬运而失真。
- **导入裁决**（先改 DOMAIN_RULES §10 再改代码，铁律 3）：
  1. 词表校验：透传 origin 非法或缺省 → 兜底盖 `import`；透传时间缺省/≤0 → 兜底记导入时刻（"何时入账"是真实事件，不算伪造）。
  2. **补证规则（heal）**：既有行不可考（origin='legacy'，或时间哨兵 NULL/epoch）时，被透传值**补证升级**——不可考不等于永久不可知，对端有据时以对端为据。
  3. **首写优先（keep）**：既有行可考时**绝不覆盖**——重复导入幂等，保守不篡改既有结论。
  4. 标签组**集级**裁决维持 0012 的 `tag_set_updated_at` 口径不变（谁新听谁）；本次升级的是**行级**溯源（并集/替换路径的每行盖章与补证）。
- 作者行（authors）：origin 只在 ON CONFLICT 分支按补证规则升级（legacy → 本次通道），display_name/created_at/followed 既有规则不动。

### 4. API 面（协议先行，仅备份载荷）

- 动：上述三个备份 schema 增可空字段 → `make sdk` 三端重新生成 → `api/sdk.lock` 同 commit 更新。
- 不动：详情/列表响应模型（AssetDetail/Author/Tag）**不透出** origin/created_at——溯源读取走 GET /export/qimeng-backup 已全覆盖（载荷携带全部关联行级溯源），详情页 UI 展示留待独立提案；web/app 对新增字段零消费零改动，仅需 SDK 再生成。

### 5. view_events 边界（不在本 ADR 范围，记档）

view_events 已有行级溯源能力（session_id + client_event_id + `legacy:` 内容键前缀，migration 0010/0014），三代回放叠加的根因是**每代键命名空间不同**而非无溯源列——修法是键空间统一或换代清洗，属导入回放语义专项，不与关联类溯源混做。关联类四表与事件流的溯源粒度自此对齐：每行可考"何时、何通道"。

## 状态（Status）

Accepted（2026-10-02）

## 后果（Consequences）

- **积极**：跨端合并从"猜"变"确定性裁决"——152 条式悬案自此可按（origin, created_at）直接判真伪/通道；备份透传使来历跨设备存续；作者行可区分 TXT 导入作者与手工挂靠作者（本次痛点）。
- **代价**：写路径全量补两个参数（机械但必须全盖，漏盖=溯源缺口）；origin 为 TEXT 无 CHECK，垃圾值理论上可入库（导入端词表校验兜底；扩枚举零迁移的代价）。
- **已知边界（记档）**：① 存量行补证依赖"对端备份有据"——两端都不可考的行永远 legacy/NULL，如实；② asset_characters.created_at 是重算时刻不是首次出现时刻（派生数据语义，重算即真相更新）；③ client 内部不区分 app/web/桌面壳（协议级客户端标识后置）。
- **联动文件**：`server/migrations/0016_*`、`server/internal/store/provenance.go`（词表单源）、`server/internal/store/queries/{authors,tags,legacy_import,legacy_export}.sql` + 生成物、`server/internal/httpapi/{tags,authors,import,export,localsync_runner}.go`、`server/internal/authorattach/{attach,edit}.go`、`server/internal/scanner/enrich.go`、`api/openapi.yaml`、`api/sdk.lock` + 三端生成物、`web/src/lib/provenance.ts`（词表 web 侧中文映射单源，第四百三十九笔起——扩词表时与服务端 provenance.go 双写同步）、`server/internal/store/store_test.go`（迁移链）+ 溯源行为测试、`docs/DOMAIN_RULES.md` §10、`docs/GUIDE_API.md`、`docs/CHANGELOG.md`（第四百三十五笔）、`docs/adr/INDEX.md`。
