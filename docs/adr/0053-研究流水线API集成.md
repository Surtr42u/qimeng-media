# ADR-0053：研究流水线API集成

## 背景（Context）

外部 AI 研究作者/作品时，此前只有本地脚本和零散实测：FxTwitter、Pixiv ajax、yande.re、e621、Wayback CDX、Steam Web API、Bing HTML 可纯 HTTP 直连；Google Lens、Google 文本、ascii2d、Yandex、Bing Visual、IQDB、DDG、Brave 不可用或需要 sidecar。Lens 只能由 PC 本地 loopback sidecar（headless Edge/CDP，单实例串行）承担，单帧 17–18s，视觉匹配卡片没有外部 href、`links[]` 经常为空。

批次复盘结论是：早停按"平台指向"而不是"认出作者"判定，平台 API 决定证据等级（confirmed/likely），检索只决定有无线索。把这些能力只留在脚本里，外部 AI 每次都要重新发现接口、绕过鉴权、重复踩 SSRF/限流坑，也无法共享统一错误语义与预算。需要把已验证能力做成服务端正式 API，同时不把任何单一 provider、也不把 Lens 变成硬依赖。

## 决策（Decision）

1. **服务端原生 provider 网关**：新增 `GET /api/v1/research/context`、`POST /api/v1/research/providers/{provider}/query`，v1 固定矩阵 fxtwitter(author,post)、pixiv(author,work)、yandere(artist,tags)、e621(post,tags)、wayback(url)、steam(workshop)、bing(search)。矩阵外组合 400 `INVALID_PARAM`；上游失败以 `ResearchProviderResult.status`（ok/not_found/blocked/rate_limited/provider_unavailable）表达而仍回 200，单个 provider 失败不影响其他 provider，调用方可自行改走其他渠道——不引入重试编排，也不硬依赖任何 provider。
2. **Lens 只经本机 sidecar 代理**：新增 `POST /api/v1/research/lens`（multipart `file`，JPEG/PNG/WebP ≤20MiB）；服务端不内嵌浏览器、不启动 sidecar，只把图片转发给 loopback 端点。sidecar 契约 `GET /healthz` + `POST /lens`（Bearer）。`links[]` 正式标注为 best-effort、可为空，不得当作识别证据；`status=ok` 不等于认出作者。
3. **默认关闭、嵌入式禁用**：`research.enabled` 默认 false，嵌入式/Android 形态默认保持关闭且不新增监听面（端点挂在既有服务端上）。开启后 provider 出口只走内建安全 HTTP 客户端（仅 https、域名白名单、禁重定向与环境代理、DNS 解析后校验公网地址、20s 超时、2MiB 响应上限）；sidecar 只允许 `http://127.0.0.1:<port>`/`http://[::1]:<port>`，token 只从 `QIMENG_RESEARCH_SIDECAR_TOKEN` 或被忽略的 `.local` 配置读取，启动期校验失败即拒绝启动。
4. **预算与证据**：provider 每 provider 每分钟、Lens 每小时/每日的进程内预算（默认 20/20/100，时钟可注入、UTC 对齐、重启清零）；超限 provider 回 `rate_limited`、Lens 回 429。证据落盘到 `<dataDir>/research-evidence/<日期>/*.json`，剥会话参数、只记公开字段与哈希、不存图片字节、不入库。
5. **协议先行**：以上三端点与 schema 先进 `api/openapi.yaml`，再 `make sdk` 生成三端，`api/sdk.lock` 同批重算。Go 侧枚举显式使用 `x-enum-varnames`：oapi-codegen v2.8.0 对裸值常量名做全局去重，新增含 `ok` 的枚举会把既有常量重命名并导致编译失败，显式命名是让新老枚举互不干扰的最小改动。
6. **分层**：provider 矩阵、安全客户端、预算、sidecar、证据都在 `server/internal/research`；httpapi 只做协议校验、错误映射与响应装配（ADR-0019）。测试用 httptest 假上游与假 sidecar，即使用合成数据，不访问真实平台。

## 状态（Status）

Accepted（2026-11-06）。源码、协议与 SDK 已同批交付；796d813f 已安装 PC/手机，2026-11-07 以临时环境在本机跑通 `/research/context` 与真实 `/research/lens`。**真实 provider 查询未验收**：本机 DNS fake-IP（198.18.1.x）被 SSRF 校验拦截返回 ADDRESS_BLOCKED，需本机切真实 DNS 或另立显式逃生配置。默认配置仍关闭，日常启动行为不变。

## 后果（Consequences）

积极后果：外部 AI 有稳定、可发现的作者/作品核验入口，错误码与预算语义统一；Lens 留在 PC 本地，服务端不引入浏览器依赖；默认关闭把出网与 CPU 成本交给部署方显式开启；单 provider 失败可回退，不把研究结论绑定到单一平台。

代价与风险：服务端新增出网面（仅白名单 https），需要平台可用性监测；sidecar 是单实例串行瓶颈（17–18s/帧），批量反查必须排队；Bing 依赖 HTML 结构、第三方接口随时可能改版或加风控，只能回退不能保证；证据目录需要部署方自行清理；`links` 为空是已确认缺陷，不能通过重试修复。
