# ADR-0025：库根自动重挂（auto-relink）——扫描器按资产样本指纹找回被改名/移动的库根

## 背景（Context）

库身份在 DB 里以 `root_path` 绝对路径登记（migrations/0001），资产只有 `rel_path` 相对路径属性（ADR-0004 路径是属性）。用户在磁盘上改名/移动库根目录是普通文件管理操作（实际事故：库 "3  cos图集" 根目录改名后 5564 条资产文件全部不可达，扫描器报「遍历库失败：找不到路径」，库显示名也停留在旧名）——**路径身份天然不可靠**，每次都要求用户手动改库配置或重建库（资产 id/收藏/播放历史全部作废）不可接受。

约束：重挂判定必须是纯函数（铁律 3）；宁可放弃也绝不猜测（挂错目录会让差集清理把整个库的记录删光）；无 schema 变更（不涉 migration）。

## 决策（Decision）

1. **触发点**：`Scanner.Scan` 与 `Scanner.Watch` 开始时发现 `RootPath` stat 出 `fs.ErrNotExist`（scanner/internal/scanner/relink.go `ensureLibraryRoot`）。
2. **样本**：经 sqlc 新查询 `ListLibraryRelinkSamples`（queries/scanner.sql）取库内**最小的 5 条**资产（rel_path+size_bytes，常量 `relinkSampleCount`）——小文件 stat 最快、内容通常最独特；无样本（空库/从未扫描成功）一律不重挂。
3. **候选**：旧根**父目录**下一层子目录（跳过隐藏/系统/数据目录）；父目录不可枚举直接放弃。
4. **匹配（纯函数）**：`pickRelinkCandidate(samples, candidates)`——每个样本 relPath 在候选下存在**且字节数完全一致**才算命中，全部样本命中该候选才合格；**恰有 1 个合格候选**才重挂，0 个或 ≥2 个保持既有失败行为并 WARN 列出候选数。不做 IO，行为由 relink_test.go 表驱动用例锁定。
5. **重挂动作**：复用 `UpdateLibrary`（name+root_path 整体更新；该查询目前唯一生产调用方就是本重挂流程）写库；**display name 跟随新目录 basename**（用户拍板：显示名跟随目录名；协议现状无 PUT /libraries，用户本无处自定义库名，不构成覆盖）；INFO 日志含旧/新路径；发一条 `library.changed`（零计数载荷，协议允许的广播型触发帧）——SseBridge 收到即失效 LIBRARIES_QUERY_KEY 等根键，三端拉取即见新根新名。
6. **刻意不做**：不递归搜索旧根上层（组合爆炸且误挂风险陡增）；不按 mtime 比对（改名不改 mtime，size 已足够，且 Windows 拷贝会变 mtime）；不做协议改动（纯服务端内部行为，openapi.yaml 不动）。

## 状态（Status）

Accepted（2026-09-28）

## 后果（Consequences）

- **积极**：改名/移动库根后最迟下一轮轮询（5min）自动恢复，资产 id/收藏/历史/统计全保留（rel_path 不变，size+mtime 全命中 → 扫描零扰动）；三端经 SSE 即时感知。
- **风险与回滚**：父目录下存在结构完全一致的兄弟副本（如备份拷贝）时合格候选 ≥2 → 放弃重挂，保持原报错（fail-safe，无静默错挂路径）；误挂的理论残余风险是"恰有唯一一个含全部样本同字节数文件的目录"，5 条最小文件样本 + 唯一性门槛 + WARN 留痕把概率压到可忽略。回滚 = 移除 Scan/Watch 的 `ensureLibraryRoot` 调用点即可，DB 无迁移无脏状态。
- **并发**：Scan 侧调用点在 beginScan CAS 闸之后，同库无并发重挂；Watch 启动期调用点不持闸，理论上可与轮询 Scan 同时发现根丢失而双写——两侧对同一文件系统独立探测、写同一组值，`UpdateLibrary` 单行 UPDATE 幂等，后果良性（Watch 尚未接线，见已知限制）。
- **已知限制**：Watch 运行中途库根被改名——轮询 Scan 会重挂并正常扫描，但已运行的 watcher 实例仍持旧根句柄（新树增量事件收不到，直到服务重启/重新接线）；Watch 当前尚未在 main 接线（M2 待办），接线时需一并处理。
- **联动文件**：`server/internal/scanner/relink.go`（纯函数+IO）、`relink_test.go`、`scanner.go`（Scan 调用点）、`watch.go`（Watch 调用点）、`server/internal/store/queries/scanner.sql` + `internal/store/db/scanner.sql.go`（新查询，sqlc v1.31.1 生成）、复用 `internal/store/db/libraries.sql.go` 的 `UpdateLibrary`；事件消费 `web/src/components/layout/SseBridge.tsx`（零改动，已有 library.changed 处理）。
