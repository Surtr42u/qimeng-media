# ADR-0056 独立 AI 接入平台架构

- 状态：已接受（2026-11-07，用户下发统一任务书 V2 并授权执行）
- 影响范围：`tools/ai_maintenance/`、`server/internal/maintenance`（worker）、两代备份布局、`api/openapi.yaml` 的 AI 相关使用方式、文档入口
- 关联：ADR-[0051](0051-外部AI维护与标签隐私.md)、[0052](0052-外部AI维护需求修订.md)、[0053](0053-研究流水线API集成.md)、[0054](0054-持久维护任务队列.md)、[0055](0055-手机无前台维护结果包协议.md)；现行执行清单见[统一任务书 V2](../AI_PLATFORM_TASKBOOK.md)

## 背景

用户 2026-11-07 下发《外部 AI 接入平台与维护系统统一任务书 V2》，要求把外部 AI（Codex、其他工具型 AI、未来模型或本地模型）的接入能力从三端客户端中独立出来：一套可独立维护升级的 AI 工具平台，对外提供统一工具调用，对内复用现有 Go 业务 API 完成查询与受控写入。

此前已确认的需求继续有效：作者资料维护、混合媒体整理、备份、持久后台任务、手机无前台同步（ADR-0051/0052），作者合并端点、维护任务账本、设备结果包 API、规则包与只读 CLI 已经落地。本轮要解决的是**架构分层与执行面缺口**，不是重写项目。

## 决策

### 1. 两层接口独立，业务只保留一套

- **AI 工具接口**（面向外部 AI）拥有自己的工具名、参数结构、工作流、版本与发布节奏，由独立工具包提供；支持 CLI，MCP stdio 为第二入口，远程 HTTP 只在出现真实远程客户端/NAS 执行器需求时另行实现且使用独立契约与版本。
- **业务 API**（`/api/v1`，[OpenAPI](../../api/openapi.yaml) 为权威）继续面向 Web/Windows/Android 与 AI 适配器。不得为了调整 AI 工具名称或研究流程频繁修改主协议；AI 工具层只做适配、计划编排、安全控制与结果核验。
- **两层不是两套后端**：作者、媒体、文件、备份等业务规则必须复用 Go 领域服务；AI 工具层禁止直写 SQLite/TXT 或建立第二份业务事实。
- 新增 AI 工具原则上不修改 Web/Windows/Android 客户端；客户端也不强制经过 AI 平台。

### 2. 工具核心形态（Python，标准库）

- 平台放在 `tools/ai_maintenance/`，仅用 Python 3.13 标准库，可独立启动、查询版本/能力、健康检查；不引入大型框架与第三方 YAML 依赖。
- **显式工具注册表**：每个工具声明稳定 ID、工具版本、描述、输入/输出 Schema、所需业务 API 能力、权限类型、只读/副作用/需确认、超时与资源预算、错误码与恢复建议、实现状态；可列举、可独立禁用；新增工具只增模块与注册条目，不修改统一入口的条件分支。
- 允许的模块拆分按真实职责（context/rules、registry、client、plans、execution、security、adapters、reports），不建空目录。不实现「上传任意 Python 文件即执行」的通用插件系统；可执行工具由可信发布流程安装并做输入校验。
- 运行中重新加载规则必须先校验 Schema/版本/完整性再原子切换，执行中任务保持原规则快照；普通工具调用不得修改权限规则或执行代码。

### 3. 版本分离与能力核对

- 至少分别维护：AI 平台版本（`platformVersion`）、工具契约版本（`toolContractVersion`）、规则包版本（`rulesVersion`/`rulepackVersion`）、主 API 来源指纹（`openapiSha256`，仅作来源与构建追踪）、目标服务实例与数据修订、长期任务的计划版本。
- 连接时先获取能力上下文；每个工具按自己声明的**端点、方法、必需字段与业务能力**独立核对。OpenAPI 中「存在某路径」不等于工具可用；未通过核对的工具标记 unavailable/incompatible，禁止 AI 猜测旧参数继续执行。
- 主 OpenAPI 任意字节变化不得导致全部 AI 工具无条件失效；无关字段变化只让实际依赖它的工具降级。
- OpenAPI 解析采用分块、可测试、行为被合成 fixture 锁定的实现，不再扩大整文件字符串行匹配；不因新增第三方解析库引入版本漂移。
- 需要新增 Go 业务能力时，先审查现有领域服务可复用性；确需改协议仍走「OpenAPI → `make sdk` → 同批 `api/sdk.lock`」正式流程。禁止复制数据库写入逻辑绕开主 API 兼容要求。

### 4. 计划与受控写入

- 写入统一流程：**查询现状 → 生成计划 → 检查前置版本/授权 → 确认 → 正式 API 执行 → 回读 → 记录结果**；prepare 与 apply 分离，计划绑定指纹、前置 revision、幂等键与可恢复步骤。
- 计划必须包含目标实例/库/对象、变更字段、影响数量、旧值与新值、证据来源、计划指纹、权限与确认要求、执行后预期结果；高风险操作（合并、删除、批量改名、媒体整理）不得省略影响预览。
- 作者链优先复用既有原子合并端点与档案 revision 语义；人工修改/人工清空字段优先保护；COS 体系隔离；失败保留已执行步骤记录，409 不静默覆盖。

### 5. 凭据与权限

- AI 模型不直接持有 Go 管理员 Token，不获得任意 shell 或数据库写权限；实际凭据由可信本地工具执行器保管，校验模型请求后再操作。日志、报告、任务工件不得包含 token/密钥/完整备份。
- 权限类型至少区分：只读查询、研究辅助、作者资料写入、媒体整理、高风险维护、管理员维护；权限绑定目标实例、目标库、授权目录与操作类型。
- 必须明确：注册表声明权限不等于服务端已强制最小权限。当前主 API 仍是管理员 Bearer；在正式开放 AI 写入生产前，另行评审受限凭据或由可信执行器实施不可绕过的隔离。管理员专用工具（数据库审计、迁移、备份恢复、环境诊断）保持独立管理，不默认对 AI 开放。
- 真实库 8420 禁止测试写入；测试只用隔离实例、临时数据与合成媒体。

### 6. 后台任务复用唯一账本

- 继续使用 `server/internal/maintenance` + migration 0023 + `/api/v1/maintenance/jobs`，**不新增第二套任务状态数据库**；任务记录输入指纹、规则版本、授权、步骤/工件、预算与失败恢复信息。
- Go 内部 Worker 只处理本进程已注册 handler 的 kind（首个真实 handler 为 `backup_export`），通过租约领取/心跳/完成，逐步骤记录、暂停/取消可恢复、重启后从已完成步骤续跑且不重复副作用；无 handler 的 kind（如 `asset_research`/`author_cleanup`/`custom`）保持 queued，供未来外部 AI 执行器。
- 外部执行器没有现成领取接口：在定稿「可信领取/续租/完成」协议前，不向普通客户端开放不受控执行端点，也不允许外部工具直接写任务表。可采用内部 Worker 桥接或受限 Worker 通道。
- 同一幂等键重复提交必须比较载荷指纹：相同才视为重放，不同返回 409，避免同键不同任务被误认为成功。

### 7. 跨设备同步

- 继续复用已实现的设备结果包 API、migration 0024 与 `deviceapply` 包，不重建第二套协议。
- 手机流程固定：充电+Wi-Fi 下主动拉取 → **先导出本地完整备份（失败即中止）** → 校验目标设备/协议/规则指纹/段摘要 → 按既有业务导入流程应用 → 回读 → 回传结果 → 清理临时包并保留两代备份。
- `targetDeviceId` 目前只是不透明标签，不是身份认证。真实跨设备自动应用前必须实现有效设备绑定与权限验证；在此之前不把真机后台自动应用写成已具备。手机不新增入站监听端口、不依赖 USB、不强制前台。
- 目前手机内嵌 Go 服务端继续保留，不因 NAS 规划提前移除。

### 8. 两代备份布局

- 维护目录采用「当前 / 上次」两个独立代目录，各自含作者资料与完整 v2 备份及独立摘要；TXT 不能替代完整备份。
- 本轮不修改主 OpenAPI：服务端 mirror 以**已配置 path 的目录命名约定**推导上一代路径（祖先目录段为 `当前`/`current` → 同根兄弟 `上次`/`previous`），推导失败或越界时保持旧 flat3 三代语义并保留回退路径；客户端（Web/Android）使用同一约定。将来若需显式布局字段，按协议流程另立变更。
- 旧布局迁移必须先只读核对（可读性与摘要复算）再复制生成新布局，保留旧文件与回退路径；没有用户授权不得删除历史文件。

### 9. 外部研究与联网边界

- 外部 AI 优先使用自身已获授权的搜索、浏览器、反向识图、帧分析与平台公开资料查询，并记录证据/日期/出处/可信度；再通过受控业务工具写入。
- 现有 Go 研究 provider/Lens 网关保留为可选能力且默认关闭；不为 Fake-IP 放行地址段，不为打通平台放宽 SSRF，不新增默认自动外网抓取服务；Lens sidecar 未使用时不自动运行。该边界只针对研究网关，不误停其他经独立授权的功能。
- AI 没有联网/识图能力时产生待研究事项，不得伪造核验成功；不启动自动作者新作抓取。

### 10. 文档与状态口径

- [统一任务书 V2](../AI_PLATFORM_TASKBOOK.md) 为现行执行清单；原 [外部 AI 维护任务书](../AI_MAINTENANCE_TASKBOOK.md) 与 [P0 底稿](../AI_MAINTENANCE_P0.md) 标记为历史需求与设计来源，保留完整内容供追溯，不再作为并行执行清单。
- 已合并源码、CI 通过、已构建、已安装与真实功能验收是五种不同状态，分别记录；不得把文档完成或测试通过写成设备已升级。实施状态以 [HANDOVER](../HANDOVER.md) 与 [CAPABILITY_MAP](../CAPABILITY_MAP.md) 为准。
- 涉及原用户明确决定的业务规则（作者身份与人工字段保护、TXT 真相、v2 备份语义、标签明文、研究默认关闭、双端独立运行）不得借架构重构修改。

## 被否方案

| 方案 | 否决原因 |
|---|---|
| 把所有旧脚本复制进新平台 | 复制会保留多份业务规则与写入算法，违反「唯一权威实现」；旧脚本按 R0 审计结果封装/合并/隔离/退役 |
| AI 直连 SQLite 或直写 TXT/媒体目录 | 绕过领域服务、鉴权与文件流程，形成第二真相；本地只读审计仅限授权的管理员工具 |
| 为 AI 工具名称/研究流程频繁修改主 OpenAPI 与三端 SDK | 把 AI 层演进成本转嫁给三端，违反两层接口独立目标 |
| 为 AI 平台新增第二套任务账本/设备结果包协议 | 双状态源导致恢复、幂等与跨端语义分裂；已有账本与协议可复用 |
| 重建 Go 后端或推倒现有业务逻辑 | 现有业务核心已多轮验证；本轮只补 AI 接入层与明确缺口 |
| 第一版就做 HTTP 服务、容器化、多 Worker 或通用插件市场 | 无真实远程调用方/规模证据；先 CLI + MCP stdio，按需求扩展 |
| 在环境无法运行 SDK 生成链时手改生成物或 `api/sdk.lock` | 违反 ADR-0009；本轮两代布局因此改用无协议变更的路径约定方案 |

## 后果

- AI 工具契约可独立演进，新增普通工具不再触碰 Go 主协议与三端；主 API 无关字段变化只影响实际依赖该字段的工具。
- 业务写入仍集中在唯一 Go 领域服务；审计、计划、确认、回读与幂等由 AI 工具层强制，降低外部模型误写风险。
- 后台任务与跨端同步沿用既有账本/协议，恢复语义与兼容边界继续由 ADR-0054/0055 约束；外部执行器接入协议仍需后续定稿。
- 两代布局通过路径约定落地，代价是配置必须遵循目录命名；旧 flat3 保留回退，将来可另行升级为显式协议字段。
- 服务端最小权限、Android 配对/后台 Worker 与 NAS 执行器仍是后续阶段事项；在取得真实设备/硬件证据前，文档只能记录为未实现或未验收。
## 2026-11-07 补充：工具目录、按需加载与权限分离（扩展性增量）

用户追加长期扩展性要求，在不推翻既有工具注册表/规则包/CLI/MCP 的前提下做最小增量：

- **精简领域目录**：新增 platform.catalog 元工具，按 author/media/research/backup/device/maintenance/system 分组返回工具 id/版本/摘要/状态/权限，不含输入输出 Schema；CLI `catalog` 与 `tools list --compact/--domain` 同源。
- **按需 Schema 与规则**：platform.tool.describe 返回单个工具完整 Schema、示例、规则引用摘录与 Go API 能力依赖；platform.rules 按节/领域返回有界规则节，不把完整 rules.json 一次性交付模型。
- **惰性模块加载**：注册表只保存 module:handler 引用，目录/状态计算不导入实现模块；首次执行或描述时才导入 tools_*.py / media_naming.py；实现模块缺失时工具状态 unavailable、执行返回 TOOL_NOT_IMPLEMENTED，不假装成功。
- **权限与发现分离**：catalog/describe 只声明权限；execution 在 Schema/计划/远程请求前按 QIMENG_AI_GRANTED_PERMISSIONS（或 rules.json toolConfig.grantedPermissions）强制拒绝（PERMISSION_DENIED）。未配置默认授予全部已声明权限仅为兼容旧 CLI；生产执行器应显式收窄。
- **MCP 兼容**：标准 tools/list 仍返回完整清单与 Schema（不因目录功能裁剪协议能力）；元工具作为符合协议的分类发现入口，descriptor 提供 _meta.domain 便于分组。
- **废弃工具**：声明 deprecated/replacedBy，精简目录默认隐藏，执行返回 TOOL_DEPRECATED。
- **管理员 Bearer 绕过风险（结论）**：工具层隐藏 token 只能约束经工具的调用，不能阻止模型直接访问 /api/v1；正式开放 AI 写入前必须实现受限凭据或不可绕过的执行端隔离。本轮把风险写入规则与 README，未假装已解决。
- **测试**：新增 tools/test_ai_catalog.py 18 项与既有 205 项 tools 测试，覆盖大量工具注册（120 个合成）、模块缺失、规则版本变化、并发、废弃/禁用、权限拒绝、CLI/MCP 一致性。仅改 tools/ai_maintenance/ 与文档，不改 Go /api/v1 / OpenAPI / schema / 三端。

## 2026-11-10 补充：本地文件引用与原语执行契约（定向优化）

用户要求在不推翻现有架构（独立 Python 平台、Go 正式业务 API、CLI/MCP、统一注册表、惰性加载、按需上下文、规则包、recipe、本地原语、计划/确认/回读）的前提下，修复本地执行权限与路径授权缺口，并降低 AI 查找文件的调用次数、上下文体积与绝对路径暴露。本轮只做定向增量，不新建第二套业务实现、数据库、搜索框架或远程服务。

### 1. 未入库文件与已入库资产的边界

| 对象 | 允许路径 | 禁止 |
|---|---|---|
| 未入库文件（下载/待整理） | 可信执行端在显式授权目录内直接搜索、哈希、抽帧、拼图、复制、命名整理 | 绕过授权根、删除源文件、默认覆盖、写入源码树 |
| 已入库资产（索引/作者/标签/业务关联/正式媒体路径） | 现有 Go `/api/v1` 正式业务 API（计划→确认→执行→回读） | 本地工具直接写 SQLite/TXT、直接改库内文件或创建第二份业务事实 |

统一的是能力、规则与执行规范，不是要求所有文件操作经过 Go HTTP；本地原语继续由可信执行器直接完成，但不得修改已入库资产的业务状态。

### 2. 授权根分离与路径安全

- 新增 `QIMENG_AI_READ_ROOTS` 与 `QIMENG_AI_WRITE_ROOTS`（逗号/分号分隔绝对路径）；`QIMENG_AI_MEDIA_ROOTS` 继续作为媒体只读扫描根并计入读根；被 Git 忽略的工作根、`.test-temp/` 与 `build/` 始终可读写。
- 未显式授权的目录默认拒绝；模型传参不能扩大授权。读取根与写入根分别校验，写操作不能借读根落盘。
- 仓库内路径仍只允许忽略工作根；`..` 逃逸、控制字符、相对路径与越界链接一律拒绝。授权根本身允许是用户配置的符号链接/junction（配置解析时规范化）；根以下的写目标与父段不得是符号链接/junction/reparse point，读路径解析后必须仍在真实根内。
- 默认拒绝覆盖已有文件、默认不删除源文件；复制后回读目标大小与 SHA-256，并在写后重新校验目标仍在授权写根内。
- 失败返回稳定错误码（`PATH_NOT_AUTHORIZED`/`PATH_UNSAFE` 等），消息不回显用户绝对路径。

### 3. 逻辑存储与 fileRef

- `QIMENG_AI_STORAGES` 以 `storageId=绝对根` 声明可信逻辑存储；storageId 只由配置产生，AI 不能通过参数新增授权目录。
- 新增只读发现工具 `files.storages` 与 `files.search`：返回有界候选（默认 20、上限 50，扫描条目硬上限 20000，可翻页），只给 `fileRef`、`storageId`、相对路径、名称、类型、大小与修改时间，不返回整棵目录树或物理绝对路径；符号链接/junction 与隐藏项默认跳过。
- `fileRef` 自描述且无落盘索引：编码 storageId、相对路径、size 与 mtime；执行器解析时重新校验 storage 配置、相对路径规范化、根内约束、存在性与 size/mtime。文件删除/替换/变化返回 `FILE_REF_STALE`，重新搜索即可；伪造或未配置 storage 返回 `FILE_REF_INVALID`/`FILE_REF_UNAVAILABLE`。
- `fileRef` 与原有 `path` 参数并存：recipe 原语（`media.probe`/`media.fingerprint`/`file.hash`/`media.contact_sheet`/`media.transfer` 源）优先接受 fileRef；现有绝对路径调用保持兼容，不要求一次性迁移。
- 不为 fileRef 复制媒体处理逻辑；扫描、哈希、抽帧、拼图仍调用 `media_scan`/`media_primitives` 唯一实现。

### 4. 原语统一执行契约

- 原语由 `PrimitiveSpec` 声明 id、版本、权限、只读状态、副作用、确认要求、超时与运行检查；`execution.policy_denial` 为工具与原语共用同一套禁用/只读/权限判定。
- 每个有副作用原语在执行前强制检查 `QIMENG_AI_READONLY`、`QIMENG_AI_GRANTED_PERMISSIONS`/`toolConfig.grantedPermissions` 与禁用列表，不依赖模型提示词；`QIMENG_AI_DISABLED_TOOLS` 也可禁用原语 ID。
- 新增权限 `local.files.write`（授权写根内的本地复制/整理/派生图）与 `local.device`（显式真机 adb 推送/拉取），与业务写权限分开；两者都不授予修改已入库资产业务状态的权力。
- 原语确认与 recipe 门禁绑定：`media.contact_sheet` 为派生只读产物不需确认；`media.transfer`/`device.push`/`device.pull` 必须已通过本次运行的人工门禁。

### 5. Recipe 可靠性

- 恢复执行时校验每个已完成步骤产物的存在、字节数与 SHA-256；不符返回 `RECIPE_ARTIFACT_TAMPERED`，不继续后续写入。
- 恢复时若发现上次崩溃在副作用步骤（`status=running`），停止并返回 `RECIPE_STEP_UNCERTAIN`，要求回读/人工核对后新建运行；只读步骤可安全重跑。
- 新建运行记录各工具步骤版本；恢复时待执行工具版本变化返回 `RECIPE_STATE_VERSION`。recipe 版本/输入变化继续拒绝续跑。
- `media.transfer` 仅在恢复上下文对“目标已存在且 SHA-256 相同”做幂等复用；内容不同仍 `TARGET_EXISTS`，默认不覆盖、不删源。复制使用排他创建避免检查后覆盖竞态。

### 6. 工具发现、状态与规则

- MCP `QIMENG_AI_MCP_DOMAINS` 过滤业务工具时，始终保留安全发现元工具（`platform.*` 与 `files.storages`），`tools/list` 与 `tools/call` 使用同一可见集合；不扩大执行权限。标准 MCP 客户端仍可能加载完整 `tools/list`，过滤只减少暴露面，不作为上下文节省承诺。
- `platform.rules` 支持有界点路径（最多 4 段，拒绝空段/`.`/`..`/数组下标），截断结果必须显式标记；不能把截断预览当完整关键规则。
- 工具状态拆分为 registered / implemented / contract / runtime / locallyAuthorized / serverVerified，不再把所有维度混为一个 `supported`；`serverVerified` 本地恒为 false，服务端 scope 仍由 Go 强制。
- `rulepack.consistency_problems()` 自动检查规则引用、示例 Schema、playbook 引用、领域规则节、recipe 权限覆盖与版本一致性；不新增第二套规则源。
- 版本：本轮工具契约新增工具 ID/输入字段/权限/错误码，`platformVersion`/`toolContractVersion` 升 `1.4.0`，`rulepackVersion` 升 `2026-11-10.3`。

### 2026-11-10 合并前安全修复（PR #53）

代码审查发现本地执行/Recipe 的失败与覆盖路径存在数据风险，按最小改动修复，不改变架构：

- **partial/failed 不再记为成功**：工具与原语结果统一在 recipe 循环检查；`partial`/`failed` 写入 artifact（保留成功/失败项）后停止后续步骤。恢复时只重跑非 ok 步骤；transfer 对已成功且内容一致的目标按 `alreadyPresent` 跳过，只重试失败项。执行前被策略拒绝的步骤标为 failed 而非不确定，handler 内部中断仍为 `RECIPE_STEP_UNCERTAIN`。
- **覆盖安全**：`media.transfer` 在任何写入前用 `os.path.samefile`/`dev+ino` 拒绝源目标同路径、硬链接或同一底层文件（`overwrite=true` 不能绕过）。覆盖改为同目录临时文件 + size/SHA-256 校验 + `os.replace`；失败保留旧目标并清理临时文件。无覆盖发布优先硬链接，文件系统不支持时退回排他占位 + 原子替换。
- **ADB 拉取**：`device.pull` 默认拒绝已有本地目标；拉取到临时文件、核对大小后安全发布；失败/链接/未授权根不破坏旧文件。仍强制显式 `QIMENG_ADB_SERIAL`，并拒绝默认模拟器。
- **只读声明一致**：`media.probe` 仅在含 `frames` 时提升为 `local.files.write` 条件副作用；纯元数据查询仍只读。只读模式关闭媒体缓存写入（probe/fingerprint/scan），避免“声明只读、实际写盘”。
- **Gate 范围**：Gate 只授权其后的具体步骤（显式 `authorizes`，否则到下一道 gate 之前）；恢复核对记录范围，范围变化拒绝续跑；条件跳过的 gate 沿用此前已完成 gate 的授权以保持既有 recipe 流程；一次 `--yes` 仍只通过一个门禁。
- **版本**：`platformVersion` 1.4.1、`rulepackVersion` 2026-11-10.4；`media.probe`/`media.transfer` 原语版本 1.1.0、`ADB_PRIMITIVE_VERSION` 1.1.0、`RECIPE_ENGINE_VERSION` 1.1.0。旧运行中的旧原语版本会被拒绝续跑。
- **残余竞态**：普通路径检查与 `os.replace` 之间仍有极短窗口；覆盖前的临时文件校验消除了“校验失败破坏旧目标”，但无法声称完全消除跨进程 TOCTOU。ffprobe/ffmpeg 读取源文件的换链窗口仍未消除。

### 后果与未做

- 未入库文件仍可高效本地处理，但必须由可信执行端显式授权目录；用户配置的下载目录可直接使用，未配置目录默认拒绝。
- AI 通过 storageId + fileRef 复用已定位文件，减少重复列目录与长绝对路径参数；物理路径与目录树留在执行端。
- 已入库媒体/作者/标签/业务关联仍只走 Go 正式 API，未新增第二套业务实现或数据库。
- 不新增全盘搜索框架、常驻服务、HTTP 服务、shell/Python 任意执行或通用插件系统；真实媒体、8420 真库与真机仍未用于本轮的破坏性验证。
