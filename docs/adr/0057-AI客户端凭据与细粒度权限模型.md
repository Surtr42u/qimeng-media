# ADR-0057 AI 客户端凭据与 Go 细粒度权限模型

- 状态：已接受（2026-11-07 用户追加长期架构要求；本文记录**方案决策**，实现按阶段推进，当前 PR 只收尾现有代码与测试）
- 影响范围：Go 鉴权/权限、新的只增 migration 与 OpenAPI 管理端点、AI 客户端凭据、审计、外部执行器协议；AI 工具层不复制领域逻辑
- 关联：[ADR-0056](0056-独立AI接入平台架构.md)、[ADR-0021](0021-多设备并发会话token模型.md)、[ADR-0054](0054-持久维护任务队列.md)、[ADR-0055](0055-手机无前台维护结果包协议.md)；方案全文见 [Go API 缺口与 AI 客户端权限模型](../AI_PLATFORM_API_GAPS.md)

## 背景

用户 2026-11-07 补充长期架构要求：不是限制可信 AI，而是让 AI 能自由调用、组合、调度现有业务能力；同时 Go 侧提供完整、稳定、可组合的基础操作，并真正强制执行细粒度权限。当前主 API 只有管理员 Bearer/用户会话，AI 执行器若长期持有全局管理员 token，无法最小授权、按工具限制、按实例撤销或审计归属；高风险操作（删除/不可逆覆盖/恢复）与低风险操作（资料补全、媒体关联、命名整理）也没有服务端区分。

现有作者、媒体、文件、备份、维护账本与设备结果包 API 已覆盖基础操作（见方案 §2），主要缺口集中在身份/权限/审计与外部执行器通道，而不是“缺少业务接口”。

## 决策

1. **Go 业务 API 作为稳定、可组合的业务底座**：基础操作尽量完整、幂等、可回读；不为 AI 工具分类重写接口，不复制领域逻辑；批量能力只在真实规模/一致性证据下补充，且复用领域服务。
2. **新增独立 AI 客户端凭据**（P1）：`ai_clients` + 可轮换密钥哈希 + scope 集合 + 过期/撤销 + last_used；鉴权身份与用户会话分离，禁止相互升级；密钥只在创建时返回一次明文。
3. **细粒度 scope**（P1）：`read`、`research`、`author.write`、`asset.author.write`、`media.organize`、`backup.export`、`maintenance.read/write` 与高风险 `author.destructive`、`backup.restore`、`admin.*`。低风险写 scope 可在授权范围内自动执行；高风险需独立 scope（P2 再加动作级确认凭据）。
4. **服务端强制**：HTTP 中间件做身份/scope 检查，领域/服务层对高风险动作复查；不依赖 AI 工具层声明或模型自觉；未授权返回稳定 403 错误。AI 工具层只声明能力，不据此放行。
5. **审计与归属**（P1）：写操作按 AI 客户端/动作/目标/结果/请求 ID 记录只增审计，可回读；管理员可创建/撤销/轮换客户端并查询审计。
6. **长任务复用唯一账本**：继续使用 `/api/v1/maintenance/jobs` + Go Worker；外部 AI 执行器通过未来受限领取/续租/完成通道（P2）参与，不建第二套任务状态表。
7. **禁止面**：任意 SQL、无边界文件访问、任意 shell；管理员能力只能经明确管理功能或受限环境；AI 默认不授予恢复/迁移权限。
8. **AI 平台独立升级**：工具发现、按需规则、字段规范、脚本扩展、MCP/CLI 与编排在 `tools/ai_maintenance/` 迭代，版本独立于 Go 主 API；预置工作流是可选模板，AI 可用基础工具自由组合。
9. **NAS 形态**：Go 服务为稳定底座，AI 平台独立部署更新；PC/Android 继续用既有业务 API，不要求手机部署完整 AI 执行器。

## 分阶段实施

| 阶段 | 内容 | 门禁 |
|---|---|---|
| P0（本 PR） | 方案与 ADR 落库；现有工具层扩展性/测试收尾 | 不改 Go/OpenAPI/migration；现有测试与 CI 全绿 |
| P1 | AI 客户端凭据 + scope + 审计 + 限流（G1/G2/G8） | 只增 migration、OpenAPI→SDK→锁、锁定 scope 拒绝/撤销/审计测试；管理员人工验收 |
| P2 | 高风险确认凭据（G3）与外部执行器受控领取（G4） | 幂等/恢复/越权测试；不放宽 SSRF/文件边界；真实任务演练 |
| P3 | 按证据补批量能力（G5）、设备配对（G6） | 真实规模/设备验收；复用领域服务 |
| 未来 | 作品/季/剧集模型（G7）、NAS 常驻执行器 | 独立领域设计与硬件验收 |

## 被否方案

| 方案 | 否决原因 |
|---|---|
| 继续让 AI 持有全局管理员 Bearer | 无法最小授权/撤销/审计；隐藏 token 不等于服务端最小权限 |
| 所有 AI 写入都强制人工逐项确认 | 低风险高频维护不可行；应按 scope 与风险分级，把确认留给高风险动作 |
| 为 AI 便利在 Go 复制数据库写入/批量逻辑 | 破坏唯一业务核心与兼容要求；批量必须复用领域服务 |
| AI 平台自建任务账本或设备协议 | 与既有 maintenance/deviceapply 冲突，恢复/幂等语义分裂 |
| 开放任意 SQL/文件/shell 或默认管理员工具 | 与安全不变量冲突；特殊管理能力走明确管理功能或受限环境 |
| 立即重构全部接口 | 用户要求先方案、按必要性分阶段，不阻塞现有功能交付 |

## 后果

- 本 PR 不改变 Go 行为，现有安装与三端不受影响；AI 工具层凭据仍须保存在可信执行端，管理员 Bearer 不是长期授权方式（风险已在 README/rules/ADR-0056 记录）。
- P1 起新增只增表/端点与鉴权分支，需要同步 OpenAPI→SDK→锁、迁移纪律、安全专题与审计查询；每阶段独立 PR 与回退说明。
- 低风险自动化与高风险单独授权分离后，可信 AI 可在授权范围内自由组合基础工具，同时保留用户可撤销与可审计的边界。
