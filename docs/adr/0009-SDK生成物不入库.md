# ADR-0009：SDK 生成物不入库，CI 从协议重建（防漂移结构）

## 背景（Context）

三端客户端 SDK 全部由 `api/openapi.yaml`（协议宪法）自动生成：Go 接口层（oapi-codegen → `server/internal/httpapi/gen/`）、TS 客户端（@hey-api/openapi-ts → `web/src/api/generated/`）、Kotlin 客户端（openapi-generator → `android/sdk/`）。

本项目 100% AI 生成、协议先行是铁律（ADR-0001）。如果生成物入库并被 AI「顺手修一下让编译过」，漂移就开始了：协议与实现各说各话，openapi.yaml 作为唯一事实源的根基被架空。靠 AI 自觉不手改是不可靠的——防漂移必须靠**结构**，而不是纪律宣示。

## 决策（Decision）

1. **生成物一律不入库**：`server/internal/httpapi/gen/*.gen.go`、`web/src/api/generated/`、`android/sdk/**` 全部 .gitignore；生成器的**配置文件**（oapi-codegen.yaml / openapi-ts.config.ts 等）照常入库。
2. **CI 重建链作结构性门禁**：`sdk-chain` job 每次 push/PR 执行 `make sdk`，从 openapi.yaml 现场重建三端并验证可生成/可编译（ci.yml）。
3. **AI 行为约束**：**禁止手改任何生成物**（`*.gen.go`、`*.gen.ts`、`android/sdk/**`）。协议改动 = 改 openapi.yaml → `make sdk` → 按编译错误适配各端实现代码。

## 状态（Status）

Accepted（2026-08-26，落地即生效；已在 .gitignore 与 ci.yml 中实现）

## 后果（Consequences）

- **积极**：三端一致性由重建链保证，任何时刻 `make sdk` 产物即协议真相；协议改动单点（openapi.yaml），杜绝多端漂移。
- **积极**：仓库干净，diff 只含手写代码与生成器配置，review 噪音骤减。
- **代价**：首次 clone 后必须先 `make sdk` 才能编译各端（CI 已自动处理；本机由 Makefile 目标自动触发安装/生成）。
- **约束**：AI 在"生成物报错"时唯一合法出路是改协议或改生成器配置，禁止就地改生成文件止血。违反此条 = 事故（AGENTS 铁律）。
