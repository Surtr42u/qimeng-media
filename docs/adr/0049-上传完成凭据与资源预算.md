# ADR-0049：上传完成凭据与资源预算

- 状态：已接受（2026-10-23，源码已实现；用户本轮恢复云端验证/构建与双端更新，结果见 HANDOVER）

## 决策

直传与分片创建接受可选客户端 uploadId（UUID），任务重试保持不变。分片未完成部分仍采用 ADR-0028 的内存会话/重启失效机制；完成凭据通过新增 migration 0020 与资产行同一 SQLite 事务保存。完成后七天内，相同任务与参数重试返回原资产；参数不同拒绝 409；原资产已删除拒绝 410，不能因重试复活。不以文件名或内容相同推断同一任务。旧客户端无 uploadId 的直传保持旧行为；既有分片 sessionId 同样获得完成结果重放。期限后不再承诺去重；文件发布后、数据库提交前的中断仍保留原件供重扫，不声称文件系统与数据库跨资源原子提交。

可选 sourceMtime 采用 Unix 毫秒，只表示源文件系统修改时间；缺失继续使用接收时间，addedAt 保持入库时间。两条上传路径在发布前应用并以落盘事实入库，不改变评分公式或拍摄时间语义。

会话数量和声明字节总预算限制在途分片，目录/磁盘检查在上传前和 readyz 执行；healthz 仍只检查进程存活。错误响应脱敏，预检不保证外部进程不会随后占满磁盘，流写错误仍由原失败处理兜底。

Android 用户取消持久化后才显示取消成功，Worker 发送前恢复取消集合；取消完成继续用 success 载荷避免串行链级联。SSE 读空闲超时采用服务端 15 秒心跳的多个周期，注释心跳字节亦续期，沿用现有退避与重连失效机制。

## 选型与验证

复用 SQLite/sqlc、DataStore、OkHttp，不加运行时依赖。上一轮用户取消测试，代码仅完成必要生成；本轮用户明确恢复现有云端完整门禁、构建与 PC/手机更新，补上传重放/事务/预算/取消恢复回归，不引入 Playwright。最终验证与部署证据见 HANDOVER；设备/NAS 验收不能由云端测试代替。归档副本释放属于客户端后处理，规则见领域 files，不属于服务端完成事务。
