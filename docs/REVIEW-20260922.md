## 2. 必须重视（上线/长期使用前）

### 2.1 免密通道是最大安全开口

**位置**：
- `启动服务端.bat` / `启动服务端-无浏览器.bat`
- `deploy/termux/qimeng-start.sh`
- `android/core/data/.../EmbeddedServerConfig.kt`

**现象**：上述入口默认 `QIMENG_AUTH_DEV_MODE=1`。文档约定是“项目未完成前免密”，但 M6 已收官，日常使用仍在免密。

**风险**：
1. 监听若为 `0.0.0.0`（曾为手机连 8420 改过），局域网内任何人可免密进库。
2. 内嵌形态 B 在 `127.0.0.1:18430` 免密 + App 持 `MANAGE_EXTERNAL_STORAGE`，同机恶意 App 理论上可读库（SECURITY 已记档，缓解未做）。
3. 管理密码曾明文写在交接文档——**已从 `HANDOVER.md` 移除**（测试夹具仍有常量）；仍建议换强密码。

**建议**：
1. 日常/生产立刻关闭 dev 模式，仅本地调试临时开启。
2. 内嵌形态补“共享密钥校验”（SECURITY 规划项，T7 后应立项）。
3. 换强管理密码（交接文档已抹掉，测试常量可留）。

### 2.2 回收站只标“30 天”，不会自动清

**位置**：`docs/SECURITY.md`、`server/internal/filing`（`TrashExpired` 无调用方）

**现象**：列表按 30 天展示到期时间，但到期后不会物理清除；配置项也无“保留天数”。

**建议**：补 config 键 + 后台巡检；或至少维护页加“手动清理过期”。

### 2.3 删除资产不清缩略图 → 孤儿堆积

**位置**：`server/internal/thumbnail`（cachekey 自述“孤儿由后续对账任务清理”未实现）、`server/internal/httpapi/trash.go`

**现象**：任务 S 实测 870 个死缩略图（约 12%）。用户手工处理过一次，**根因未修**（删资产只动 DB + 进回收站，不扫 thumbs）。

**建议**：删库行/删资产时联动删缩略图，或加对账清理任务。

### 2.4 `sourcematcher` 的 `"SC"` 别名误伤截图

**位置**：`server/internal/sourcematcher` 内置表「星际争霸」条目

**现象**：大小写不敏感前缀匹配使所有 `Screenshot_*.jpg` 误归出处「星际争霸」。用户 2026-09-22 拍板暂不修，但手机截图是最大受害场景。

**建议**：真机部署后若仍明显，从表数据移除 `"SC"` 别名，连动 matcher 测试 + `DOMAIN_RULES §4` 勘误（成本很低）。

### 2.5 M5 部署闭环 —— **已收官（2026-09-22 用户确认真机 NAS 测试完成）**

| 项 | 状态 |
|---|---|

| buildx **arm64** 半边 | 移 M7+ 按需储备（实测部署形态 amd64，无 arm64 部署目标） |
| 大库扫描压测 | 不设专项：真机真实库日常使用覆盖常规扫描路径 |
| Dependabot | 未配置（仍为待办） |

## 4. 工程 / 运维债

1. **`启动服务端.bat` 双胞胎未收敛**（AUDIT E2）  
   两脚本重复同一套启动逻辑（含安全敏感的 `QIMENG_AUTH_DEV_MODE` 行），改一处漏一处。建议抽成一个启动脚本，另一脚本只调用。

2. **根 `docker-compose.yml` 与 `deploy/docker-compose.yml` 并存**  
   根里那份仍是“架构约定目标形态”注释，易误导。建议根文件改成指针注释或删除，只留 `deploy/`。

3. **工作区噪音**  
   根下 `.mimosa/`、`仓库清理暂存-20260921/`、`旧版UI实录/`、26MB 终包 APK；`android/**/build/` 大量构建产物。建议定期外移/归档；**真实库数据与密码不要留在交接文档**。

4. **HANDOVER.md 信息密度过高**  
   文头 2000+ 字、历史批次堆在待办节。建议拆成 `HANDOVER_CURRENT.md`（现状+待办）与 `HANDOVER_HISTORY.md`。

5. **本机硬件不稳**（HANDOVER 2026-09-16 记档）  
   周内 9 次 WHEA 致命断电。构建/大库扫描前先排 BIOS/电源，否则压测会假红。

## 7. 总评

协议先行、迁移只加不改、UI 与逻辑解耦、ADR/CHANGELOG 署名齐全——这套纪律对“AI 生成、无编程基础维护”的项目是有效的质量防线。

当前主要风险不在代码正确性，而在：

1. **安全默认值太松**（免密 + 局域网监听）
2. **磁盘生命周期缺口**（缩略图/回收站）
3. **部署半成品**（arm64 / 压测 / 依赖巡检）
4. **文档体积过大 + 过时待办未清**（交接成本高，易误导；上传/查看器/批次导航误报即一例——已于 2026-09-22 修正 HANDOVER/HANDOVER_UI）

## 复核后记（2026-09-22 二次会话执行记录）

用户完成真机 NAS 测试后触发的复查批，本报告 Top5 中 3 项当日清偿，全部带测试与文档同步：

1. **磁盘生命周期（原 §2.2/§2.3，Top5 #2）**：回收站到期自动物理清除落地（`trash.retention_days`/`sweep_interval` 配置 + 后台清扫 `trash_sweeper.go`，trash 列表 ExpiresAt 同源取值）；缩略图删除时机联动清理（`thumbnail.DeleteAssetThumbs`：单条物理删除/清空/到期清扫/删库四入口；软删→恢复不清）。残余缺口=扫描器外部删除路径的孤儿，仍待全量对账任务（DOMAIN_RULES §11 记档）。
2. **安全加固（本次复查新发现，非初稿项）**：Host 校验防 DNS rebinding（默认只放行 IP 直连 + localhost，`trusted_hosts` 配置白名单，SECURITY 新节）；安全响应头补 `X-Frame-Options: DENY`；auth setup 的 argon2 哈希移出写锁（双检锁，保留已初始化快路径 409）。
3. **正确性修复**：listTrash 遍历与并发 RemoveAll 的竞态容忍（Windows 枚举竞态偶发 500，口径对齐 scanner）；缩略图 warmup 投递循环对 ErrPoolClosed 的自旋（停机后 250ms 空转不退出）；config applyEnv 超线函数拆节段。
4. **工程卫生（Top5 #5）**：两份 `启动服务端*.bat` 收敛为 `_server-common.cmd` 单一逻辑源（薄壳包装，行为不变）；根 `docker-compose.yml` 删除（`deploy/` 唯一权威，llms.txt 指针同步）。
5. **文档对齐**：M5 收官七处统一回写；README/ARCHITECTURE 的「docker-build 未实现」过时句修正；OBSERVABILITY 的 `deploy/grafana/` 死路径修正；web 4 处 + android 4 处指向已删文档的注释改自包含。
6. **本轮复核确认为「可接受、不再追」的新增项**：媒体直链 If-None-Match 不支持逗号列表/弱实体形态（仅损失 304 机会，方向安全）；库内 symlink 跟随留白（威胁模型=用户自管库目录）；auth 限速全局窗口无 per-IP（单用户 LAN 场景）。

验证：`go test ./...` 15 包全绿（新增 config/thumbnail/httpapi 共 10 个用例）、golangci-lint 零告警、web build+lint 通过。
