## 1. 用户需求原意与完成目标

用户会从“小红车”等渠道一次下载十几份喜欢的内容，包含图片、视频、动图、COS及图组。用户希望将指定范围交给AI，自动清点、找来源、核对作者和作品、整理命名、补资料、建立关联并执行维护，以减少逐文件操作。这个例子只是入口，还要覆盖后续多批次、历史资料补全、纠错、重复核对及按条件维护。

具体完成目标有以下六项。

1. 混合媒体研究：对授权输入清点文件、识别类型与图组、记录来源证据，区分已核实与候选。
2. 核对作者与作品：查询库内既有身份、别名、作品命名与来源，形成可复核的对应关系。
3. 规范命名：按现有命名与序号规则生成计划，保留原名到入库名的映射，图组与独立作品分别处理。
4. 补档案与关联：补头像、官网/X主页链接、双语简介，按正式接口维护作者档案、来源与作品作者关联。
5. 执行维护：按任务授权完成纠错、归类、重复核对及下文的作者清理。
6. 无前台跨端应用：在手机上不需要打开App前台、不需要USB，由后台任务完成结果应用与回读。

本批新增的作者维护目标：删除作者三清（TXT块、关联与作者行）、改名身份迁移、改挂资产作者、重复作者合并/删除、搁置作者清理。这些动作一律先输出计划与影响数量，经用户或任务授权确认后执行，执行后回读核对。现有删除、改名、改挂、TXT重放与镜像端点可复用；合并语义若现有端点凑不齐，按协议先改 OpenAPI 再生成 SDK，不由客户端拼凑写入。

本批新增的跨端目标：手机本机模式与 PC 8420 是两个独立实例，没有服务端→手机单机库的在线回写通道。手机在充电与Wi-Fi约束下由后台 worker 主动拉取 PC 任务结果包，自动先导出两代备份与摘要，再校验版本/指纹、分段应用主表 TXT 对齐或 v2 导入、回读核对并回传结果。不需要手机前台，也不需要 USB；手机只主动连接电脑，不新增监听面。

明确取消的标签需求：本批不要求 AI 生成或写入标签，也不新增标签隐私增强（加密、代号、密钥及相应迁移全部不做）。标签继续按现行口径明文存储，FTS5、唯一约束、搜索/筛选/排序与关联语义保持不变；标签组改动时间裁决仍属现有迁移语义。任务书不再包含任何标签专项交付物，后续重构只要求不破坏现行标签行为。

用户还要求AI能容易理解项目规则。工具应主动提供头像、链接、简介、双语翻译、作者身份、作品命名、作者清理及关联写入的机器可读说明，连同示例、错误码与恢复方法。新AI接手后应能发现规则、查询现状、生成合法计划并执行，所需规范有固定入口。

任务执行应在后台持续，用户照常操作手机，任务通过服务和正式接口工作。未来媒体长期存放NAS，下载内容可直接送入NAS待整理目录，再由NAS上的执行端调用云端AI完成维护，手机作为浏览与任务控制端。手机的缩略图及播放临时缓存须有明确预算，NAS模式的长期媒体库存归NAS。

当前装机仍为264b9d83、0.2.1/schema22：维护目录三代保留、标签明文、无跨端桥接。本文描述的是待实现目标，不改变现装事实。

## 3. 权威入口与重构不变量

按任务读取以下正文，规则发生变化时同步权威位置。

- [AGENTS](../AGENTS.md)及[协作规范](../AI_README_FIRST.md)负责范围、云端执行和交付门禁。
- [OpenAPI](../api/openapi.yaml)及[API导航](GUIDE_API.md)负责字段、方法、状态码和SDK生成。
- [作者研究指南](../tools/AUTHOR_RESEARCH.md)负责查询、证据、身份及候选认定。
- [媒体复核流程](../tools/MEDIA_RESEARCH_IMPORT.md)负责工作单、命名、正式写入、双端核对与证据留档。
- [作者](domain/authors.md)、[文件](domain/files.md)、[匹配](domain/matching.md)、[标签](domain/engagement.md)、[迁移](domain/migration.md)负责具体领域规则。
- [安全](SECURITY.md)、[架构](ARCHITECTURE.md)、[UI](GUIDE_UI.md)及[内嵌部署](../deploy/embedded/README.md)负责信任边界、分层和后台约束。

重构必须继承以下行为。

1. 正式服务保存业务真相，工具通过现有领域服务及API读写。任务账本保存执行状态和证据索引，作者、标签及关联继续复用业务身份。
2. 作者人工资料、手工清空语义、头像来源绑定、原文与译文、候选状态及版本冲突保护完整保留。
3. 常规作者与COS目录体系分开处理，文件改名、关联、TXT及镜像沿现有一致性维护链执行。
4. 浏览事件身份守恒、标签组时间裁决及现行备份恢复语义继续遵守。任务schema版本独立于当前v2备份版本。
5. 作者主表和完整备份各保留最新与上次两代，每代独立目录（当前/上次）；旧上上次文件在实施时按用户授权清理。
6. 文件原件、并发编辑和跨实例身份受保护。比对使用作品身份、相对路径、大小/摘要及业务内容，并分别记录本机时间、ID和溯源。
7. 手机单机库与 PC 实例相互独立，PC→手机单向应用，导入前必须先导出当前实例；两者都不接受对方在线回写。
8. AI 维护不写标签、不直接写数据库；所有业务写入经正式 API 与领域服务。

## 4. 总体结构与AI实际调用方式

推荐链路为“AI客户端/任务提交端 → 工具适配层 → 持久任务与执行器 → 正式业务API → App/Web”。研究证据与媒体处理由执行器在授权范围内完成。主服务继续遵守模块化单体和ADR-0019的编排边界。

AI工具运行入口可独立部署于PC/NAS，作为本地可信执行端：可只读访问服务端数据目录（qimeng-data，含SQLite/WAL与备份快照），可在用户授权的资料维护目录内读写，业务数据写入一律走正式API（Bearer admin，凭据只放忽略的本地配置）。手机侧不承担工具适配层，只以后台worker拉取结果包并应用。先提供可脚本调用的结构化入口，再以同一套操作能力提供MCP适配。实施时核对当前官方协议与SDK，选定兼容版本并锁定依赖。本机接入使用标准输入输出等适合本机进程的传输，远程接入遵守隧道策略。

### AI客户端接入交付

实现者必须提供可直接照做的接入说明和模板，包含以下内容。

1. 工具如何安装、启动、连接目标影库及检查健康。
2. 支持工具调用的客户端如何登记工具服务、发现工具、读取规则并提交任务。
3. 云端模型API如何由代理运行器调用，如何执行工具调用并将结果交回模型，如何持久化任务。模型连接、工具执行和后台调度各自有明确进程与责任。
4. 客户端暂时缺少工具连接时，如何导出脱敏上下文、接收结构化维护计划，再由可信执行器校验执行。
5. 连接配置只用占位符与环境变量名；真实模型密钥、服务口令、路径与设备信息放忽略的本地配置，不进入任务记录、结果包与日志。
6. 搜索、浏览、反向识图、视觉模型及媒体下载能力逐项声明。任务按实际能力运行，缺少研究工具时输出可继续处理的证据请求或研究包。

## 5. 让AI理解规范的规则包

必须提供一个固定可发现的规则入口，供工具调用和离线交接共同使用。机器可读内容与简明中文指南同批交付，协议字段从OpenAPI/领域验证器生成或核对，规则包带版本和指纹。

规则包与工具契约必须作为发行物的一部分，随服务端或工具适配器自包含交付：AI 运行时不依赖仓库内 AGENTS、任务书、领域文档或历史记录是否存在；仓库文档保留为规则源头、维护依据与排障入口。日常执行只读规则包与示例，仅规则变更、异常排障与交接时按需查专题。规则包指纹与服务端/OpenAPI 版本绑定，升级时同源更新。

规则包至少包含以下内容。

- 当前实例与库类型、支持的动作、字段schema、必填项、枚举、长度/字节预算、分页和冲突码。
- 作者、作品、作品作者关联、来源词与时间轴标签之间的区别与身份来源；标签提供只读说明，不提供标签写入动作。
- 工作流顺序，以及来源不足、缺头像、译文缺省、文件歧义和并发更新的处理。
- 每个写入动作的最小合法示例、成功回读示例、常见拒绝示例和恢复方法，使用合成数据。
- 内容来源、证据引用、候选与已核实的区别，哪些字段可补缺、哪些需要明确修改意图。
- 作者清理动作的候选口径、影响数量、计划指纹、确认与回读方式，以及与人工删除/改名的边界。
- 规则更新与能力变化检测。执行前发现协议/规则指纹变化时重新获取上下文并校验计划。

以下场景必须有完整教程，能由新AI从零走通。

1. 查询已有作者，补一个已核实主页及双语简介，回读验证。
2. 研究一个候选作者，保存证据和候选字段，等待后续新线索。
3. 下载并持久化一张合规离线头像，在外网不可用的客户端显示。
4. 一份图片和一个视频按现有序号命名，入库后关联既有作者。
5. 已有作者人工简介正在被用户编辑时，任务如何处理版本冲突。
6. COS输入按当前库/目录规则处理，来源不明的文件独立列入待核实项。
7. 搁置作者清理：从候选清单、影响数量、计划确认到执行与回读的完整链路。
8. 手机无前台应用：从PC生成结果包，到手机后台拉取、导入前导出、分段应用与回读核对。

### 5.1 作者档案与作者清理的写入规范

以下限制为2026-11-06核对的现状。规则包实现时以当时OpenAPI和验证器为准。

| 内容 | 必须告诉AI的规则 |
| --- | --- |
| 作者身份 | 查询并复用既有authorId，显示名和别名按服务端规范解析，COS作者由目录体系管理 |
| 并发保存 | 先GET当前资料和revision，再准备写入，409时重读并重新核对本次字段与人工修改 |
| PUT完整字段 | 当前CreatorProfileWrite有多个必填字段，适配层按当前值合并本次明确修改，完整合法提交，保持其他分组资料 |
| 整理简介 | `biography`当前最多2000字符，与X原文分开保存 |
| X原文 | `xProfile.url`绑定已核对账号主页，`xProfile.biography`保留原文，当前最多1000字符 |
| 中文译文 | `biographyZh`当前最多2000字符，绑定同一账号及原文，省略与显式空字符串按协议分别处理 |
| 链接 | `homepageUrl`为作者主页，`evidenceUrls`为证据，当前证据最多8条，单URL最多2000字符，账号主页/原帖/作品下载页分别标明用途 |
| 来源词 | 作者来源渠道词、作者个人链接、作品出处/角色分区按现有专题分别维护 |
| 核验状态 | `empty/candidate/verified`按证据区分，昵称、水印或转载标签的弱线索不能单独支撑verified |
| 自动维护 | autoRefresh、feedUrl、trackUpdates按任务明确授权及现有来源能力保存 |
| 删除作者（三清） | DELETE /api/v1/authors/{authorId}：移除全部片段块、`asset_authors`关联与作者行，媒体与资产保留；仅常规作者，COS返回400，作者不存在返回404；执行前必须先出影响数量 |
| 改名身份迁移 | PUT /api/v1/authors/{authorId}：原地重写TXT别名并迁移身份、关注标记、关联与上传条目；回读id必须等于迁移后身份；新身份命中其他作者返回409且本端点不做合并 |
| 改挂资产作者 | PUT /api/v1/assets/{assetId}/authors：提交authorIds∪newAuthorNames的并集；移除关联会删除作品行，已关联作者幂等补行；COS作者不参与该端点 |
| 重复作者合并 | 现有端点不做合并；先输出计划（保留身份、删除身份、作品行、关联、关注标记、档案取舍），再逐项执行删除+改挂+档案补缺并回读；端点不足时先改OpenAPI再生成SDK |
| 搁置作者清理 | 只用`author.cleanup.prepare`列出候选、证据与影响数量，确认后由apply执行；判定口径（零关联、无有效档案、长期未维护等）在P0与用户确认，文档不预设阈值 |

接口教程必须展示“读取现状 → 准备字段变更或清理计划 → 验证完整载荷 → 正式保存或执行 → 回读”的完整链路。平台停用、封禁或隐退时记录稳定数字ID、历史证据、获取时刻及不可访问事实，保留待核实结论。

### 5.2 头像规范

1. 区分头像来源地址、持久离线图片与认证展示接口，记录作者归属证据、来源、抓取时刻、图片类型及摘要。
2. 当前普通资料PUT接收avatarUrl，离线avatarData位于v2作者段。规则包必须如实说明现有写入路径；需要专用头像持久化入口时先改OpenAPI并云端生成SDK。
3. 复用既有来源绑定及持久化机制。当前离线图片解码后最多2MiB，允许PNG/JPEG/GIF/WebP，采用内容嗅探、大小与来源校验。
4. 公共图片下载沿用SECURITY的HTTPS、DNS/IP、重定向和SSRF限制。缓存已有合规图片可由可信端复用，外站失败输出原因及可恢复状态。
5. 普通资料响应保持小体积，AI默认接收图片可用状态和摘要。界面通过现有认证头像接口显示，跨设备完整备份保留图片正文。

### 5.3 作品、命名与关联规范

- 先查库内命名、名称联想、规范出处/角色及序号，再提交命名计划。图组与独立作品分别处理，保存原名到实际入库名的映射。
- 上传、扫描、重名处理及移动复用正式文件流程，记录uploadId、assetId、实际relPath和源时间，响应丢失时查完成事实后再继续。
- 作者关联通过正式资产作者接口维护，并验证TXT及主表链路。新建作者行后继续显式建立作品关联。
- 改名、删除、改挂与合并按5.1的规则生成计划；删除只解除业务关联，媒体文件保留，永久删除媒体仍只走独立管理操作。
- 标签沿用现行明文存储与集合语义，AI不写标签；需要标签时由用户在界面维护，任务只报告现状与冲突，不提交任何标签变更。

## 6. 本地维护权限与无前台跨端通道

### 6.1 权限档位与边界

| 档位 | 主体 | 允许 | 禁止 |
| --- | --- | --- | --- |
| 宿主数据只读 | PC/NAS 本地可信执行端 | 只读服务端数据目录`qimeng-data`内的SQLite/WAL、备份快照与导出文件 | 任何写入、打开写事务、VACUUM、改动文件时间 |
| 资料维护目录 | PC/NAS/手机 | 在用户授权的资料维护目录内按任务读写两代备份、摘要与结果包 | 越出授权根、写系统目录、未经保护地覆盖待导入文件 |
| 业务数据写入 | 所有执行端 | 正式API（Bearer admin） | 直连数据库/SQL、绕过领域服务与鉴权、向外部模型导出密钥/令牌 |

- 凭据只放忽略的本地配置（环境变量名或`*.local`），不写入仓库、任务记录、结果包或日志。
- 只读访问不转移一致性责任：执行端不得改动WAL与快照，不把只读副本当作业务真相；需要历史状态时读快照，不追加写入。
- 8420 真库禁止测试写入；验证使用隔离实例、临时数据与合成媒体。
- 手机单机库与PC实例各自持有业务真相，跨端只经结果包与正式导入/导出交换，不共享数据库文件。

### 6.2 宿主数据与授权目录

- 服务端数据目录`qimeng-data`归服务端所有：AI维护任务只读SQLite/WAL、在线快照与既有导出文件，用于核对现状、生成计划与结果包。
- 资料维护目录由用户一次性选定根目录，生成作者资料与备份子目录；服务端通过既有作者总表镜像配置向该目录单向写出主表，AI维护任务不接管镜像配置。
- 本地执行端的读取范围、临时目录与清理策略写入任务记录；临时文件不得落在媒体根、库根或资料维护目录之外。
- 任何目录写入前校验规范化路径仍在授权根内，并沿用现有外部替换保护：待导入文件被用户替换时先停止覆盖。

### 6.3 手机后台拉取流程与状态

手机主动连接电脑，拉取结果包并应用；电脑不连接手机，也不存在服务端向手机单机库的在线回写通道。流程固定如下，不得省略导出步骤。

1. 电脑端生成结果包并登记任务（`device.apply.prepare`）：包含协议/规则版本指纹、目标实例与段清单、主表TXT与完整v2备份的文件摘要、期望回读指标。
2. 手机worker在充电与Wi-Fi约束满足后领取任务，不需要用户打开App；需要短时保活时使用带通知的前台服务，不驻留常开前台。
3. 自动先导出当前实例的两代备份与摘要；保存失败立即中止，不应用任何段。
4. 校验包版本、指纹、段摘要与目标实例；不匹配进入waiting_authorization或失败项，不执行“尽量应用”。
5. 分段应用：主表TXT只含作者身份、作品行与来源区，按keep口径重建对齐；需要头像、简介、译文等完整资料时必须走v2导入。
6. 回读核对（作者数、关联数、标签数、事件数、文件摘要），成功后回传结果与本地摘要；失败保留可恢复状态与已应用段记录。
7. 任务结束后清理临时包，保留两代备份与结果摘要。

状态至少包含`waiting_authorization`（未授权、授权失效或需用户确认）与`waiting_device`（设备离线、未充电、非Wi-Fi或进程被杀）；两者可恢复，恢复后从最近已确认段继续，不重复应用。

### 6.4 导入前导出与两代备份分代目录

导入前必须先导出，是现行规范保护：桥接必须自动执行，导出保存失败即中止导入。实施后由两代替换现行三代，轮换与摘要校验语义不变。

建议布局（P0可细化文件名，但必须两代且每代独立文件夹）：

```text
资料维护/
  当前/
    作者资料/   作者总表.txt、阅读版、索引
    备份/       影库备份.json 及其摘要
  上次/
    作者资料/   上一代作者总表
    备份/       上一代完整备份
```

- 每代目录独立保存文件与摘要，当前与上次不共用路径、不复用同一文件名后缀。
- 相同数据重导出只更新当前一代，不挤掉上次；轮换按“当前→上次、并写入新当前”的顺序提交，失败重试避免同份旧内容重复轮换。
- 导入前保护写入当前一代；导入成功后重新导出合并结果为最新当前份。
- 旧上上次文件在实施时按用户授权清理，清理前先核对摘要与可读性；不在未授权时删除用户目录中的历史文件。
- 当前装机仍是三代同目录结构；两代分代目录属于待实现项，不得写成已实施。

### 6.5 主表TXT与v2的分工

- 主表TXT只含作者身份、作品行与来源区，不含头像、简介与译文；手机仅靠主表TXT无法完成完整资料对齐。
- 完整资料必须走v2导入。v2分段合并语义维持：事件身份幂等合并、收藏/关注并集、作者档案保留本端并补缺、TXT按keep重建、appPrefs覆盖；标签改动时间裁决仍沿用现有语义。
- 导入按段提交，后段失败保留已提交段并明确报告；不得宣称整份成功，也不得用再次合并充当“撤销”。
- 错误指纹、版本不符、摘要错配、结构非法在任何写入前拒绝。

### 6.6 不新增监听面与恢复

- 手机只作为客户端主动连接电脑或未来NAS，不开放入站端口、不监听局域网；不需要USB调试或ADB转发。
- 离线、授权失效、进程被杀、系统升级后均可恢复：任务与结果包保留在电脑侧，手机侧保留已应用段与摘要，重试按幂等键判定。
- worker采用有界租约，领取超时可由下一次运行接管；同一任务同一段只允许一次有效写入。
- 电量、流量、时间与并发有明确上限，前台浏览与播放优先；约束不满足时进入waiting_device而不是抢资源执行。

## 7. 输入与研究流水线

| 阶段 | 关键产物 |
| --- | --- |
| 输入清点 | 授权目录/上传批次、可稳定读取的文件、大小、摘要、类型、尺寸、时长与图组 |
| 库内对照 | 重复候选、已有作者/别名、出处/角色及规范命名 |
| 外部研究 | 实际用到的搜索能力、查询词、页面/原帖/历史留档、截图摘要、证据与未决项 |
| 维护计划 | 每个对象的前置版本、拟执行操作、字段来源、目标库、依赖与资源预算 |
| 正式执行 | 上传/扫描/命名/档案/关联/作者清理按依赖提交，保留每一步完成事实 |
| 回读核对 | 对象、实际文件、业务关联、主表、离线头像及归档/备份状态 |
| 交付报告 | 新增、更新、跳过、冲突、待核实、失败、可恢复步骤与实际出站数据 |

下载目录可能仍在写入，清点需确认文件稳定并在使用前复核版本。输入以不透明artifactId引用，执行器解析到授权根内的文件。对视频后台抽取有限代表帧并记录时间点，原件保持原有保存规则，样本数、尺寸、出站字节与费用有界。

小红车/创意工坊的条目ID和上传者作为来源证据分别记录，作品原作者和转载者的关系按实际证据判断。X账号之外，允许沿官网互链、旧数字ID、原帖关键词、关联推文、存档及其他公开平台继续查询。研究失败保留已有证据和待核实状态。

任务类型至少覆盖以下四类。

1. 单批新下载：清点、研究、命名、入库、关联与补档案。
2. 指定作者或库的资料检查：缺头像、缺主页、缺译文、命名不规范与来源待核实的批量修复。
3. 作者清理：搁置作者与重复作者。先在库内生成候选与影响数量，再执行删除三清、改名身份迁移、改挂或合并，逐项回读。
4. 跨端应用：主表TXT对齐或v2导入，由手机后台worker拉取执行并回传结果。

历史库批量任务先输出影响数量、抽样及资源估计，再按任务授权策略执行。未知项可与已确定项分开交付。

## 8. 后台执行、状态和恢复

任务创建立即返回jobId。运行状态独立于浏览器、手机当前页面和聊天窗口，持久保存输入指纹、规则版本、授权、步骤、幂等键、证据、预算、目标实例及完成结果。

建议状态包含queued、inventory、research、planned、applying、verifying、waiting_evidence、waiting_authorization、waiting_device、paused、completed、partial、failed和cancelled。状态转换及终态含义在协议中定义。部分成功逐项可追踪，单个未知作者或单个失败段可进入待审项。

- worker采用有界并发与持久领取/租约，避免多个执行器重复处理同一步；跨端应用使用同一租约与幂等键模型。
- 幂等键结合任务、输入版本、目标实例、操作、载荷指纹以及跨端段标识。超时先查提交事实，上传继续复用既有uploadId。
- 跨端应用步骤固定为“先导出 → 校验版本/指纹 → 分段应用 → 回读 → 回传”，导出失败即中止。
- 用户并发编辑时检查revision/前置状态，重读并保留人工修改，冲突项输出可继续处理的差异。
- 取消停止后续提交与可取消研究，已经完成的变更明示保留，补偿操作逐项限定并受相同权限约束。
- PC/NAS服务停止、断网、限流、模型失败、手机进程被杀、授权失效和电量/网络约束不满足均保留进度，按可恢复错误分类进行有预算的重试和退避。
- 抽帧、哈希、上传与模型调用按任务设置CPU/IO、并发、时间、缓存、token/费用和出站预算，前台浏览播放优先。

## 9. 手机、电脑与未来NAS

| 形态 | 执行位置与要求 |
| --- | --- |
| 电脑服务 + Web/App连接 | PC常驻执行器与工具适配层调用电脑服务，Web关闭后继续；手机作为客户端查看同一任务状态，单机场景另走结果包 |
| 手机单机 + 电脑研究 | 电脑生成结果包，手机后台worker在充电+Wi-Fi约束下拉取应用；不需要手机前台、不需要USB |
| 手机单机离线 | 待领取/待应用任务保留在电脑侧，手机保留已应用段与摘要；恢复网络与授权后续跑，状态含waiting_device/waiting_authorization |
| 未来NAS + 云端模型 | NAS保存媒体、业务数据与任务执行状态，执行器向模型服务发起调用；PC/App控制任务与浏览，手机仍按单向拉取应用 |

Android本机API位于手机回环地址，电脑执行器不能直接用自身回环地址访问手机，手机也不监听入站。实现必须采用“手机主动拉取结果包”的桥接：电脑侧登记任务与包，手机侧沿现有Repository/SDK及WorkManager（必要时带通知的前台服务）领取、应用并回传。保留系统通知、授权撤回、Doze、厂商后台限制和进程重启的真实边界，验收覆盖任务恢复与重复应用防护。

PC/NAS承担长期研究与较重媒体处理，同时是本地可信执行端：只读宿主数据、在授权维护目录内读写、业务写入走正式API。NAS部署前补硬件、磁盘、架构、资源、时区、隧道、权限与恢复验证。手机长期媒体库存迁往NAS时，原件完成与独立备份验证先行，手机释放按用户实际授权执行。

## 10. 权限、安全与自动执行策略

- 每个任务明确目标实例、库、输入根、可修改对象/字段、外部检索与截图上传范围、自动执行策略和预算。授权范围内证据充分的常规补全自动推进，歧义或冲突项进入独立待处理清单。
- 删除、合并、大规模改名和释放原件必须先生成计划与影响数量，经授权确认后执行并回读；不接受模型直接给出“已删除”结论。
- 本地执行端按6.1的档位限权：宿主数据只读，资料维护目录按授权读写，业务数据只走正式API。凭据只放忽略的本地配置，不下发给手机worker、结果包或模型。
- API沿现有鉴权。工具侧按动作限权，服务端细粒度凭据若有缺口须先设计再实现。模型密钥留在执行器Secret配置，任务绑定目标实例，切服后旧任务保持原目标并校验可用性。远程访问沿隧道规则部署。
- 不向外部模型导出密钥、令牌、数据库文件或完整备份；模型调用只接收任务所需的最小媒体与文本样本。
- 搜索结果、网页、文件名、媒体元数据和附带文档作为不可信数据处理。模型输出走结构校验及允许操作清单，媒体处理采用固定受控参数和路径根校验。证据不能修改权限、工具规则或任务目标。
- 模型出站逐项记录实际外发字段与样本摘要（媒体画面、文件名、来源正文、作者资料）；出站记录不含任何标签脱敏、代号映射或密钥材料。
- 真实文件路径、浏览记录、设备标识和真实研究材料按SECURITY处理。人工授权的样本范围与业务自动执行权限分开记载。
- 8420 真库禁止测试写入；Android 设备须显式选择，禁止操作默认或雷电模拟器。

## 11. 分阶段交付清单

## 12. 验收矩阵

自动检查使用隔离服务、临时数据及合成图片/视频，构建和测试走云端。当前8420真库遵守AGENTS，设备须显式选择。

| 验收 | 通过条件 |
| --- | --- |
| 新AI接手 | 只靠规则发现入口及示例完成合成作者、头像、链接、双语简介和作品关联维护 |
| 混合小批次 | 图片、视频、动图、COS、图组、重复和未知项逐项正确记录 |
| 协议约束 | 必填/枚举/超限/空值/来源及revision失败明确，GET返回字段不会被无意清空 |
| 原件及命名 | 命名延续、并发抢号、重名和源文件变更按领域规则处理 |
| 后台不抢焦点 | 用户浏览/操作手机时任务继续，无导航跳转或自动播放，前台资源有保障 |
| 恢复与幂等 | 在上传完成、作者保存、关联写入及回读前后断开，恢复后无重复资产和事件 |
| 双端并发编辑 | 人工资料与任务交错，冲突可见且已提交修改守恒；AI不写标签 |
| 作者清理 | 删除三清、改名身份迁移、改挂与合并均先出影响数量，执行后回读一致，媒体文件保留，冲突返回409且不静默合并 |
| 重复作者去重 | 计划覆盖作品行、关联、关注标记与档案取舍，合并后无孤立关联、无重复身份 |
| 权限边界 | 本地执行端对宿主数据只读可核验，越界写入被拒绝；业务写入只经正式API，凭据不外泄 |
| 先导出保护 | 跨端应用前自动导出两代备份与摘要，导出失败即中止；错版本/错指纹/摘要不符在写入前拒绝 |
| 两代分代布局 | 当前/上次各自独立目录与摘要，相同数据重导出不挤掉上次，导入前保护与导入后重导出语义成立 |
| 手机无前台应用 | 不打开App前台、不接USB，充电+Wi-Fi下完成拉取、应用与回传；离线、授权失效、进程被杀后可恢复且不重复应用 |
| 新设备首次绑定 | 覆盖先复制旧完整目录及摘要、再绑定空库根目录的顺序，确认恢复前保护待导入文件和可恢复旧份 |
| NAS及手机库存 | 媒体驻留NAS，手机仅使用明确预算的缓存，后台任务与恢复在目标设备验证 |
