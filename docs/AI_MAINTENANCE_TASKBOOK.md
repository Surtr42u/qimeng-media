# 外部 AI 维护、后台任务与标签隐私任务书

> 需求确认日期为2026-11-06。拟交接执行者为用户指定的DeepSeek V4.1。本文件记录实施要求，所有阶段初始状态均为待实现。当前已有OpenAPI及业务服务，AI工具、持久任务队列和标签加密须按本任务书交付证据后更新状态。
> 用户要求完整保留需求，供后续重构继承。方向决策见[ADR-0051](adr/0051-外部AI维护与标签隐私.md)，能力状态见[CAPABILITY_MAP](CAPABILITY_MAP.md)，实际运行包见[HANDOVER](HANDOVER.md)。

## 1. 用户需求原意与完成目标

用户会从“小红车”等渠道一次下载十几份喜欢的内容，包含图片、视频、动图、COS及图组。用户希望将指定范围交给AI，自动清点、找来源、核对作者和作品、整理命名、补资料、打标签、建立关联并执行维护，以减少逐文件操作。这个例子只是一个入口，还要覆盖后续多批次、历史资料补全、纠错、重复核对及按条件维护。

当前使用手机单机和电脑Web。任务执行应在后台持续，用户照常操作手机，任务通过服务和正式接口工作。未来媒体长期存放NAS，下载内容可以直接送入NAS待整理目录，再由NAS上的任务执行器调用云端AI完成维护，手机作为浏览和任务控制端使用。手机的缩略图及播放临时缓存须有明确预算，NAS模式的长期媒体库存归NAS。

标签名称具有隐私性，用户要求加密，并希望减少真实标签向外部模型发送。标签真名显示、加密存储、外部代号及跨端恢复均须覆盖。标签加密与模型平台的内容处理规则分别说明，任务报告必须准确陈述实际出站数据。

用户还要求AI能容易理解项目规则。工具应主动提供头像、链接、简介、双语翻译、作者身份、作品命名及关联写入的机器可读说明，连同示例和错误处理。新AI接手后应能发现规则、查询现状、生成合法计划并执行，所需规范有固定入口。

## 3. 权威入口与重构不变量

按任务读取以下正文，规则发生变化时同步权威位置。

- [AGENTS](../AGENTS.md)及[协作规范](../AI_README_FIRST.md)负责范围、云端执行和交付门禁。
- [OpenAPI](../api/openapi.yaml)及[API导航](GUIDE_API.md)负责字段、方法、状态码和SDK生成。
- [作者研究指南](../tools/AUTHOR_RESEARCH.md)负责查询、证据、身份及候选认定。
- [媒体复核流程](../tools/MEDIA_RESEARCH_IMPORT.md)负责工作单、命名、正式写入、双端核对与证据留档。
- [作者](domain/authors.md)、[文件](domain/files.md)、[匹配](domain/matching.md)、[标签](domain/engagement.md)、[迁移](domain/migration.md)负责具体领域规则。
- [安全](SECURITY.md)、[架构](ARCHITECTURE.md)、[UI](GUIDE_UI.md)及[内嵌部署](../deploy/embedded/README.md)负责信任边界、分层和后台约束。

重构必须继承以下行为。

1. 正式服务保存业务真相，工具通过现有领域服务及API读写。任务账本保存执行状态和证据索引，作者、标签及关联继续复用业务身份。
2. 作者人工资料、手工清空语义、头像来源绑定、原文与译文、候选状态及版本冲突保护完整保留。
3. 常规作者与COS目录体系分开处理，文件改名、关联、TXT及镜像沿现有一致性维护链执行。
4. 浏览事件身份守恒、标签组时间裁决及现行备份恢复语义继续遵守。任务schema版本独立于当前v2备份版本。
5. 作者主表和完整备份继续各保留最新、上次、上上次，路径与中文命名遵守当前维护目录约定。
6. 文件原件、并发编辑和跨实例身份受保护。比对使用作品身份、相对路径、大小/摘要及业务内容，并分别记录本机时间、ID和溯源。

## 4. 总体结构与AI实际调用方式

推荐链路为“AI客户端/任务提交端 → 工具适配层 → 持久任务与执行器 → 正式业务API → App/Web”。研究证据与媒体处理由执行器在授权范围内完成。主服务继续遵守模块化单体和ADR-0019的编排边界。

AI工具运行入口可独立部署于PC/NAS。先提供可脚本调用的结构化入口，再以同一套操作能力提供MCP适配。实施时核对当前官方协议与SDK，选定兼容版本并锁定依赖。本机接入使用标准输入输出等适合本机进程的传输，远程接入遵守隧道策略。凭据留在可信执行端。

### AI客户端接入交付

实现者必须提供可直接照做的接入说明和模板，包含以下内容。

1. 工具如何安装、启动、连接目标影库及检查健康。
2. 支持工具调用的客户端如何登记工具服务、发现工具、读取规则并提交任务。
3. 云端模型API如何由代理运行器调用，如何执行工具调用并将结果交回模型，如何持久化任务。模型连接、工具执行和后台调度各自有明确进程与责任。
4. 客户端暂时缺少工具连接时，如何导出脱敏上下文、接收结构化维护计划，再由可信执行器校验执行。
5. 连接配置只用占位符与环境变量名，真实模型密钥、服务口令、路径与设备信息放忽略的本地配置。
6. 搜索、浏览、反向识图、视觉模型及媒体下载能力逐项声明。任务按实际能力运行，缺少研究工具时输出可继续处理的证据请求或研究包。

下列名称是待定稿的目标契约，实现时标明每项支持状态和对应正式API。

## 5. 让AI理解规范的规则包

必须提供一个固定可发现的规则入口，供工具调用和离线交接共同使用。机器可读内容与简明中文指南同批交付，协议字段从OpenAPI/领域验证器生成或核对，规则包带版本和指纹。

规则包至少包含以下内容。

- 当前实例与库类型、支持的动作、字段schema、必填项、枚举、长度/字节预算、分页和冲突码。
- 作者、作品、标签、作品作者关联、作品标签关联、时间轴标签之间的区别与身份来源。
- 工作流顺序，以及来源不足、缺头像、译文缺省、文件歧义和并发更新的处理。
- 每个写入动作的最小合法示例、成功回读示例、常见拒绝示例和恢复方法，使用合成数据。
- 内容来源、证据引用、候选与已核实的区别，哪些字段可补缺、哪些需要明确修改意图。
- 规则更新与能力变化检测。执行前发现协议/规则指纹变化时重新获取上下文并校验计划。

以下场景必须有完整教程，能由新AI从零走通。

1. 查询已有作者，补一个已核实主页及双语简介，回读验证。
2. 研究一个候选作者，保存证据和候选字段，等待后续新线索。
3. 下载并持久化一张合规离线头像，在外网不可用的客户端显示。
4. 一份图片和一个视频按现有序号命名，入库后关联既有作者及标签代号。
5. 已有作者人工简介正在被用户编辑时，任务如何处理版本冲突。
6. COS输入按当前库/目录规则处理，来源不明的文件独立列入待核实项。

### 5.1 作者档案的写入规范

以下限制为2026-11-06核对的现状。规则包实现时以当时OpenAPI和验证器为准。

| 内容 | 必须告诉AI的规则 |
| --- | --- |
| 作者身份 | 查询并复用既有authorId，显示名和别名按服务端规范解析，COS作者由目录体系管理 |
| 并发保存 | 先GET当前资料和revision，再准备写入，409时重读并重新核对本次字段与人工修改 |
| PUT完整字段 | 当前CreatorProfileWrite有多个必填字段，适配层按当前值合并本次明确修改，完整合法提交，保持其他分组资料 |
| 整理简介 | `biography`当前最多2000字符，与X原文分开保存 |
| X原文 | `xProfile.url`绑定已核对账号主页，`xProfile.biography`保留原文，当前最多1000字符 |
| 中文译文 | `biographyZh`当前最多2000字符，绑定同一账号及原文，省略与显式空字符串按协议分别处理 |
| 链接 | `homepageUrl`为作者主页，`evidenceUrls`为证据，当前证据最多8条，单URL最多2000字符，账号主页/原帖/作品下载页分别标明用途 |
| 来源词 | 作者来源渠道词、作者个人链接、作品出处/角色分区按现有专题分别维护 |
| 核验状态 | `empty/candidate/verified`按证据区分，昵称、水印或转载标签的弱线索不能单独支撑verified |
| 自动维护 | autoRefresh、feedUrl、trackUpdates按任务明确授权及现有来源能力保存 |

接口教程必须展示“读取现状 → 准备字段变更 → 验证完整载荷 → 正式保存 → 回读”的完整链路。平台停用、封禁或隐退时记录稳定数字ID、历史证据、获取时刻及不可访问事实，保留待核实结论。

### 5.2 头像规范

1. 区分头像来源地址、持久离线图片与认证展示接口，记录作者归属证据、来源、抓取时刻、图片类型及摘要。
2. 当前普通资料PUT接收avatarUrl，离线avatarData位于v2作者段。规则包必须如实说明现有写入路径；需要专用头像持久化入口时先改OpenAPI并云端生成SDK。
3. 复用既有来源绑定及持久化机制。当前离线图片解码后最多2MiB，允许PNG/JPEG/GIF/WebP，采用内容嗅探、大小与来源校验。
4. 公共图片下载沿用SECURITY的HTTPS、DNS/IP、重定向和SSRF限制。缓存已有合规图片可由可信端复用，外站失败输出原因及可恢复状态。
5. 普通资料响应保持小体积，AI默认接收图片可用状态和摘要。界面通过现有认证头像接口显示，跨设备完整备份保留图片正文。

### 5.3 作品、标签和关联规范

- 先查库内命名、名称联想、规范出处/角色及序号，再提交命名计划。图组与独立作品分别处理，保存原名到实际入库名的映射。
- 上传、扫描、重名处理及移动复用正式文件流程，记录uploadId、assetId、实际relPath和源时间，响应丢失时查完成事实后再继续。
- 作者关联通过正式资产作者接口维护，并验证TXT及主表链路。新建作者行后继续显式建立作品关联。
- 当前资产标签PUT整体替换tagIds。任务的“追加标签”先读取当前集合并合并本次目标，识别并发编辑；新协议需要集合版本时先补契约和SDK。
- 标签删除、解除关联、时间轴标签分别提供动作说明，时间轴含视频毫秒位置，继续遵守标签组时间裁决。

## 6. 标签隐私与加密

### 必须达到的结果

1. App/Web授权用户能显示真实标签并正常搜索、筛选、排序与维护关联。
2. 外部AI默认接收稳定的不透明tagId与代号，如T001。映射保存在可信端，重启与任务重试后映射稳定。
3. 分类所需语义通过用户允许的公开说明、可信本地规则或本地模型提供。涉及语义外发的模式写进任务策略与报告。
4. 明文存储、WAL/临时文件、FTS、索引、备份、日志、任务计划、URL、异常和诊断包逐项审查，形成具体数据流与威胁边界。

### 实施前必须定稿的加密设计

采用维护良好的认证加密能力，具体字段/数据库存储路线、密钥管理和可搜索索引在安全设计中定稿。保护目标至少包括标签名称及敏感别名的落盘和备份。关系ID、数量和访问模式的泄露范围单独说明。

密钥按平台使用可信密钥存储或受控Secret，定义首次初始化、解锁、轮换、丢失提示及新设备恢复。移动端和NAS的密钥封装分别设计，密钥与密文备份分开保管。外部AI工具持有受限调用能力，解密在可信端执行。

标签查重/搜索索引必须保留唯一性及现行匹配语义，评估索引泄露与规模预算。加密、解密、过滤、标签名展示只在明确的可信边界完成。锁定、损坏和缺密钥有可辨识的错误状态。

备份先决定加密容器与内层当前v2数据的关系，写明格式版本、认证失败、密钥恢复、大小上限、三代轮换及跨端导入。现用v2数据安排一次受控迁移，旧项目v1继续按退役规则处理。加密升级必须有失败恢复与真实迁移证据。

## 7. 输入与研究流水线

| 阶段 | 关键产物 |
| --- | --- |
| 输入清点 | 授权目录/上传批次、可稳定读取的文件、大小、摘要、类型、尺寸、时长与图组 |
| 库内对照 | 重复候选、已有作者/别名、出处/角色、既有标签代号及规范命名 |
| 外部研究 | 实际用到的搜索能力、查询词、页面/原帖/历史留档、截图摘要、证据与未决项 |
| 维护计划 | 每个对象的前置版本、拟执行操作、字段来源、目标库、依赖与资源预算 |
| 正式执行 | 上传/扫描/命名/档案/关联按依赖提交，保留每一步完成事实 |
| 回读核对 | 对象、实际文件、业务关联、主表、离线头像及归档/备份状态 |
| 交付报告 | 新增、更新、跳过、冲突、待核实、失败、可恢复步骤与实际出站数据 |

下载目录可能仍在写入，清点需确认文件稳定并在使用前复核版本。输入以不透明artifactId引用，执行器解析到授权根内的文件。对视频后台抽取有限代表帧并记录时间点，原件保持原有保存规则，样本数、尺寸、出站字节与费用有界。

小红车/创意工坊的条目ID和上传者作为来源证据分别记录，作品原作者和转载者的关系按实际证据判断。X账号之外，允许沿官网互链、旧数字ID、原帖关键词、关联推文、存档及其他公开平台继续查询。研究失败保留已有证据和待核实状态。

任务范围可以覆盖单批新下载、指定作者/标签、某个库的缺资料或规范检查。历史库批量任务先输出影响数量、抽样及资源估计，再按任务授权策略执行。未知项可与已确定项分开交付。

## 8. 后台执行、状态和恢复

任务创建立即返回jobId。运行状态独立于浏览器、手机当前页面和聊天窗口，持久保存输入指纹、规则版本、授权、步骤、幂等键、证据、预算、目标实例及完成结果。

建议状态包含queued、inventory、research、planned、applying、verifying、waiting_evidence、paused、completed、partial、failed和cancelled。状态转换及终态含义在协议中定义。部分成功逐项可追踪，单个未知作者可进入待审项。

- worker采用有界并发与持久领取/租约，避免多个执行器重复处理同一步。
- 幂等键结合任务、输入版本、目标实例、操作和载荷指纹。超时先查提交事实，上传继续复用既有uploadId。
- 用户并发编辑时检查revision/前置状态，重读并保留人工修改，冲突项输出可继续处理的差异。
- 取消停止后续提交与可取消研究，已经完成的变更明示保留，补偿操作逐项限定并受相同权限约束。
- PC/NAS服务停止、断网、限流、模型失败和手机进程被杀均保留进度。按可恢复错误分类进行有预算的重试和退避。
- 抽帧、哈希、上传与模型调用按任务设置CPU/IO、并发、时间、缓存、token/费用和出站预算，前台浏览播放优先。

## 9. 手机、电脑与未来NAS

| 形态 | 执行位置与要求 |
| --- | --- |
| 电脑服务 + Web/App连接 | 常驻执行器调用电脑服务，Web关闭后继续，手机查看同一任务状态 |
| 手机单机 + 电脑研究 | 手机授权输入上传到任务暂存区，研究在电脑执行，手机可信桥接通过本机正式API应用结果 |
| 手机单机离线 | 持久保存待发送/待应用任务，本机只执行已具备条件的步骤，恢复连接后续跑 |
| 未来NAS + 云端模型 | NAS保存媒体、业务数据与任务执行状态，执行器向模型服务发起调用，PC/App控制任务和浏览 |

Android本机API位于手机回环地址，电脑执行器不能直接用自身回环地址访问手机。实现必须明确采用授权上传、持久轮询/结果包或等价可信桥接，沿现有Repository/SDK及WorkManager/前台服务接线。保留系统通知、授权撤回、Doze和进程重启的真实边界，验收覆盖任务恢复。

PC/NAS承担长期研究与较重媒体处理。NAS部署前补硬件、磁盘、架构、资源、时区、隧道、密钥和恢复验证。手机长期媒体库存迁往NAS时，原件完成与独立备份验证先行，手机释放按用户实际授权执行。

## 10. 权限、安全与自动执行策略

每个任务明确目标实例、库、输入根、可修改对象/字段、外部检索与截图上传范围、自动执行策略和预算。授权范围内证据充分的常规补全自动推进，歧义或冲突项进入独立待处理清单。大规模改名、删除和释放原件分别受任务范围约束。

API沿现有鉴权。工具侧按动作限权，服务端细粒度凭据若有缺口须先设计再实现。模型密钥留在执行器Secret配置，任务绑定目标实例，切服后旧任务保持原目标并校验可用性。远程访问沿隧道规则部署。

搜索结果、网页、文件名、媒体元数据和附带文档作为不可信数据处理。模型输出走结构校验及允许操作清单，媒体处理采用固定受控参数和路径根校验。证据不能修改权限、工具规则或任务目标。

真实标签、文件路径、浏览记录、令牌、设备标识和真实研究材料按SECURITY处理。模型调用逐项记录实际外发字段和样本摘要，人工授权的样本范围与业务自动执行权限分开记载。媒体画面、文件名、来源正文及标签均纳入出站数据流核对，模型服务按其规则处理收到的图文。
