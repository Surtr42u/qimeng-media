# 便携备份导入导出（qimeng_backup.json）

> 本专题是领域规则正文；[领域目录](../DOMAIN_RULES.md)保留原 §编号。公式与常量保持原义，标记「逐字遵守」者未经用户明确要求不得改变。

## 10. 旧数据迁移映射（qimeng_backup.json → 新库）

业务宿主为 `portablebackup`：独立文件 DTO，不依赖 HTTP/gen；有界 JSON 解码、状态码和附件头留在 HTTP。仅接受v2并在任何写入前拒绝其他版本；身份匹配、TXT→作者→标签→事件→点赞收藏→时间轴→关注→偏好原顺序保留。各段仍独立提交；后段失败保留已提交前段并返回原阶段错误，可幂等重试，已提交数据同步失效推荐/推进修订号并通知连接客户端，避免失败响应遮住部分提交。取消前未提交则不通知；TXT 单片段失败仍警告跳过，keep 与镜像刷新沿用 authorimport。导出全部查询绑定同一个事务快照，任何段查询失败中止，偏好缺省兼容边界不扩大。既有全量备份/64MiB限额不变，本次不是流式容器或历史截断改造。

**当前便携格式v2（ADR-0040/0050）**：旧项目v1导入已退役；schemaVersion非2（包括缺失/0/1/未知值）一律写前400。旧版聚合转事件、批次快跳与取最早同名文件的路径已删除；[旧映射仅作历史](../history/LEGACY_BACKUP_V1.md)。当前导出 v2 必带 `viewEvents`（允许空数组），保留事件身份、原始会话/来源、UTC 毫秒时间、可空秒数及原日键；导入只按事件身份幂等合并，绝不再回放同份 mediaStats/dailyBrowse/history。已有 clientEventId（包括 legacy 内容键）原样保留；无键历史由 migration 0019 的旁表分配持久 portable 身份，不改历史事件原文；首次导回自身也能认出。v2 缺事件段/重复 recordKey/非法事件拒绝并且不写入。既有无键历史及legacy内容键仍由migration0019/事件身份机制原样往返，不改历史迁移或清理已有记录。已发生的重复不会被擅自删除。

**v2 文件映射**：recordKey 只负责备份内关联，全份唯一；按资产 ID 排序后逐次查重，碰撞追加资产 ID 与序号。导出可选 assetId/libraryName/relPath（不含绝对根）；导入本库 assetId 命中优先，跨库按文件名→相对路径→库名逐层唯一消歧，仍歧义或多个源条目指向同一目标时全部相关条目跳过并告警，绝不套用 v1「取最早」兜底。未匹配数据按既有跳过口径，媒体仍须先行。A→A、A→B→A 与实时补传交叉按事件身份守恒；不同历史来源本来就已丢失身份的聚合记录无法逆推重合关系。


v2的点赞/收藏段仍沿用既有载荷：点赞按最后点赞日幂等落一行，累计次数大于1无法还原逐日来源时给出警告；收藏按唯一键合并。偏好对象自身的version=1独立于备份信封schemaVersion=2，保留该元信息不代表接收v1备份。

### v2关联与载荷规则

文件映射以本节「v2 文件映射」为准；下列未匹配处理、标签组裁决、溯源及TXT片段规则继续保留，不属于已退役的聚合转事件逻辑。

**未匹配与载荷边界（2026-10-01 文档澄清，第四百二十五笔）**：导入不创建/删除媒体资产，也不主动清理已有事件；标签组可按下文的较新时间整体替换，TXT按keep规则重建涉及作者的关联，不能概括为所有元数据只增不减；目标库没有同名文件（recordKey 匹配不上既有资产）时，该文件的作者/标签关联计入响应 skipped 计数，行为数据（浏览/点赞/收藏/时间轴）静默跳过，assetsMatched/mediaFilesTotal 可看匹配率。备份不含媒体文件本体（文件先行走上传/本机同步通道）；TXT 作者片段自 2026-10-01 起随备份迁移（见本节「TXT 片段」段，import-txt 手动通道保留为备用）。

**标签组同步语义（2026-09-20 用户拍板）**：资产标签组带改动时间——`assets.tag_set_updated_at`（migration 0012 新增，RFC3339，`''` = 未知/旧数据），任何标签组变更（替换式 PUT、单关联解绑、删除标签级联清关联、导入改写）随动写服务器当前时刻；备份 mediaFiles 条目新增可选 `tagsUpdatedAtMillis`（该资产标签组最后改动毫秒；缺省或 ≤0 = 未知，旧版备份恒缺省）。导入按资产逐个判定：**两侧时间都已知且备份 > 库内** → 该资产标签组整体替换为备份集（清空后按 mediaTagRefs 重挂）并把库内时间改写为备份时间、替换资产数计入结果 `assetsTagsReplaced`；其余情况（任一侧未知 / 备份 ≤ 库内）维持并集合并（只增不删）且**不改写库内时间**——并集结果没有单一来源时刻，宁可保留「未知」也不造假版本。导出恒带 `tagsUpdatedAtMillis`（库内 `''` → 字段缺省）。标签池（tags 段）始终并集 upsert，不参与时间判定。

**关联溯源与行级合并裁决（2026-10-02，ADR-0032）**：作者/标签关联与作者行的每一行携带来历证据——`created_at`（关联成立时刻，RFC3339 固定毫秒文本，库内统一口径）+ `origin`（写入通道受控词表：`client`=HTTP 客户端端点〔web/app 共用，服务端不区分 UA〕、`txt`=TXT 片段统一重建手动导入、`import`=备份导入、`local-sync`=本机同步自动导入、`scanner`=扫描器派生〔角色行/COS 作者〕、`legacy`=0016 迁移回填存量行=不可考；常量单源 `server/internal/store/provenance.go`）。时间哨兵：asset_authors/asset_characters 新列 NULL=不可考（存量行如实回填 NULL，禁止伪造时间）；asset_tags.created_at 沿用 0004 既有 epoch 哨兵（语义等价：都表示不可考）；asset_characters 的 created_at 语义=当前重算发生时刻（先删后插派生数据，重算即刷新）。**备份透传**：导出把库内原始来历原样带出（`LegacyAuthor.origin`、`LegacyAuthorMediaRef.createdAtMillis+origin`、`LegacyMediaTagRef.origin`，可空=旧版备份无此信息；asset_characters 是扫描器派生数据不入备份）——A 端手工创建的关联到 B 端仍是 `client`，来历不因搬运失真。**导入行级裁决**：① 词表校验——透传 origin 非法或缺省 → 兜底盖 `import`，透传时间缺省/≤0 → 兜底记导入时刻（入账时刻是真实事件，不算伪造）；② **补证（heal）**——既有行不可考（origin='legacy' 或时间哨兵 NULL/epoch）时被透传值补证升级：不可考不等于永久不可知，对端有据时以对端为据；③ **首写优先（keep）**——既有行可考时绝不覆盖：重复导入幂等，保守不篡改既有结论。注意补证与 keep 只约束**导入裁决**：TXT 重建/tags PUT 等替换式路径先删后插，行章随重建通道刷新、不参与补证与 keep（重挂=新章，与「最近添加置顶」既有口径一致）。标签组**集级**「谁新听谁」裁决维持上一段 tag_set_updated_at 口径不变，本次升级的是**行级**溯源（并集/替换两路径的逐行盖章与补证）。view_events 不在此列：事件流已有 session_id/client_event_id 行级溯源（migration 0010/0014），其三代回放键空间问题属导入回放专项另行处理。**读取面（2026-10-02 详情透传，ADR-0032 独立提案落地）**：详情响应的作者/标签关联条目（AssetDetailTag/AssetDetailAuthor）纯透传行级 `origin`+`createdAtMillis`（可空；NULL/epoch 哨兵归一为 null/缺省=不可考，≤0 同待遇）——只读零裁决，本段补证/keep 语义不涉读取面；角色行不入详情溯源面（扫描器派生 origin 恒 scanner、时间为重算时刻，AssetSummary 的 characters 是 string[] 共享列表面）；标签池/作者列表端点不带溯源（详情条目专属视图）。

### TXT片段

**TXT 片段（txtFragments 段）（2026-10-01）**：备份载荷并入 TXT 作者片段，作者表随备份全量同步。**导出**：全量已导入 TXT 片段逐字导出（`filename`/`content`/`importedAtMillis`，来自 kv `imported_txt_sources`），不截断不转换。**导入**：该段在 authors/authorMediaRefs 段**之前**处理（片段导入触发统一重建，若后处理会冲掉备份携带的关联数据）；逐片段合并——目标库无同名片段 → 直接导入；同名且内容相同 → 跳过（幂等）；同名但内容不同 → 按 import-txt 的 keep 语义处理（目标端上传写入条目并回后替换重建，绝不 remove）；旧备份无该段 → 零处理（向后兼容）。**导入响应计数**：`txtFragmentsImported`（新增+替换数）/ `txtFragmentsSkipped`（未产生变更的跳过数＝内容相同幂等跳过＋单片段导入失败跳过，失败有 Warn 日志不中止整个导入）。keep 路径下目标端 kv 内容为「备份∪上传条目」合并结果≠备份原文，同一备份重复导入恒计 imported=1、终态内容幂等不变（口径如此，非缺陷）。

### 作者公开档案

当前v2作者条目可选`profileJson`为公开档案JSON（最多256KiB），旧备份缺省不处理。导出共享原有只读事务快照；导入在业务写入前校验作者ID一致、HTTPS地址形态与内容预算，任一无效拒绝整份输入。默认 keep 下作者段单事务，只在本端无档案时恢复，已有资料保留；恢复强制关闭autoRefresh/trackUpdates，避免导入直接启动外部访问。档案不包含API凭据、本地媒体或内部地址，不改变v2事件身份、分段提交与旧版本拒绝规则。

作者条目另可携带`avatarData`标准Base64，将已下载的头像图片一并传输。解码后最多2MiB，只接受PNG/JPEG/GIF/WebP，必须绑定同条有效`profileJson`中的非空头像来源；无效图片在任何业务写入前拒绝整份输入。图片随作者附属档案持久保存，普通资料API只返回来源信息，认证头像接口优先读取本地图片，手机可离线显示。导出将图片放在独立`avatarData`字段，保持profileJson预算；旧备份缺省继续只保存来源地址。备份请求总大小上限保持现有64MiB。

本端已有档案时，若其头像来源与传入档案一致且本端缺少离线图片，仅补图片并递增本端revision，已有人工资料和维护状态继续保留。已有离线图片或来源不一致则跳过，重复导入幂等；来源地址经人工保存变更或清空时，同时清除旧图片，避免错配。作者身份迁移和删除沿用同一档案事务与版本墓碑。

导入接口可选 query `authorProfileConflict=replace`：对备份中带 profileJson 且本机已有档案的作者，以备份整份替换档案（含离线头像，revision 在本机当前值上 +1，关闭自动维护），结果计入 `authorProfilesReplaced` 且不再产生「保留本机」提示；缺省 `keep` 仍保护本机已有资料与上述补缺规则。


### 统一目录与外部待导入文件

统一维护目录使用中文文件名与「当前/上次」两代目录轮换，具体文件角色见下节；旧 flat3 三代同目录布局继续兼容读取，未按新路径约定配置时服务端镜像回退旧语义。自动写入前校验当前文件及摘要，用户从外部替换了待导入文件时停止自动覆盖并提示先导入。确认导入时载荷已读取并校验，先保存本机现状，成功后更新最新导出。旧的独立SAF备份目录仍有手动/自动槽，统一目录不再输出这些旧槽。

### 缺省X原文的便携补充

profileJson可携带xProfile。已有档案只在双方身份已核实、本端尚未保存xProfile、传入X账号与本端已核实主页/证据链接一致时补充该对象，Twitter/X域名与账号大小写按同账号识别。其他人工字段保留，已有X原文继续保留。译文只在双方已核实、账号及原文一致、本端译文字段尚缺省时补充，人工空字符串同样保留，重复导入幂等；空档案恢复沿现有本端版本递增及自动维护关闭规则。


### 统一资料目录的文件角色

统一目录只维护一份可导入的`作者资料/作者总表.txt`。服务端在同一备份快照中生成`data.authorMasterTxt`，合并片段别名、来源与作品行，并补齐实际常规作者关联。片段首次出现决定顺序，未列入片段的作者按入库记录时间追加。COS及无法由名称往返的历史身份继续由v2保存。目录不再额外输出原始片段，阅读版资料表与主TXT分开。镜像master模式随作者编辑持续重新生成主表，片段模式用于显式片段导出。

v2保留完整元数据、作者档案和离线头像。作者资料.md用于阅读，片段索引只列作者总表.txt。v2的txtFragments仍保存完整原文，不以合成主表替代原始资料；目录不累积原始TXT或历史子目录。

选根目录、手动导出及自动更新共用影库备份.json，自动写入通过摘要保护外部替换的待导入文件。恢复继续按本章v2身份、标签时间与档案补缺规则确认合并，目录整合不新增覆盖资料策略。媒体先同步并扫描，之后导入当前元数据。

作者关联与TXT作品行保持可重建一致性。v2导入常规作者关联后，在同一作者事务中用实际匹配资产的当前文件名补入TXT并保护条目；不修改既有来源和关联成立时间。媒体改名在文件回滚保护下，事务提交路径属性及作者作品行，提交后刷新镜像。2026-11-08 起改名/移动在同一事务内把该资产的作品行替换为当前文件名（物理删除时移除；其他同名资产的作品行不受影响）。对应回归覆盖改名后的TXT与关联溯源、备份恢复后重新匹配不丢作者。

历史不透明作者ID继续以v2原身份保留。TXT没有独立ID列，无法由显示名往返为原ID时记录警告并保留已恢复关联，不以TXT补行失败拒绝原本合法的v2恢复。


### 目录备份的写入与恢复保护

目录导出的手动、自动及导入前快照各自附带SHA-256文件摘要，按原始UTF-8字节计算。目录导入有摘要时必须匹配，摘要过大、错配或写入未完成均阻止导入；用户从外部单独选择的本项目v2文件仍沿现有结构与业务校验链导入。摘要用于检测文件损坏及替换，不能验证发布者身份。维护目录采用 `当前/` 与 `上次/` 两个独立代目录：`当前/作者资料/作者总表.txt`、`当前/备份/影库备份.json` 及各自 `.sha256`，`上次/` 保存上一代同名文件与摘要；旧 flat3 三代同目录（作者总表（上次）/（上上次））继续兼容读取，新写入不再产生第三份。内容变化时先把当前整代提交为上次、再写新当前；相同数据重导出只更新当前，不挤掉上次；每代独立摘要，摘要不符或文件不可读时拒绝覆盖。备份忽略信封导出时间比较数据段。

选定维护目录后，确认v2导入先导出当前实例到同一两代备份链（当前整代提交为上次），保存失败则不开始导入。导入前状态纳入当前代，不另建快照槽；导入成功后重新导出合并结果为最新一份。历史份用于核对及数据恢复，导入仍为按段提交的幂等合并，不能用再次合并宣称撤销本次全部写入。已有作者档案与输入不同则汇总提示并保留本端现有内容（显式 `authorProfileConflict=replace` 时以备份整份覆盖），缺头像、同源X原文和译文继续遵守补缺规则。

Web在已登录、页面打开且目录授权有效时，合并本端成功写入、库变更和重连信号后写自动槽及主表；并发信号合并串行执行，切换目录后丢弃旧导出结果。关闭页面期间由下次打开补齐，失去授权或写回失败在维护入口显示。Android本机主表由服务端master镜像随作者变更更新，全量资料与备份按明确导出及原自动备份周期更新。

Android导出时，若当前本机服务端的master镜像已绑定同一个主表文件，客户端只写备份及伴随资料，不重复覆写主TXT，避免慢导出快照覆盖服务端刚写入的较新作者关联。远程模式及未绑定本机镜像的目录仍由客户端写出主表。

本机明确导出或自动输出前沿现有镜像配置端点刷新主表，可补回被手动移走的主文件，继续遵守外部未导入编辑保护。导入前快照不额外触发主表写回。

合成主TXT的来源区合并已核实作者保存的主页、X主页及证据链接，原有来源词保留。候选账号不自动写成已确认来源。来源链接属于主表的可读/可导入资料，完整简介、译文、离线头像及其他元数据仍由同一维护目录中的v2备份承接。保存作者档案提交后刷新主表镜像，并发送库变更通知，其他已授权页面可更新归档。
