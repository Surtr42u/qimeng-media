# 媒体类型与缩略图

> 本专题是领域规则正文；[领域目录](../DOMAIN_RULES.md)保留原 §编号。公式与常量保持原义，标记「逐字遵守」者未经用户明确要求不得改变。

## 11. 媒体类型与缩略图

### 回填与并发

待处理不同表示统一限 256（沿用原后台队列规模），键为最终缓存路径；队列、外层尺寸集合与内层单尺寸通过引用共用同一预算，不重复计数。每个集合元数据也最多 256 个，防止同一批表示的不同集合组合无限起续生体。后台 Submit 非阻塞，预算或队列满返回既有 ErrQueueFull，由回填可取消重试；前台先在请求栈等待准入，最多 60s，未接纳不启动后台体。Submit 的原件 stat 失败分类为单资产 ErrSourceUnavailable，回填记录并跳过，不中止范围遍历；之后的独立全量轮次会再尝试。失败仍走既有缩略图不可用占位响应，不新增 HTTP 状态码；资源释放后重试可重新准入。

已接纳集合固定原件版本，整个集合与各尺寸依附 Generator 服务生命周期；请求取消只离开等待。入队任务同样持有版本/表示引用，原件变化不会一面占旧预算一面等待新预算。源版本复核在真实生成和排队后缓存命中两条路径均执行，继续只移除本次失效表示，不触及当前版本缓存。Close 停止所有准入，取消服务根 context（闸位等待与 ffmpeg），等待队列、集合和表示生成体收齐；默认最多等待既有单尺寸超时 60s，CloseContext 可由调用方提供更短期限，逾期明确报错/记录日志。操作系统文件调用若不响应无法承诺强杀 goroutine；正常可取消外部进程和闸位路径有关闭回归。

前后台生成按最终缓存路径（资产、表示版本、生效像素、格式）共用进行中任务，重叠尺寸及不同顺序的尺寸集合也会合并；等待者取消不杀正在生成的尺寸，懒生成入口仍续生完整尺寸集合。生成闸位前后均查缓存，续生体完成后复核原件变化并清理失效版本。

开机静默窗后全量回填。内部库变更携带资产/库范围：上传、移动、回收站/恢复及已知路径监听按资产；全扫/富化/根变化/库开关按库；旧入口/信息缺失提升全量，不改变对外 SSE 载荷。待办合并同资产，库范围覆盖该库资产；最多保留 256 个范围键（单页规模的资源预算），超过时先提升本库，再提升全量，不能丢任务。执行中的通知留待下一轮，失败范围重新入待办；对账起点仍至少间隔 30s。10min 全量兜底使用独立时钟，局部回填不能不断延期外删缓存修复。每批按 asset_id 游标最多读取 256 条启用库记录，缺图立即投递有界队列，不积累整库候选或缺图清单；不再逐任务等待 200ms；队列满时按 250ms 可取消背压重试，由生成闸控制实际工作量。命中时仅检查扫描元数据对应的当前缓存文件，缺图才检查安全路径并由生成器读取原件；回填不是原件变化发现器，变化仍由扫描/监听发现。

生成并发预算仍跟随 GOMAXPROCS，既有任务不抢占。多核后台新任务仅在总占用低于“容量减一”且无前台等待者时启动，保留前台余量；单核允许一个后台任务，但已排队的前台优先取得下一个空位。前台请求同一表示时提升已有后台生成体，可使用保留预算，无需另起转码。等待者取消不撤销已提升/已开始的续生任务；连续前台负载可能推迟回填，单核须等待当前生成结束，单尺寸仍受 60s 生成超时约束。已缓存任务不占生成名额，容量不因前后台分类增加。

覆盖进度沿用“启用库资产的当前 md 档表示已落盘”口径，不数孤儿或其他版本；同样全量分批检查，可复用最近全量回填快照（局部回填只失效，不能发布局部分母），缓存 30s，库变更立即使快照失效；等待进度计算闸可随请求取消退出，取消结果不发布缓存。分页期间库变化可能短暂延迟，下一轮/周期对账收敛，未持整库长事务；扫描发现原件变化前，基于扫描元数据的覆盖统计也有延迟。实际生成及媒体出口仍检查原件，不能用回填快照替代授权或原件版本校验。缓存身份、抽帧、画质及永不按数量删除有效缓存规则不变。

### 媒体表示规则

- 类型：IMAGE / ANIMATED_IMAGE(gif) / VIDEO。
- 视频缩略图抽帧优先级（2026-08-26 对齐旧项目 v1.18 真机验证策略）：**内嵌封面优先**（cover art）→ 无则按**视频时长 35% 偏移取代表帧**（对齐 Windows 资源管理器 Icaros 体验，35% 帧构图最有"封面感"；旧版 ffprobe 实测用户参考库 376 个视频 0 个带内嵌封面，体验 100% 来自代表帧）→ 系统缩略图兜底。图片取缩放帧；动图取首帧静帧。
- 黑白/极端帧检测：采样 100 像素，**全部** <15 判黑、**全部** >240 判白（判定语义为**全部**采样像素超阈值才判，99/100 黑不判黑：角落台标与片头淡入残影是有效内容，不应触发跳帧）；不合格按比例向两侧扩散（35%→25%→45%→15%→55%→5%→65%→0ms）；取不到时长时短路 0ms 帧，不重复取同一帧。
- 抽帧位置策略变更后旧缩略图缓存必须**失效重建**；列表/详情实时显示用首帧（中段 seek 慢会加剧滑动掉帧），代表帧只用于预生成缓存——两者分工是旧版验证过的性能决策。
- **缩略图缓存身份（2026-10-19，ADR-0040）**：当前策略段为 v4（v3=EXIF 转正，v4=JPEG 质量升级）。表示版本由策略、原件 size+mtime（毫秒、与扫描器一致）、输出格式与配置像素导出；磁盘键为 SHA-256(策略:assetId:尺寸:表示版本)，按资产哈希分目录清理所有版本。URL 必带 `v` 与 size；Android 仅剥 exp/sig，保留 v。原件替换/策略升级改变表示身份，旧版本请求 410/no-store；缺省 v 的旧客户端 URL 兼容但 Cache-Control 为 private/no-cache。强 ETag 包含实际缩略图字节哈希，重生不同字节不再误 304；预取将 thumbnailVersion 与库 revision 一起比较。永不按数量上限删除有效缓存；永久删除/清空/到期/删库及扫描重探测清理资产缓存，旧布局遗留和外部删除孤儿仍待全量对账。相同 size/mtime 的外部改写不在 ADR-0004 检测面。
- **原件出口与优化边界**：详情图片/视频仍通过 origUrl 直出源文件，Android 图片使用 Size.ORIGINAL；Range 仅按原文件字节范围传输，不做图片像素切块、按需缩放或视频转码。列表缩略图是独立缓存表示，不替换原件。本次算法/取数优化不改变该出口；合成图片/视频的完整响应和 Range 响应均逐字节对照源文件验证。
- 输出格式：libwebp 可用输出 webp，缺失降级 mjpeg；格式现已纳入表示版本，磁盘扩展名/封装/Content-Type 三同源。原件永不转码。
- 静图方向（2026-10-01）：竖拍照片（EXIF Orientation≠1）的缩略图**显式按 EXIF Orientation 旋转**——服务端手写解析 JPEG APP1 EXIF 的 Orientation tag（零新依赖；HEIF/解析不到/非 JPEG 一律按 1 不转），按映射表换 ffmpeg transpose/hflip/vflip 滤镜于缩放前应用（thumbnail/orientation.go）；同时 scaleStill 输入侧恒带 `-noautorotate` 关闭 ffmpeg 解码期隐式 EXIF 转向——该隐式行为**随版本漂移**（本仓 9.0.1 实测新版默认已转、旧版不转），不关闭则显式滤镜叠在隐式之上双重变换，跨部署行为不可复现，关闭后显式滤镜是唯一方向权威；浏览器显示 /media/orig 直链自行按 EXIF 转向（CSS image-orientation 默认 from-image），原图不处理；视频 display matrix 由 ffmpeg autorotate 常态可靠，不在此列。方向策略变更即本笔：**v2→v3 全量重建**（v2 键全部失效，旧文件变孤儿由对账清理）。
- 实现状态（2026-08-29）：**M2 UI 段随附后端已对齐**——ffprobe 探测内嵌封面（disposition.attached_pic）优先 → 35% 代表帧 → 黑/白扩散序列（35%→25%→45%→15%→55%→5%→65%→0ms），取不到时长短路 0ms、不重复取同一帧（毫秒精度去重）；缓存键升版本段使旧缓存全部失效重建。**性能分工（列表/详情实时显示用首帧、代表帧用于预生成缓存）M3 预留**：md 档预生成已落地（开机回填/库变更补齐/10min 周期兜底，thumbnailwarmup），按需同步生成兜底；『列表实时首帧/预生成代表帧』双管拆分仍未做，两条管道分派点已在 thumbnail.Generator 注释标注。
