# 浏览与分组展示规则

> 本专题是领域规则正文；[领域目录](../DOMAIN_RULES.md)保留原 §编号。公式与常量保持原义，标记「逐字遵守」者未经用户明确要求不得改变。

## 8. 浏览与分组展示规则

- 列表按日期分组标签：今天 / 昨天 / 周一~周日（距今 2~6 天）/ `yyyy-MM-dd` / 未知日期（无时间）。
- **组头计数必须是该日真实总数，不得用已加载条数**（2026-10-10 第五百一十三笔）：分页（`GET /assets` limit≤200）下同一天文件多时，组头若取「已加载条数」会随滚动一路跳增，第一眼看到的就是错的（真机实测：`今天 120→125`、`周三 66→282`）。数据源 = 服务端按**客户端本地日历日**聚合的精确计数（`GET /assets` 的 `dateCounts=true`，仅首屏计算；作品/角色维沿用 `/assets/facets` 排自身计数——修复D-1 口径，本笔补齐日期维）。**回退语义**：未命中（未请求/翻页未带/无 mtime 的「未知日期」组/服务端未覆盖的日）回退组内已加载条数——只准少报，不准多报。
- **日界时区口径**（同笔，2026-10-10 第五百一十四笔收紧）：`dateFrom`/`dateTo` 与 `dateCounts` 的分桶日界一律按客户端时区（`GET /assets` 的 `tzOffsetMinutes`，东八区=480，取值域 UTC−14~+14）；缺省不传 = 0（UTC），既有 UTC 日口径逐字节不变（向后兼容是加参数而非改参数的前提）。服务端 mtime 存 UTC、客户端按设备时区分组，两侧同键（`yyyy-MM-dd`）才能对齐；App 与 Web 都在 SDK 边界恒补该参数（设备属性，不是页面参数），调用点无处可漏。**固定偏移要求**：客户端算日键/日期标签必须用**请求里那一个固定偏移**（纯整数 `floorDiv(ms + offset×60000, 86400000)`），**禁止**改用该日期当时的历史时区规则（`Calendar`/`new Date` 本地规则）——夏令时区域夏冬偏移差 1 小时，同一日期会与服务端分桶键劈叉，导致查不到计数、回退已加载条数（原缺陷在夏令时区复现）。
- 网格列数用户可调（2~5 列），双指缩放即时生效，按页面记忆。
- 排序结果缓存指纹机制：`库大小+页签+周期+筛选态哈希+搜索词+seed` 变化才重排，滚动加载只取缓存（位置稳定不跳动）。
