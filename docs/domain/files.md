# 文件操作规则（新需求，2026-08-22 确认）

> 本专题是领域规则正文；[领域目录](../DOMAIN_RULES.md)保留原 §编号。公式与常量保持原义，标记「逐字遵守」者未经用户明确要求不得改变。

## 9. 文件操作规则（新需求，2026-08-22 确认）

- **上传**：手机/网页上传文件到库内指定目录；类型白名单（图片：jpg/jpeg/png/gif/webp/avif；视频：mp4/mkv/webm/mov/m4v/avi），单文件大小上限可配置（默认 2GB，`upload.max_bytes`/`QIMENG_UPLOAD_MAX_BYTES`）；原样落盘**永不转码**。目标同名文件存在时**自动重命名"基名 (2).ext"**（上传是批量采集通道，同名是常态；最终名以响应 relPath 为准）。media_type 分类与扫描器同口径（gif 单列 animated_image）。（本机自动同步通道（ADR-0030）入库同款复用本口径，不另设规则。）
- **移动/重命名**：走 API，更新路径属性，全部关联数据无感保留（见 ARCHITECTURE §6）。目标位置已有同名文件 → 409 拒绝（移动不覆盖，覆盖须显式分步）。cos 库在移动/改名后按新目录首段重算作者映射（§6「COS 作者清理与目录变更」）；normal 库按新文件名重算出出处/角色。
- **删除**：一律先进回收站（服务端管理的独立目录），可手动恢复或清空；物理删除仅回收站内的显式操作。保留判定口径默认 30 天（`filing.DefaultTrashRetentionDays` = `config.DefaultTrashRetentionDays`，两常量同值互指），可经 `trash.retention_days`/`QIMENG_TRASH_RETENTION_DAYS` 覆盖，trash 列表 ExpiresAt 按生效值返回。**到期自动清除已实现（2026-09-22）**：后台清扫按 `trash.sweep_interval`（默认 1h，`QIMENG_TRASH_SWEEP_INTERVAL`）巡检，超保留期条目物理清除（`filing.TrashExpired` 判定；retention<1 永不判过期——误配兜底），清除时联动清理该资产缩略图缓存（见 §11）。
- **恢复语义**（M2 实现，2026-08-27）：asset_id 不变（身份机制）；浏览/播放历史保留（ViewEvent 事件流无外键，ADR-0005 设计红利）；**标签/收藏/点赞绑定不随恢复还原**（删除时库行硬删、FK 级联清理，恢复=重建行）——已知限制，用户在意时给回收站 meta 加关联快照；原位置被占用时自动重命名"基名 (2).ext"（恢复永远成功，不因冲突失败）。
- **异常恢复实现约束（2026-10-19，ADR-0039）**：扫描不完整时保留全部破坏性差集并报告失败，已成功入库的变更照常广播。扫描与API文件操作仅在短提交段共用库锁；外部移动合并只消费扫描自身新建的身份，并事务提交。回收站恢复先保存目标/size/mtime意图，原ID重建成功后才清理meta；失败重试继续原落点，扫描不得抢注新ID，后台到期清扫不得丢弃未完成意图。size+mtime异常时保留文件及意图并报错，手动清空仍会移除回收站恢复依据。分片complete保留源且会话记住已发布路径，入库失败重试不得重复落盘；封存后拒绝PATCH。以上修复不改变同名自动改名、删除后不还原标签/收藏/点赞、会话重启失效的既定语义。
- **日统计恢复（2026-10-19，ADR-0040）**：恢复原资产基础行与该资产的事件日物化统计在同一写事务提交；仅按 asset_id 索引读取保留历史，失败保留恢复意图供重试。全量统计重建同样在持写锁事务内读取/聚合/替换，不能覆盖并发已提交增量。
- **新建目录**：库内任意层级。
- **文件名推荐与作品名序号联想（`SuggestSeriesNames` 纯函数，2026-10-09 智能推荐增强）**：
  - **三级匹配梯度**：Tier 1 前缀匹配（输入为文件名前缀）> Tier 2 多词 Token 全包含（输入所有 token 均包含在文件名中，如「法环 菈妮」命中「艾尔登法环 菈妮」）> Tier 3 子串包含（输入为文件名任意中段子串，如「法环」命中「艾尔登法环 玛丽卡」）；支持中段关键词检索。
  - **多风格序号解析与位宽保留**：解析半角/全角圆括号 `()`/`（）`、方括号 `[]`/`【】`、带标前缀（`No.`、`#`、`EP`、`Vol.` 等）；保留原始数字位宽与前导零（如 `01` -> `02`，`09` -> `10`），自动推导下一序号。
  - **主体聚类平权轮转（Cluster Diversity Round-Robin）**：基于角色主体/子实体提取聚类键，首轮各主体首选条目优先曝光（不同角色平等享有曝光机会，彻底杜绝单角色多子变体垄断全部槽位），次轮填补剩余高频变体。
  - **独立子实体智能推荐**：无序号独立角色（单文件角色）经词边界检验后智能推荐下一序号（基名 + 2）；剥离修饰符（如 `（特写）`）。
  - **容量上限**：推荐列表扩容为 8 条（`cap 8`）。
  - **别名/出处反查联想（2026-10-09 第五百零九笔）**：用户按「记得角色记不住出处」的习惯只输角色名/别名/出处昵称（`dva`/`女武神`/`老头环`）时，整名字面匹配零命中（真实库 7056 文件名实测命中数为 0）。反查引擎（`sourcematcher/related.go`，纯函数）把输入折成**模糊键**（去标点/分隔符/空白后小写——`D.Va`/`d.va`/`dva` 同键）后与内置 133 组的角色别名、出处变体比对，命中即返回结构化 `RelatedTerms`（角色规范名+全部别名、出处规范名+全部变体、汇总词）；`(m *Matcher) FindRelatedTerms` 走运行期索引快照，含自定义词表层。联想侧由 `extraQueries` 接住这批词：参与 cleanFuzzy 形态匹配（整名去标点前缀 / 多词 token / 去标点子串），且**关联词命中（梯队 >3）不受「无序号词边界过滤」限制**——库内单文件角色因此也能形成推荐。`GET /search/suggestions` 只消费其中的**规范名档**（角色 canonical + 出处 canonical）并逐条做库内存在性校验（候选词必须是库里真实存在的值，别名不是列值不补）。

## 作品名联想执行策略与性能边界

命名族仍按原匹配梯队/序号风格汇总，聚类键仍取「已有族键 + 半角空格」的最短前缀。实现对每个规范化族键沿空格边界由短到长查询现有族 map，命中即停止；不再让每个族遍历全部其他族。不能按任意字符前缀合并，不能把「角色甲乙」并入「角色甲」，也不能选择较长的中间层。匹配梯度、角色轮转、命中次数排序、序号推进及 8 条上限不变，无新依赖/缓存/协议变化。

合成纯函数基准（2026-10-20，Windows；每个族一个文件，q=共同出处，`-benchtime=500ms -count=3` 三轮中位数）：

| 命名族负载 | 原全族互扫 | 边界查表 |
|---|---:|---:|
| 500 个并列族 | 1.98ms | 0.78ms |
| 2000 个并列族 | 26.98ms | 3.33ms |
| 8000 个并列族 | 433.15ms | 18.15ms |
| 2000 个含多层前缀的族 | 37.55ms | 4.85ms |

该优化减少聚类 CPU 工作，每次堆分配基本不变；不能当作 HTTP/数据库取数/手机输入框延迟。既有完整建议结果与 1000 余键、8 种插入顺序的原聚类算法对照通过，包含多层前缀、相似非边界名称和中文/Unicode。

端点通过专用 `ListFileNamesForSuggestions` 仅装载目标库的 file_name，保留全量文件名及原输入顺序，不用 SQL LIKE 预截候选，停用/COS 库的原联想范围不变；扫描差集所需整行查询保持原职责。两万合成资产，三轮中位数：取整行再抽文件名 40.41ms→仅文件名 7.92ms，累计堆分配 46.27MB→2.48MB。此为 SQL/Go 解码装载，不含联想纯函数、HTTP、设备网络。词条预归一化规则及反查对照见 [匹配专题](matching.md#反查词条预计算与性能边界)。

## 上传目标与时间边界（ADR-0042）

Android 入队记录服务器 URL，直传/分片及挂靠固定同端，切服或旧任务缺目标时拒绝并提示重新入队；不自动重定向。已发请求可在原端完成，URL 不能识别同址更换实例。当前上传不传源文件系统 mtime，落盘使用接收时间；本机跨卷移动保留 mtime 不能证明 HTTP 上传保时。恢复与验证见 [RESTORE](../RESTORE.md)。
