# AI 平台后续优化与合并执行任务书

版本：1.0｜编制日期：2026-11-14｜状态：待交接执行。

本文件是用户要求交给另一个 AI 的执行任务书。本次编制仅写文档，不继续实现、测试应用、部署或合并。接手 AI 的目标是完成本文件规定的必要优化、验证、审查和最终合并，不能停在建议、草稿代码或“请用户再说继续”。

## 1. 目标、范围与结束条件

### 1.1 最终目标

让外部 AI 能在接入一次工具服务后，通过简短需求自行发现工具、读取相关规则和工作流，处理图片/视频研究、复用产物、执行获授权的业务操作，并在中断后安全恢复。保证未来接入其他 AI 宿主或迁入重构项目时，主要复用工具层和适配层，不复制 Go 业务规则。

**本次必须完成 S0–S6 和 M1–M5，最后合并 PR #60 或承接其全部变更的唯一后继 PR。** S7 是后续远程接入范围的拆分说明，本次不强制新增远程 MCP 服务。

结束时应同时成立：

- 必须实现项有源码、契约、对应文档和可复核测试证据。
- 标准 MCP 默认连接可调用业务工具，不依赖客户端动态刷新。
- 只给图片或视频即可启动只读研究；研究产物可以通过受控引用接续使用。
- 研究与业务写入分开；证据不足可正确结束为待核实，不编造作者或误写档案。
- 未决操作核验和预算续期有正式可信端入口，不再依靠临时脚本改内部状态。
- 工具层可从仓库外独立运行，有最小安装说明、依赖检查和来源清单。
- 当前最终代码的适用云端门禁与审查通过，按用户要求完成合并并核对远端 master。
- 临时凭据撤销、测试进程清理、原始数据守恒核对完成，交付报告如实保留失败及限制。

### 1.2 明确不扩展的范围

- 不实施仓外 Next 的 T01–T07，不重写应用、不顺手整理全仓、不升级无关依赖。
- 不重新设计 Telegram/微信消息机器人、动态订阅平台、模型托管或计费系统。
- 不修改推荐/统计/命名/身份等领域公式，不改变 COS 派生归属规则。
- 不为研究失败放宽 SSRF、路径隔离、鉴权、证据要求或验证码/付费访问限制。
- 不默认覆盖日常 PC、真实手机或 NAS。云端出包、隔离安装、生产部署分别记录。
- 不把“所有随机图片都能识别作者”当可保证指标；工作流必须能正确表达 unresolved。

### S1｜拆分纯素材研究与获授权写入（必需，优先）

参考实现：`recipes/author.discover.json`、`catalog.py`、`recipes.py`、`tools_research.py`、`tools_query.py`、`tools_author.py`。以下能力名称是设计意图，不是断言这些新接口已经存在；尽量复用现有ID，不为了命名统一破坏兼容。

要求：

1. 提供“作品研究”入口，输入可只包含图片/视频引用，作者名和profileChanges不是启动前提。媒体类型及实际可用研究能力自动检查，缺依赖给准确原因。
2. 研究输出至少区分：候选作者、作品来源、平台稳定ID/URL、采用的证据、证据等级、排除候选及原因、未解决条件、下一步可用动作。不可把转载页/标签/水印/同名账号当已确认作者。
3. 允许外部AI使用自己的公开搜索能力；项目提供抽帧/目录/受控写入等能力。不要强制所有搜索只能经过当前受限provider。
4. 视频按现行研究规范采样，先用最必要帧，避免无依据地逐帧上传；有缓存/已完成步骤时复用。图片研究不能因为没有视频duration而直接结束为“已研究”。
5. 研究阶段不新建作者、不改档案、不关联资产；可产出candidate/unresolved，不能补造nameHint或profileChanges来凑配方。
6. 独立写入阶段复用作者查重、prepare/planRef、revision、原子业务API与回读。保留人工字段保护及本次用户明确的字段修改范围；不扩大为覆盖整份档案。
7. 老`author.discover`调用保持明确兼容，或提供显式版本升级/迁移说明；禁止悄悄改变旧配方的输入和恢复语义。适时更新工具/配方/规则版本，旧计划按既有版本规则拒绝。
8. capability、context、任务卡和工作流描述与真实能力一致：只读研究与写入权限区分，planned/unavailable不呈现为已执行。

验收：无作者线索、仅一张图或一段视频可开始；输出可明确结束为unresolved；研究调用不写业务数据；已有作者被复用，拒绝同名误认和不同作者候选合并。

### S2｜统一研究产物引用与工具间衔接（必需）

2. 引用绑定实例/凭据或等价可信上下文、授权根、文件身份/摘要、有效期和适用版本；失效、文件替换、篡改、跨凭据/跨实例使用均明确拒绝。
3. AI可通过工具读取所需工件或把帧引用直接交给识图工具，不需知道本机绝对路径，也不需浏览源码或遍历磁盘猜产物位置。

### 5.2 独立模型测试要求

### 5.3 隔离、证据与成功判定

1. 默认合成媒体/对象保护确定性边界。真实样本沿用用户已授权的只读抽样→复制→隔离测试方式；不得把真实库/凭据整份复制给模型。

3. 改名/关联/恢复测试保留非空记录，比较原ID、文件内容、作者/标签关联、事件身份及必要时间字段；合法API引起的派生变化按业务规则区分，不用只比总数代替核对。
4. 截图、真实名称、作者答案、响应和完整日志只放本地忽略目录；公开报告只用合成标签、统计和来源版本。
5. 报告每场景首次结果/错误/额外提示/复测/回读，工具调用与协议错误、provider受限、脚本退出及模型限制分开。
6. 本机原生MCP由实现者手动调用的测试明确标0模型turn；它证明宿主接入，不冒充独立AI自主任务。
7. 外部网络不可控：离线确定性fixture验证候选/证据判定与失败行为；实际图片/视频案例仍各跑一次并记录。若只能unresolved，功能上可正确结束，但作者识别率/原帖确证记未通过或受限，不把它写成成功识别。不可反复扩大抓取强行凑成功。
