## 1. 推荐算法（10 维自适应加权评分）

### 1.1 十维评分公式【逐字遵守】

| 维度 | 设计权重 | 计算方式 |
|---|---|---|
| tagRelevance 标签相关性 | 0.22 | 每个标签在所有已浏览文件中出现频次，归一化后取该文件标签的平均相关性；标签相关性数据为空时默认 0.2（同 tagCollection 空默认 0.15 的防饿死设计，2026-09-07 补记） |
| tagCollection 标签合集 | 0.15 | 文件标签集与用户 Top-20 偏好标签集的 Jaccard 相似度（\|交集\|/\|并集\|）；为空时默认 0.15 |
| engagement 互动热度 | 0.10 | (viewCount + playCount) / 全库最大值，归一化 0~1 |
| recency 浏览时效 | 0.15 | 距上次浏览天数衰减：<1天=1.0，<3天=0.8，<7天=0.5，<30天=0.2，更久=0；从未浏览=0.3 |
| likeScore 点赞 | 0.05 | likeCount / 全库最大点赞数，归一化 0~1 |
| discovery 发现 | 0.20 | 1 − min(viewCount/5, 1)，浏览越少分越高 |
| freshness 新鲜度 | 0.05 | 入库时间衰减：<1天=1.0，<3天=0.7，<7天=0.4，<30天=0.2 |
| browseDepth 浏览深度 | 0.03 | totalBrowseSeconds / 全库最大时长，归一化 0~1 |
| randomFactor 随机扰动 | 0~0.30 | 确定性随机：(assetKey hash xor seed) 取 16bit / 65535 × maxRandom，**同 seed 可复现，禁止纯随机** |
| dailyPenalty 每日去重 | 0 / −0.8×n | 惩罚项不计入权重合计：今日已被展示 n 次则 −0.8×n，未展示为 0 |

固定权重合计 0.95（前 9 维）；最终分 = Σ(维度分×权重) + randomFactor − dailyPenalty。

### 1.2 自适应权重回收（数据空缺时自动重分配）

| 数据状态 | 回收 | 分配给 |
|---|---|---|
| 库内无任何标签 | tagRelevance(0.22)+tagCollection(0.15) | discovery ×50% + randomFactor ×50% |
| 无任何点赞 | likeScore(0.05) | freshness |
| 无浏览历史 | engagement(0.10) | discovery |

用户自定义权重作为**初始值**传入，回收逻辑仍然生效；数据完善后自动恢复设计权重。

### 1.3 用户可调权重与预设

9 维权重 + maxRandom 用户可调（「推荐偏好」设置页），提供 4 个预设：

| 预设 | tagRel | tagColl | engage | recency | like | discov | fresh | depth | random |
|---|---|---|---|---|---|---|---|---|---|
| 均衡推荐（默认） | 0.22 | 0.15 | 0.10 | 0.15 | 0.05 | 0.20 | 0.05 | 0.03 | 0.30 |
| 高记忆流行 | 0.15 | 0.10 | 0.20 | 0.25 | 0.10 | 0.05 | 0.05 | 0.05 | 0.10 |
| 深度探索 | 0.30 | 0.20 | 0.05 | 0.05 | 0.02 | 0.30 | 0.02 | 0.05 | 0.40 |
| 新鲜优先 | 0.10 | 0.05 | 0.05 | 0.10 | 0.02 | 0.25 | 0.20 | 0.03 | 0.35 |

### 1.4 排序后处理（既有机制，必须保留）

1. **视频/图片自然混合**：评分排序后按剩余数量比例随机交错取视频/图片，避免连续分组；代价是牺牲部分排序精度换浏览多样性（有意为之）。
2. **同分桶随机打散**：seed>0（下拉刷新）时，±0.05 分差内视为同桶，桶内确定性随机打散。
3. **每日展示计数**：服务端记录每个资产当日被推荐展示次数（当日零点重置），作为 dailyPenalty 输入；刷新不清零当日已展示计数。
4. **响应短缓存（2026-09-18 新增，server recommend_cache.go）**：推荐流带 60s TTL 响应缓存，键=（修订号, 日界, seed, mediaType, cosOnly, 权重快照, offset, limit）。语义边界：命中路径**仍对返回项回写当日展示计数**（上条口径不破坏，计数语义不变）；同键重复请求在 TTL 内返回同序（不按最新计数重排，旧行为是每请求重排）——累计的每日惩罚在下次未命中重算时统一生效；高频浏览事件（open/play/dwell）**不触发失效**，行为维度（engagement/recency）变化在 TTL 到期后自然反映；结构性变更（点赞/收藏/标签/库开关/扫描完成/上传/导入/文件整理/作者重建）**即时失效**（修订号作废）。缓存另设**开机预热**（recommend_prewarm.go）：起监听即后台预计算 App 首屏同键默认流（seed=1&limit=200&offset=0，与 App 端初始请求常量互指），并经单飞与首条请求共享同一次计算；**预热只算不服务，不写展示计数**（计数仍以真实展示为准，本条与上条口径均不因预热改变）。失效主通道=装配期订阅 library.changed 事件（watch 增量/扫描/上传/回收站/标签/整理/库开关全覆盖），周期轮询扫描零变更不发事件、缓存跨扫描存活。

### 1.5 冷启动原则

无历史时优先混合不同类型/作者/出处；从未浏览文件 recency=0.3 不被完全忽略；新文件靠 freshness 获得基础曝光。

## 2. 排行榜

- 热度 = **窗口内** open+play 事件计数 + 窗口内点赞计数，降序（2026-09-18 用户拍板：原「viewCount+playCount+likeCount 全量累计」口径废止——累计值不随周期变化，切换 7天/30天 榜单不变；窗口化后周期榜随窗口滚动，Web/App 共用的 GET /rankings 单点生效）。窗口内 open+play 计数取自「资产×日」物化表 asset_daily_stats（day ≥ cutoffDay 的 view_count/play_count 求和；事件流仍是唯一真相源，物化表可随时重建，见 §5/§10）；窗口内点赞计数取自 likes 表的「资产×日」行（likes 主键 (asset_id, day)，day ≥ cutoffDay 计数——表自带日粒度，无需降级口径）。cutoffDay = 服务器当前时间减去周期窗口所得时刻的本地日历日（YYYY-MM-DD，按日取界：cutoff 当日全天活动计入窗口）。
- period=all：热度 = 全量累计（view_events 全量 open/play 计数 + likes 全量行数），与旧口径一致，零窗口聚合开销。
- 准入过滤与窗口聚合自洽（2026-09-18 起）：非 all 周期仅保留「窗口内热度 > 0」的资产（窗口内存在 open/play/点赞任一活动）；原「lastViewedAt ≥ now − 窗口」时间戳准入口径随窗口化废止——按日取界下与窗口计数边界日不一致，以窗口计数为准。
- 同分按文件修改时间（mtime）降序不变（2026-09-07 勘误保留：实现口径 = assets.mtime，行为由 TestRank_tieScore_newerModifiedAtFirst 锁定）。
- 周期：日/周/月/年/季（近 90 天）/总（period=quarter 为 2026-09-03 新增档位）。
- 排行不使用个性化推荐，纯热度。

## 3. 筛选体系（枚举全表）

筛选同时作用于搜索结果（搜索词与筛选叠加生效）。

| 区域 | 选项 |
|---|---|
| 搜索词 | 全文搜索 q：空格分词；多词 AND；每词子串匹配任一维度 |
| 排序 | 默认、文件日期、添加日期、观看次数、播放次数、文件大小、名字、收藏时间（仅收藏筛选时语义成立） |
| 顺位 | 降序、升序 |

**「默认」排序的语义 = 文件日期（mtime，2026-09-17 晚拍板）**：等价于「文件日期」档，与「添加日期」（入库时间）档区分。历史：M1 起服务端把 `sort=default` 回退为 addedDate 的**临时占位**（本想让推荐算法当默认，未成行）；2026-09-15 曾改相册端默认档为文件日期，2026-09-17 上午精简面板三档时随「缺省档=默认」退回占位语义；当晚用户实测单机形态（整批一次性扫描入库的库，入库时间趋同且顺序=扫描顺序）默认相册被扫描顺序支配——同目录类型整段聚堆，跨端表现随机。定为文件时间：任何库（新旧、整批/增量）默认视图都按媒体自身新旧有序，与旧版绮梦影库「全部」页口径一致。
| 观看次数 | 全部、未观看、1-5、5-20、>20 |
| 播放次数 | 全部、未播放、1-5、5-20、>20 |
| 文件大小 | 全部、<1MB、1-10MB、10-50MB、>50MB |
| 时间范围 | 全部、今天、本周、本月、近三月、本年、按年份区间选择 |
| 点赞 | 全部、已赞（likes 表存在任意日行）、未赞 |
| 标签模式 | 模糊（任一命中即显示）、精确（全部命中才显示） |
| 标签 | 多选 |
| 分区/作品/角色/作者 | 来源匹配引擎与作者体系产出的维度 |

**多值筛选（2026-09-09 协议批）**：GET /assets 与 GET /history 的 `source` / `character` / `work` 为**数组参数**（query 同名重复或生成器数组语法展开）——**同维内 OR**（命中数组内任一值即入选）、与其余筛选维 AND；`source` 数组可含「其他」桶（NULL source 的常规文件，`?source=站点甲&source=其他` 合法）；`character` 每个元素仍是组合表达式（`天使+黑百合` 组内全部命中不变，§4 分隔符语义），数组内多组合 OR。**单值 = 单元素数组，与旧单值协议向后兼容**（GET /history 另增可选 `source`/`authorId`，语义同 GET /assets）。公式常量与排序/分桶口径不受本批影响。

### 全文搜索口径（q 参数，FTS5 实现）

- **分词**：按空白（空格/制表）拆分，每个非空片段为一个关键词；全文为空白时视为不启用搜索（返回全量）。
- **分区**：搜索叠加 §6 COS 三态开关——**缺省全部（常规∪COS，2026-09-04 用户拍板变更，原第五笔（历史档）"搜索默认排除 COS"口径就此废止：库内容大头是 COS，默认排除致多数搜索词零结果）**；`cosOnly=1` 只要 COS；「常规」=不传参（主动切换才排除 COS）。Web 搜索页以「全部/常规/COS」分区胶囊呈现、类型徽标计数同口径（2026-09-04 第十六笔（历史档）补入口）。
- **组合**：多词 AND——每个关键词都必须命中（旧项目 applyFilter 语义）。
- **命中维度**（每词命中其中任一维度即算命中）：
  1. 文件名（file_name）
  2. 文件夹路径（rel_path 的目录段，含多级子目录；根目录文件此维度为空）
  3. 标签（该资产全部标签名）
  4. 作者（常规/COS 双体系的 display_name）
  5. 角色（asset_characters 的角色规范名）
  6. 出处（source 规范名，未命中出处的资产此处为空）
- **匹配方式**：任意长度的**子串**匹配（contains 语义，含单字/两字中文词）；ASCII 大小写不敏感（"dva" 匹配 "DVA"）；`%`、`_`、`\` 是普通字符（无 LIKE 通配语义）。
- **叠加**：搜索与 §3 全部其它筛选（排序/顺位/次数/大小/时间/标签/出处/角色/作者/收藏）以 AND 叠加；分页（keyset 游标）与 totalMatched 在搜索下与未搜索时口径一致。
- **索引**：SQLite FTS5 trigram（migrations/0002_search_fts），由迁移触发器按写路径增量维护，业务代码不直接写索引；查询侧用 instr 子串（trigram 的 MATCH 不支持两字短词，2026-08-29 SQLite 3.53.3 实测后定案；性能基准 3 万行文本 <150ms/词）。
- **出处列表端点（GET /sources）**：按出处规范名分组的文件计数，name=null 表示无出处文件（显示层兜底"其他"），按 fileCount 降序；口径与资产列表一致——默认排除 COS 作者关联文件（§6 隔离口径），includeCos=true 重新包含。
- **相册四维聚合端点（GET /assets/facets，2026-09-03 第三笔（历史档）建 / 第五笔（历史档）语义修正）**：分区/作者/角色/类型四维候选计数——partitions 恒三项（all/regular/cos，regular=all−cos）；types 固定 all/image/animated_image/video 四项（key=MediaType 枚举值，可直接回传 GET /assets 的 mediaType）。**作者行 = 常规出处分组 ∪ COS 作者**（第五笔（历史档）拍板，替代原 authorId 全量作者；= 旧版「全部」tab「作品」行的 groupBySource(!isCos) ∪ groupByCosAuthor(isCos) 合并口径）：常规分区只出处、COS 分区只 COS 作者、all 分区两者合并；出处分组只统计**非 COS 关联**资产（NULL source 行=用户侧「其他」桶，且 COS 关联资产永不落入——source_is_other 谓词含 NOT EXISTS cos 排除，browse.sql/source 口径一致），常规 TXT 作者表行不进本行。**角色行**：常规分区=角色规范名（key 回传 character）、COS 分区=cos_work 作品名（key 回传 work，NULL 不列入，前端兜底）、all 分区=两者合并（COS 作品进角色行）。每行候选带 **kind**（source/author/character/work）=回传哪个筛选参数（同一行混合两种候选时前端按 kind 分派）。**排自身口径**：计每维候选时忽略该维自身当前选择——前端每维独立请求各缺自身参数；服务端把 source/authorId 对全部行**照常作为收窄条件**（2026-09-09 协议批修订，原「source 与 authorId 同属作者行一起忽略」口径废止——作者集合页固定传 authorId 即可让作品维候选按作者收窄，#34 闭环）。**子集计数（2026-09-05 S-1）**：`favorite` / `history` 是子集约束非四维之一——favorite=1 只统计收藏资产（与 GET /assets favorite=true 同义）、history=1 只统计存在 kind='open' 浏览事件的资产（「浏览历史」口径）；传入时对**全部四维（含分区栏）**统一收窄统计口径（如 favorite=1 的分区芯片=收藏子集内 all/regular/cos），四维之间仍按排自身口径互算。COS 三态开关口径见 §6。
- **搜索框补全端点（GET /search/suggestions，2026-09-05 S-1 批次新增，LEGACY §C + 用户 3B 拍板）**：五维候选 = 出处 / 角色 / COS 作者 / COS 作品（assets.cos_work）/ 常规作者；q 对候选名做子串匹配（contains 语义，ASCII 大小写不敏感，同本节匹配口径；`%`/`_` 无通配语义）。五维合并去重——**同维同名只一条、跨维同名各保留**（`type` 字段 = source/character/cosAuthor/cosWork/author，即前端类型徽标的分派语义）；排序 = **名称长度升序、再名称字典序**（短名优先，贴近补全直觉）；limit 默认 10、上限 50；**作者维只返回实际有关联文件的作者**（LEGACY §C：零关联作者行对补全无意义；回收站删除即移出 assets 表，作者随之失去候选资格）；COS 作品 NULL（无作品子目录）不产生候选；**q 为空（trim 后）且未开 recommend 时返回空列表；recommend=1 且 q 为空时返回随机抽取的五维候选合并 ≤limit 条**（旧版「推荐搜索=名字索引随机取 10 条」语义，2026-09-05 用户拍板对齐；实现=五池各 ORDER BY random() 后轮转交错合并，任一维缺货由其余维填满；q 非空时 recommend 被忽略、照常子串匹配）。

## 4. 出处与角色匹配引擎（SourceMatcher 规则）

- **结构**：SourceGroup = 规范名 canonical + 变体列表 variants + 角色列表 CharEntry(canonical + 别名)。变体含中文名（带/不带空格）、英文名、常见缩写。
- **版本合并**：同系列不同版本归入同组，版本号进 variants（铁拳7/8→"铁拳"；生化危机2/3/4/8→"生化危机"）。
- **匹配流程**：去扩展名 → 去空格折叠 → 小写 → 变体按**长度降序**前缀匹配（最长优先）→ 未命中归"其他"。"其他"永远排在列表最底部——指**展示层**分组/分区列表的约定（旧版 UI 行为；服务端 /sources 端点按 §3「fileCount 降序」返回，name=null 行的沉底由客户端展示层负责，2026-09-07 澄清）。
- **角色匹配**：先匹配出处 → 从文件名中剥离开头出处部分（带数字保护：`^\d+(?![a-zA-Z])` 不剥 "2B"、"9S"——Go RE2 无负向先行，实现为等价手工扫描：单数字+字母与 PCRE 语义一致，多位数字+字母整段保护（"12ab" 全保留），2026-09-07 补注）→ 剩余部分在该出处角色别名表做子串匹配 → 多角色按 canonical 字典序 "+" 拼接；分隔符 `+`/`x`/`&` 天然支持。
- **命名规约兜底提取**（2026-10-03 新增，ADR-0033 配套第二层）：收藏命名高度统一（`出处  角色名 序号.扩展名`），别名表未收录的新/冷门角色由本层兜住——词表从此只需维护**出处与改名映射**，不必逐角色补词条。规则：**别名表命中非空时结果完全以表为准**（本层不参与，零回归）；表零命中时，把剥离出处后的剩余串按空格分词、词内再按 `+`/`&` 拆分（裸 `x` 词作分隔词丢弃），自左向右收集——**纯数字词或纯括号序号词（如 `(1)`）终止收集**（序号及其后是描述词，不是角色名）；普通词命中本出处别名表则取其 canonical（改名/归一，如 `Dmon`→`D.Mon`），否则按原词入库；**以数字开头且后跟 ASCII 字母的词（"2B"/"9S" 形）仅当别名表认识它才保留**（防 "8K"/"1080p" 类画质词混入角色）。结果去重后按字典序排序。（2026-10-03 用户拍板备注口径，二次修正：**序号之后无论加什么都是纯备注**，只留在文件名显示、永不进胶囊；角色位上的描述词〔「触手」「白丝」「婚纱」这类〕同备注处理、也不进胶囊——它们与真角色名同形，位置规则无法区分，经**停用词表**过滤：兜底提取跳过命中词〔精确匹配、跳过不终止〕。停用词表 = 内置冻结基线〔触手/白丝/婚纱/多角色/多角色酒吧〕+ 词层可扩（custom-groups 端点 `stopWords` 可选字段：PUT 缺省=保持现值、显式空数组=清空回内置基线；kv_settings `custom_stop_words`）。停用词只作用于兜底提取层，别名表层（人工维护的检索表）不受影响。）
- **引擎版本自愈重算**（2026-10-04 新增）：兜底提取/停用词等引擎语义升级后，已入库资产的富化结果不会随扫描自然刷新（size+mtime 未变即跳过）。服务端启动时比对 kv 版本标记 `enrichment_engine_version` 与代码内引擎版本常量：标记落后（含无标记的存量部署）→ 后台对全部常规库自动 RecomputeEnrichment 一次并落新标记；标记持平则跳过（幂等，每次启动只多一次 kv 读）。词表端点触发的重算语义不变；本机制保证内嵌（App 单机）/桌面壳/NAS 各部署形态在引擎升级后开箱自愈，不依赖端点与鉴权（内嵌形态 dev 登录受一次性密钥保护、外部不可调，2026-10-04 实证）。
- **多出处**：文件名含 "+" 时分段分别匹配合并。
- **唯一标识**：出处+角色名（跨出处同名角色是不同角色）；例外：单文件多出处（文件名含 "+"）命中同名角色时按角色名去重合并显示——asset_characters 主键为 (asset_id, 角色名)，出处归属不落库（2026-09-07 补注）。
- **用户自定义出处**：用户手动添加的分区名自动加入识别。管理端点 `GET/PUT /api/v1/sources/custom`（整体替换，空数组=清空；写入后运行中匹配引擎立即生效，且服务端自动对全部常规库存量资产重算出处/角色——资产 size+mtime 未变时全量扫描只跳过，**必须显式重算**才能传导到已入库 source 列，不依赖重扫）。
- **用户自定义出处组**（ADR-0033，2026-10-03）：带角色检索表的词层，管理端点 `GET/PUT /api/v1/sources/custom-groups`（整体替换，空数组=清空，kv_settings `custom_source_groups`，存储形态=引擎输入形态）。与内置 130 组及裸名层按 canonical **合并**：同名=并入（变体追加、同名角色扩别名），新名=追加新组；服务端规范化（trim/去空/去重/重复 canonical 取首个/**canonical 自并入自身变体与别名**）。生效与存量传导同「用户自定义出处」（引擎同步替换 + 后台全常规库重算）。**内置 133 组冻结为基线**（2026-10-04 一次性固化用户首批审定词条 130→133：守望先锋+D.Mon、铁拳+风间明日香别名/风间准、最终幻想+阿拉尼雅、新组 怪物猎人·杰玛/战锤40k·战斗修女/初音未来——动机=内嵌形态词表端点受一次性密钥保护、kv 无法跨部署同步，固化使各端引擎级一致，配引擎版本自愈自动生效；此后增补词条仍一律走本词层，不再改代码扩表）；裸名与内置组同名时角色表不因裸组覆盖而丢失。
- **性能**：匹配结果按文件名缓存；批量场景 O(1) 命中。
- **内置检索表**：旧版 130 个 SourceGroup（游戏/动漫/影视，仅收录女性角色——本项目核心场景；2026-08-30 整表翻译时实测旧源文件恰 130 组，此前文档记 131 系把 data class 定义行误计，已勘误）。迁移时整表翻译，后续增补遵循旧版「查重优先/规范命名/别名完整/长度降序」四原则。
- 匹配发生在**服务端扫描入库时**（新架构下为服务端职责，非客户端）。

## 5. 统计口径

- 图片 viewCount：进入详情页 +1，**同一会话内只计一次**（横滑切走切回不重复计）。
- 视频 playCount：点击播放 +1，同会话只计一次（play 事件覆盖面=播放器起播路径 ∪ 原生 video play 兜底，同一次起播客户端防重只报一条；暂停后重新起播属新起播、逐条上报，同会话当日的重复起播去重由服务端幂等吸收）。
- 浏览时长：详情页停留秒数（段级上报：一次连续停留=恰好一条 dwell 事件，页面隐藏期间不计入；**不足 1s 的停留段不上报**——2026-09-12 W6 #45 用户拍板回退 V5 口径 B，恢复原口径：浏览 open 事件已计入访问，快速划过的零值停留段冗余、不上报）；秒数整数口径（2026-09-20 闭环）：客户端可上报小数秒，服务端入库时逐事件向零截断为整数（engagement.go int64 转换），聚合链路全整数。
- 点赞：每资产**每日可赞一次**，次日重置；累计 likeCount 永久保留。
- 收藏/关注：布尔标记，无次数。
- 底层数据 = **ViewEvent 事件流**（只追加），一切统计从事件聚合；按天聚合表是物化视图（可随时从事件流重建）。**唯一真相源口径 = 按「文件×天」聚合**（每文件每天一行，无限保留），数字卡、趋势、窗口排行全部同源同口径，主页面与详情页一致。
- **趋势图「全部」分桶口径**：按数据实际跨度动态选粒度（≤12 周按周 / 12 周~24 月按月 / 更长按季），从最早数据铺到当前周期**全量不丢弃**，各桶之和 = 全量总和；周对齐用"距周一回退"法（从周一算起，与系统 locale 无关）；数据不足 2 个周期时补前导 0 桶保证折线可画；空数据显示"暂无趋势数据"。
- **趋势图固定 range 窗口表**（GET /stats/trends 的 range 枚举，2026-09-03 补全）：day=近 30 天逐日、week=近 12 周、month=近 24 月、quarter=近 8 季、year=近 5 年、**7d=近 7 天逐日、90d=近 90 天逐日**（7d/90d 为 2026-09-03 新增档位）、all=「全部」动态粒度（见上）。
- **统计聚合榜单口径**（GET /stats/most-viewed、/stats/top-authors、/stats/top-tags，2026-09-09 协议批 P2 新增；range 窗口一律复用上方固定窗口表，起点=窗口首日本地日历日 00:00，all=不设窗口）：
  - **常看文件**：metric=views = 窗口内 kind='open' 事件次数倒序；metric=seconds = 窗口内 dwell 事件 seconds 累加倒序，**无 dwell 事件的文件不参与 seconds 榜**；榜单响应与 metric 对应（value 字段统一承载）。
  - **常看作者**：窗口内该作者关联资产的 open 次数倒序；资产×作者多对多，一次 open 对每个关联作者各计一次；**COS 作者按其 COS 关联资产计**（asset_authors 对 COS 作者只含 COS 关联，前缀隔离天然成立，无需额外过滤）。
  - **常看标签**：窗口内带该标签资产的 open 次数倒序（按标签名聚合）。
  - **现存资产限定**：三个榜单一律内连接 assets——事件流无 FK、可能引用已删资产（ADR-0005），其历史计数仍由总览类纯计数承载，但榜单须返回文件信息，已删资产不可入榜。
  - **同分 tie-break** = 主键字典序升序（assetId/authorId/tag 名），保证分页与跨端渲染排序确定。
- **来源桶口径**（/stats/trends 的 source 参数与 /stats/overview 的 sourceNormalCount/sourceCosCount，2026-09-09 协议批 P2 新增）：**引用 §6 既有分区判定，不新造口径**——normal=不关联 COS 作者的资产（NOT EXISTS asset_authors×authors type='cos'）、cos=关联 COS 作者的资产（EXISTS 同谓词）；库存两计数之和恒等于 totalFiles。
- **平均浏览次数**（/stats/overview 的 avgViewsPerFile，2026-09-09 协议批 P2 新增）：窗口内现存资产的 open 事件总数 ÷ 窗口内至少一次 open 的**不同**现存文件数；窗口由 overview 的 range 参数决定，缺省 all=全时段累计口径；**分母 0 → null**（不返回 0，空库/无浏览的空态语义）。
- **分类型大小**（/stats/overview 的 per_type_size_bytes，2026-09-14 新增）：现存资产按 media_type 分组各求和 size_bytes，键=image/video/animated_image 三协议值；image 键**不含** animated_image（与 imageCount「动图并入图片」的计数口径不同——大小是物理占用，动图独立成键才可与分类型行各值对账，per_type 各键之和 = totalSizeBytes）；空库/该类型无资产 → 0。
- **分来源大小**（/stats/overview 的 per_source_size_bytes，2026-09-14 新增）：现存资产按来源分区各求和 size_bytes，键=normal/cos；**引用 §6 既有分区判定，不新造口径**（与 sourceNormalCount/sourceCosCount 同谓词：normal=不关联 COS 作者、cos=关联 COS 作者），两键之和 = totalSizeBytes；空库/该来源无资产 → 0。

## 6. 作者体系（两套隔离的来源）

| 维度 | 常规作者 | COS 作者 |
|---|---|---|
| 创建方式 | TXT 导入 | COS 目录扫描自动创建 |
| 标识 | generateAuthorId 规则 | 同规则 + `cos_` 前缀 |
| 关联方式 | 文件名匹配（精确 + 序号括号容错，如 `(1)`/`(2)`）。精确 = 基础名（去扩展名、去空格）一致，且**作品名带媒体扩展名时文件扩展名必须同名**——png/mp4 同基础名各归各（旧算法扩展名检查，2026-09-05 实机回归修复；「带媒体扩展名」判定集合 = §9 索引白名单 ∪ wmv/bmp/svg/tiff/tif，大小写不敏感，2026-09-07 补记） | 扫描时记录 author→files 映射 |
| 同名冲突 | 前缀隔离，不冲突 | 前缀隔离，不冲突 |

- authorId 生成：保留中日文 Unicode，去特殊符号，空格转下划线，转小写；清洗后为空用哈希兜底。
- 作者只管理：ID/别名、显示名、关联文件。不管来源网址/外部链接。
- 文件与作者多对多；删除作者保留文件，删除文件清理关联。
- **关注作者（follow）**：关注是作者维度的布尔标记（无次数、取消即清除，口径同 §5 收藏/关注），`PUT /authors/{id}/follow` 设置/取消；取消关注不删除作者及其文件，仅清除标记。
- **TXT 导入**：支持三种格式（旧版格式 A/B/C 自动识别）；导入与重新匹配以「全部已导入 TXT 统一重建」为语义（跨 TXT 同名作者关联取并集，禁止单 TXT 覆盖）；新文件入库后自动触发重新匹配。具体格式定义迁移时从旧仓库 `GUIDE_AUTHOR.md` 抄录为服务端解析器测试用例。
- **COS 目录结构**：`作者/文件`、`作者/作品/文件`、`作者/作品/子目录/文件` 三种；作品名取目录名（folderName 覆写规则）；作品名落库 `assets.cos_work`（migration 0008：rel_path 第二段，扫描入库与作者关联重算两条路径维护，NULL=无作品子目录，部分索引 idx_assets_cos_work）——/assets 的 `work` 筛选与 facets COS 分区角色维的数据源；**COS 卡片标题（2026-09-05 用户拍板）**：AssetSummary 增可空 `cosWork`，客户端卡片标题优先作品文件夹名、null 回退 fileName（COS 卡不显示裸文件名）。COS 文件不出现在常规浏览流：首页推荐默认排除 COS 作者关联文件；**收藏/历史缺省改为全部=常规∪COS（2026-09-05 用户拍板变更，原「收藏/历史默认排除 COS」口径就此废止；显式 includeCos=false 切常规分区、cosOnly=1 切 COS 分区）**；搜索页 2026-09-04 用户拍板改为默认全部=常规∪COS（见 §3 分区条）；/assets 非收藏流缺省排除不变（协议侧 includeCos default 仍为 false，收藏流特例由服务端分支实现）。COS 有独立入口：**首页 cos tab = COS 推荐模式（2026-09-05 用户拍板，对齐旧版首页 COS chip「COS 推荐模式」语义——GET /recommendations?cosOnly=true，同一套十维打分/权重回收/每日惩罚跑在 COS 关联资产子集上，原「纯浏览流 addedDate 降序」实现就此废止）**、/assets cosOnly=true（分区浏览参数）。**例外：相册页 = 旧版「全部」tab 语义**——缺省「全部」分区常规∪COS 同流展示（作者行=出处∪COS 作者、角色行=角色∪作品合并可见），隔离浏览用「常规/COS」分区胶囊（第五笔（历史档）用户拍板）。
- **COS 作者清理与目录变更**：扫描收尾与增量删除后自动清理孤立 COS 作者（作者目录文件全部消失后残留的零关联行——旧项目 deleteOrphanCosAuthors 语义）；作者目录改名/文件移出目录时，作者映射沿移动路径重算（API 移动/改名与扫描移动合并两条路径都按新目录首段刷新），旧作者随之孤立被清。

### 作者挂靠编辑与通用来源词表（2026-09-25）

> 本小节前身「上传挂靠与作者来源」（同日，ADR-0023）——上传协议可选挂靠参数（`authorId`/`authorName`/`source`）随 ADR-0024 **退役删除**，上传回归纯上传；挂靠入口迁资产编辑页，TXT 真相/同事务/重导入保护语义不变。以下为现行口径。

- **片段本体是唯一真相**：作者关联与来源的一切程序化变更**直接写进已导入 TXT 片段本体**（原地变更）——写入内容与手工片段同构（同一解析管线可原样读回），任何统一重建/重放后**不丢不重**；片段之外不设第二套存储（kv `imported_txt_upload_entries` 仅是重导入保护的比对依据，非真相）。落点规则（编辑端点与原上传挂靠共用，禁复制粘贴）：既有作者并入其作者块所在片段（数组序第一个）；新作者/不在片段的既有作者并入最近导入片段；库中无任何片段时自动建「上传自动挂靠.txt」（`authoring.AutoFragmentFilename`）。
- **编辑端点三件套（ADR-0024）**：
  - **PUT /assets/{assetId}/authors**（body `{authorIds}`，整体替换资产作者关联）：提交的 authorIds 就是该资产的作者全集（空数组=解除全部常规作者关联）。新增=把资产**当前文件名**作为作品行追加进对应作者块（落点规则同上；作品行/来源行已存在不重复追加，幂等）；移除=遍历**全部**片段删除该资产的作品行（行文本精确匹配优先、trim+小写+去空格归一匹配回退——**归一保留扩展名**，png/mp4 同名互不误伤）；同事务更新 asset_authors；200 回 AssetDetail（authors=替换后全集）。仅 `Library.capabilities.authorAttach=true` 的库可用（否则 400）。
  - **GET/PUT /authors/{authorId}/sources**（常规作者片段来源区读写）：GET=作者块所在片段的「来源/出处」区词列表（无块=空数组；作者不存在 404；COS 作者 400——挂靠/编辑是 TXT 常规作者体系能力）；PUT 带 `mode`（落点规则同上；写出内容与手工片段同构、可被解析器原样读回；校验同通用来源词表）——`mode=replace`（缺省，编辑页语义）=整体替换该作者块来源区；`mode=append`（上传流程自动挂靠语义，ADR-0024 修订）=并入去重、永不覆盖既有来源（对齐 ADR-0023 原上传来源口径，重复提交幂等零写入）。
- **上传流程自动挂靠（ADR-0024 修订，2026-09-25）**：上传协议保持纯上传（无挂靠参数）；App 上传流程在单文件 201 后由客户端依次调用 PUT /assets/{assetId}/authors（authorIds 单项——新上传资产零关联，无覆盖风险）与 PUT /authors/{authorId}/sources（**mode=append**，不覆盖作者既有来源）。挂靠失败**不重试上传**（重试=文件重复入库），条目落「已入库待挂靠」态、由资产编辑页补挂；TXT 真相同步/镜像刷新与编辑端点完全同链路。批次默认（库/作者/来源）持久化、入队时刻快照继承；暂存列表/逐项编辑已随 2026-09-29 直传化退役，选完即传。
  - **GET/PUT /authors/source-vocabulary**（通用来源词表）：kv_settings `author_source_vocabulary` 持久化；GET 无记录=空数组；PUT 整体替换——提交列表 trim+去重后即生效词表（空数组=清空），单项含控制字符或超 500 rune 400 INVALID_PARAM，**原始数组超 32 项 400**。**出厂自动预填一次**（2026-09-25 上传暂存批）：kv **键不存在**时（从未预填且用户从未 PUT——PUT 恒写键，清空也写空数组，故用户清空不会被预填复活），从全部片段来源区统计每个词被多少**不同作者**引用，保留 **≥2 位作者共用**的词（单作者个人地址排除）、排除链接形态（含 http/www. 或含点号的域名形态），按 authorCount 降序、name 升序取前 20 写入；无合格词不写键（未来片段导入后自然重试）。
- **kv 上传条目修剪**：编辑变更成功后同步修剪 `imported_txt_upload_entries`——**修剪方向=内容中已不存在的登记条目才剪**（编辑是有意变更，防同文件名重导入 409 误报）；编辑**不新增**登记条目，故重导入保护此后只覆盖存量条目（上传退役前写入的）。
- **作品行记录最终落盘文件名**：冲突自动重命名后的最终名——重放等价（作品行被 MatchWorks 规则 1 精确命中），挂靠后关联立即可见。
- **来源=「获取渠道/平台名」，不是 §4 的作品出处**：来源词（如「论坛乙」）进入作者片段来源区，**仅记录、永不参与匹配**；**来源建议唯一数据源 = 通用来源词表**（服务端手动维护的小清单，Web 设置页维护卡收编自由输入的新词；个人片段来源区词表退出建议场景——作者各自的个人链接对他人无意义）；与 §4 资产出处分区（SourceMatcher/custom_sources）互不相干，禁止混用。
- **重导入保护（现状）**：同文件名清单重导入且新内容缺少上传写入条目时不静默丢弃——缺省 409 二选一（`TxtImportConflict` 只列缺失项）；`conflictResolution=keep` 自动并回后替换落库、`=remove` 明示移除（元数据一并清除）；格式 C 不存片段不触发。保护范围=kv 存量登记条目（见上「kv 上传条目修剪」）。
- **镜像单向尽力而为**：GET/PUT /authors/mirror 配置本地 txt 绝对路径（空=关闭默认）；服务端→本地单向投影（本地手改会被下一次服务端变更覆盖），临时文件+rename 原子写，失败仅告警绝不阻塞/回滚核心操作；挂点=资产作者/来源编辑保存后/TXT 导入落库后（含 keep/remove 结果）/片段删除后/镜像配置保存后，rebuild 不改片段不挂。
- **已知缺口（记档，不修）**：① 资产改名/移动不回写片段作品行（既有行为）——按当前文件名匹配不到的残留行会被统一重建重新关联，后续项=改名同步片段行；② 同片段跨块同名作者 RemoveWorks 只清首遇块（与解析器身份口径一致，统一重建兜底）。

## 7. 标签/收藏/点赞/时间轴

- 标签：全局池 + 文件多对多；模糊/精确两种筛选模式；浏览中新标签自动入池；删除标签清理全部关联（级联）。
- 标签**不写入媒体文件**（元数据只在库内）。
- **标签排序**：标签列表（GET /tags，筛选面板等非详情场景）按**名称升序**返回；资产详情页 tags 按**关联时间倒序**（最新添加置顶）——PUT /assets/{id}/tags 为整体替换，每次替换即刷新全部关联时间（替换即置顶，重添加天然置顶）；同批毫秒内按标签创建时间倒序 tie-break。**逐条解除**（DELETE /assets/{id}/tags/{tag}，2026-09-09 协议批 P2 新增）：只删该条关联，**其余关联的 created_at 一律不动**（旧版「chip 关闭即时移除单条」语义，不触发整体替换的时间刷新）；幂等 = 标签存在但未挂载 → 204，资产不存在或标签池无此名 → 404。
- 收藏：布尔标记集合。
- 关注：作者维度的布尔标记（对象是作者而非文件），语义见 §6「关注作者」；与收藏同为无次数布尔量（§5）。
- 点赞：见 §5；排行榜热度含点赞数。
- 时间轴标签：视频内时间点标记（assetId + 毫秒 + 名称），与文件标签完全独立的体系；点击跳转回看。**颜色协议化**（2026-09-09 协议批 P2）：标签对象增可选 `color`（hex 6 位，如 `#d6336c`），创建/更新/响应三处透传；缺省 = 服务端不存颜色、客户端自兜底；**预设类型不入协议**（客户端按 color 自持）。

## 8. 浏览与分组展示规则

- 列表按日期分组标签：今天 / 昨天 / 周一~周日（距今 2~6 天）/ `yyyy-MM-dd` / 未知日期（无时间）。
- 网格列数用户可调（2~5 列），双指缩放即时生效，按页面记忆。
- 排序结果缓存指纹机制：`库大小+页签+周期+筛选态哈希+搜索词+seed` 变化才重排，滚动加载只取缓存（位置稳定不跳动）。

## 9. 文件操作规则（新需求，2026-08-22 确认）

- **上传**：手机/网页上传文件到库内指定目录；类型白名单（图片：jpg/jpeg/png/gif/webp/avif；视频：mp4/mkv/webm/mov/m4v/avi），单文件大小上限可配置（默认 2GB，`upload.max_bytes`/`QIMENG_UPLOAD_MAX_BYTES`）；原样落盘**永不转码**。目标同名文件存在时**自动重命名"基名 (2).ext"**（上传是批量采集通道，同名是常态；最终名以响应 relPath 为准）。media_type 分类与扫描器同口径（gif 单列 animated_image）。（本机自动同步通道（ADR-0030）入库同款复用本口径，不另设规则。）
- **移动/重命名**：走 API，更新路径属性，全部关联数据无感保留（见 ARCHITECTURE §6）。目标位置已有同名文件 → 409 拒绝（移动不覆盖，覆盖须显式分步）。cos 库在移动/改名后按新目录首段重算作者映射（§6「COS 作者清理与目录变更」）；normal 库按新文件名重算出出处/角色。
- **删除**：一律先进回收站（服务端管理的独立目录），可手动恢复或清空；物理删除仅回收站内的显式操作。保留判定口径默认 30 天（`filing.DefaultTrashRetentionDays` = `config.DefaultTrashRetentionDays`，两常量同值互指），可经 `trash.retention_days`/`QIMENG_TRASH_RETENTION_DAYS` 覆盖，trash 列表 ExpiresAt 按生效值返回。**到期自动清除已实现（2026-09-22）**：后台清扫按 `trash.sweep_interval`（默认 1h，`QIMENG_TRASH_SWEEP_INTERVAL`）巡检，超保留期条目物理清除（`filing.TrashExpired` 判定；retention<1 永不判过期——误配兜底），清除时联动清理该资产缩略图缓存（见 §11）。
- **恢复语义**（M2 实现，2026-08-27）：asset_id 不变（身份机制）；浏览/播放历史保留（ViewEvent 事件流无外键，ADR-0005 设计红利）；**标签/收藏/点赞绑定不随恢复还原**（删除时库行硬删、FK 级联清理，恢复=重建行）——已知限制，用户在意时给回收站 meta 加关联快照；原位置被占用时自动重命名"基名 (2).ext"（恢复永远成功，不因冲突失败）。
- **新建目录**：库内任意层级。
- **文件名推荐与作品名序号联想（`SuggestSeriesNames` 纯函数，2026-10-09 智能推荐增强）**：
  - **三级匹配梯度**：Tier 1 前缀匹配（输入为文件名前缀）> Tier 2 多词 Token 全包含（输入所有 token 均包含在文件名中，如「法环 菈妮」命中「艾尔登法环 菈妮」）> Tier 3 子串包含（输入为文件名任意中段子串，如「法环」命中「艾尔登法环 玛丽卡」）；支持中段关键词检索。
  - **多风格序号解析与位宽保留**：解析半角/全角圆括号 `()`/`（）`、方括号 `[]`/`【】`、带标前缀（`No.`、`#`、`EP`、`Vol.` 等）；保留原始数字位宽与前导零（如 `01` -> `02`，`09` -> `10`），自动推导下一序号。
  - **主体聚类平权轮转（Cluster Diversity Round-Robin）**：基于角色主体/子实体提取聚类键，首轮各主体首选条目优先曝光（不同角色平等享有曝光机会，彻底杜绝单角色多子变体垄断全部槽位），次轮填补剩余高频变体。
  - **独立子实体智能推荐**：无序号独立角色（单文件角色）经词边界检验后智能推荐下一序号（基名 + 2）；剥离修饰符（如 `（特写）`）。
  - **容量上限**：推荐列表扩容为 8 条（`cap 8`）。

## 11. 媒体类型与缩略图

- 类型：IMAGE / ANIMATED_IMAGE(gif) / VIDEO。
- 视频缩略图抽帧优先级（2026-08-26 对齐旧项目 v1.18 真机验证策略）：**内嵌封面优先**（cover art）→ 无则按**视频时长 35% 偏移取代表帧**（对齐 Windows 资源管理器 Icaros 体验，35% 帧构图最有"封面感"；旧版 ffprobe 实测用户参考库 376 个视频 0 个带内嵌封面，体验 100% 来自代表帧）→ 系统缩略图兜底。图片取缩放帧；动图取首帧静帧。
- 黑白/极端帧检测：采样 100 像素，**全部** <15 判黑、**全部** >240 判白（判定语义为**全部**采样像素超阈值才判，99/100 黑不判黑：角落台标与片头淡入残影是有效内容，不应触发跳帧）；不合格按比例向两侧扩散（35%→25%→45%→15%→55%→5%→65%→0ms）；取不到时长时短路 0ms 帧，不重复取同一帧。
- 抽帧位置策略变更后旧缩略图缓存必须**失效重建**；列表/详情实时显示用首帧（中段 seek 慢会加剧滑动掉帧），代表帧只用于预生成缓存——两者分工是旧版验证过的性能决策。
- 缩略图缓存键：SHA-256("v3:assetId:size") 前缀 hex（策略版本段+冒号定界，纯拼接有边界歧义；2026-09-07 勘误，原公式省略定界符），存数据目录，永不因数量上限删除有效缓存（孤儿待对账任务兜底，规划项）。缓存键包含**策略版本段**（当前 "v3"）：抽帧位置策略变更后旧键全部失效，旧缓存变孤儿由对账清理，无需启动时全量删除。**删除时机联动清理已实现（2026-09-22，`thumbnail.DeleteAssetThumbs`）**：资产"永久消失"的四个入口——回收站单条物理删除、清空回收站、到期清扫（§9）、删除库——联动删除该资产全部档位（含格式/像素漂移前的历史键）缓存文件；软删除→恢复不清理（asset_id 不变，缓存继续命中）。**第五触发器（2026-10-01 第四百一十八笔）**：扫描器重探测变更（size/mtime 与库内记录不一致的重入库，含仅 touch 的保守触发）同联动删除——外部原地换文件后旧内容的缩略图/海报帧不再永久陈旧（缓存键不含内容指纹，变更信号必须显式接失效）。扫描器外部删除（文件在库外被移走）产生的孤儿仍待全量对账任务兜底（规划项）。
- 输出格式（2026-09-15 U11 批次D 记档）：静图缩略图编码=部署期 ffmpeg 能力自适应——libwebp 可用输出 webp（NAS/桌面不变），缺失降级 mjpeg（内嵌形态 hzw1199 LGPL 成品无 libwebp；FFmpeg 无原生 WebP 编码器）。格式不在缓存键内（键公式不变）；缓存扩展名=输出封装=Content-Type 三同源（thumbnail/stillformat.go）。
- 静图方向（2026-10-01）：竖拍照片（EXIF Orientation≠1）的缩略图**显式按 EXIF Orientation 旋转**——服务端手写解析 JPEG APP1 EXIF 的 Orientation tag（零新依赖；HEIF/解析不到/非 JPEG 一律按 1 不转），按映射表换 ffmpeg transpose/hflip/vflip 滤镜于缩放前应用（thumbnail/orientation.go）；同时 scaleStill 输入侧恒带 `-noautorotate` 关闭 ffmpeg 解码期隐式 EXIF 转向——该隐式行为**随版本漂移**（本仓 9.0.1 实测新版默认已转、旧版不转），不关闭则显式滤镜叠在隐式之上双重变换，跨部署行为不可复现，关闭后显式滤镜是唯一方向权威；浏览器显示 /media/orig 直链自行按 EXIF 转向（CSS image-orientation 默认 from-image），原图不处理；视频 display matrix 由 ffmpeg autorotate 常态可靠，不在此列。方向策略变更即本笔：**v2→v3 全量重建**（v2 键全部失效，旧文件变孤儿由对账清理）。
- 实现状态（2026-08-29）：**M2 UI 段随附后端已对齐**——ffprobe 探测内嵌封面（disposition.attached_pic）优先 → 35% 代表帧 → 黑/白扩散序列（35%→25%→45%→15%→55%→5%→65%→0ms），取不到时长短路 0ms、不重复取同一帧（毫秒精度去重）；缓存键升版本段使旧缓存全部失效重建。**性能分工（列表/详情实时显示用首帧、代表帧用于预生成缓存）M3 预留**：md 档预生成已落地（开机回填/扫描后补齐/10min 周期兜底，thumbnail_warmup.go），按需同步生成兜底；『列表实时首帧/预生成代表帧』双管拆分仍未做，两条管道分派点已在 thumbnail.Generator 注释标注。
